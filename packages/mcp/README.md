# @lincyaw/mcp

Presmium's agent environment: a document's tools and resources over MCP, for agents such as Claude Code, Codex or VS Code.

Part of [Presmium](https://github.com/Lincyaw/presmium), which compiles canonical lecture.json teaching documents into web pages, slides, Jupyter notebooks and narrated playback.

## Usage

`presmium dev` and `presmium serve` serve it at `/mcp` and print its address and the file that holds its token. Without a server, run it over stdio:

```sh
pnpm exec presmium-mcp <document directory>
```

The reading tools (`list_sections`, `get_section`, `get_step`, `search`, `get_code_ref`, `get_outputs`, `get_diagnostics`, `check_document`, `locate_source` and others) are always there; `--allow operate` also provides `run_code` and `build`.

`get_diagnostics` reads version-bound diagnostic snapshot fragments without compiling or checking. Keep both version and digest on continuation reads, join decoded `text` at `nextOffset`, and parse once after `complete`. `check_document` explicitly runs compilation and plugin checks; its counts do not verify the current source or browser. The full protocol and compiler-only stdio boundary are in [diagnostic feedback](../../docs/diagnostic-feedback.md).

The workspace host behind `presmium serve` also provides canonical authoring. Start with `get_authoring_capabilities` and `get_document_outline`, then read complete saved entities or fields through `read_document_part`. Keep the returned source on every continuation; a source change returns 409. The legacy `get_document` still returns the full document for SDK consumers and can exceed an agent's tool-result budget. `get_section/get_step` read derived runtime data, not editable authoring content.

`get_document_outline({ document?, source?, collection?, offset? })` defaults to ordered pages. It includes entity counts, stable IDs and explicitly marked title previews; `offset > 0` requires source. Other collections include unused narrations, assets and definitions. `read_document_part({ document?, source, target: { collection, id?, path? }, offset? })` selects a map entity by stable ID or a root field, then own JSON fields or canonical array indices. Small values return `encoding: 'value'`. Large values return `encoding: 'json-text-fragment'`: concatenate decoded `text` in returned `nextOffset` order, then `JSON.parse` the complete text once. Offsets are UTF-16 positions and never split a valid surrogate pair. The FNV-1a 64 digest covers UTF-8 `JSON.stringify(selectedValue)` with no indentation. It verifies the selected canonical value, not original file whitespace. Shared read contracts cap requests at 2,048 `JSON.stringify` UTF-16 characters and responses at 7,168 pretty-JSON UTF-16 characters; see the [exact protocol and limits](../../docs/rfc-mcp-authoring-actions.md#18-已实现的版本绑定局部读取).

Workspace Git history uses `get_document_history` and `read_history_file`. History pages contain original changes with complete-chain state; a historical file read never restores current content. For explicit saved-source changes, use `undo_document_change`, `redo_document_change` or the Web-equivalent per-row `revert_document_change` with a stable id, returned historyBinding and full expect commit. Root document `""` stays scoped. These share existing locks, permissions and failure rollback; they do not control native editor Undo or discard browser drafts. See [history protocol and limits](../../docs/document-history.md).

Preflight a `DocumentChange` with `plan_document_change`, then submit the identical change and its `planId` to `apply_document_change`. Web and MCP share CAS, same-document text-file transactions, locking, rollback and history. The result confirms saved source and files; compilation and playback remain separate. Existing semantic operations are advertised in capabilities, and a complete replacement is available for explicit structural changes. Generic large-document change requests and results are not yet budgeted; the partial reader does not make those large writes agent-safe by itself.

For comments and inherited voice settings, use `plan_authoring_action({ document, request: { id, source, action } })`, then `apply_authoring_action({ document, request: { planId, source, digest } })`. Actions are `comment.create/reply/update/react/resolve/reopen/delete` and `voice.set`; comment content is canonical `RichTextNode[]`, never BlockNote JSON. Create supplies an explicit stable UTF-16 anchor or null. The service fixes member, dates and fresh IDs once per plan; an owner may manage earlier authors while preserving their IDs, editors only edit their own comments. Omitted update metadata is preserved. Delete also requires `confirmDeletion: true` for that exact plan. Default requests are at most 4096 JSON UTF-16 characters and results 7168 pretty-JSON characters; full candidates/details are optional resources. Reuse the original apply reference after lost ACK, with the same process/current-source limits as other authoring plans. The HTTP routes use the same owner with trusted editor origin; MCP keeps agent review/origin, and payloads cannot select an origin. Voice settings accept TTS/none/null with document/page/step/steps scope and explicit override replacement; new recording adoption still requires `adopt_recording`. Saving settings does not generate or prove playback. See [the shared contract and limits](../../docs/rfc-mcp-authoring-actions.md#20-已实现的批注与音色语义计划).

For page creation, rename, move or deletion, call `plan_page_change` with `{ document, request: { id, source, action } }`. The strict action is `{ type: "create", title, after?: sectionId | null }`, `{ type: "rename", sectionId, title }`, `{ type: "move", sectionId, before: sectionId | null }` or `{ type: "delete", sectionId }`; null placement appends. Read the compact target and impact, then `apply_page_change` with `{ document, request: { planId, source, digest } }`. Deletion also needs `confirmDeletion: true`, bound to that exact planned action and source. All retained narration cue references, including unused narrations, block deletion. Shared narrations/assets/definitions and discussions are retained; only owned content is removed, and affected comment anchors are detached. Last-page deletion retains its title and one empty step. Web uses the same pure page rules; new pages retain the native creation Undo/focus path and 4000 ms hold / 500 ms pause defaults. Default MCP requests are at most 2048 JSON characters and results at most 7168 pretty-JSON UTF-16 characters; full candidates/details are optional resources. The existing bounded plan/receipt owner performs validation, CAS, lock, history, role/review checks and exact readback. Reuse the unchanged apply reference after a lost ACK; do not silently replan after a 409 or claim cross-process idempotency. This does not bound the legacy generic full-document write API.

For page duplication, call `plan_page_duplication` with `{ document, request: { id, source, sectionId, title } }`. It fixes fresh IDs on the server and returns a compact source/planId/digest/expiry, target and count summary. Commit with `apply_page_duplication` using only `{ document, request: { planId, source, digest } }`; its compact receipt verifies the actual planned file version and new page. The service retrieves the exact candidate from the same plan owner and uses the original apply/transaction/receipt path. Full candidate, copied-ID mapping and details are optional resources; the model does not need to echo a document or mapping. Assets/definitions stay shared, and opaque payloads and original comments stay unchanged. Plans last five minutes and plans/receipts retain at most 64 entries each in this process. Retry the identical apply reference; a 409 is not permission to silently replan. This is not cross-process or unlimited history idempotency.

Authoring initialization and reads do not wait for compilation. Plugin tools appear after their actual compilation is ready; clients should follow tool-list change notifications. Compiler-only stdio reports authoring unavailable. Required agent review is not integrated with canonical apply yet, so that configuration rejects apply; retry receipts are limited to the current process and saved result. See the [authoring actions RFC](../../docs/rfc-mcp-authoring-actions.md) for the remaining capability and feedback work.

Transcription uses the workspace's shared task service. `get_transcription_capabilities` reports actual Node service configuration without compiling scenes; `configuration-only` does not verify provider authentication. `start_transcription` is a spending action with host-owned confirmation. Discover tasks with `get_transcriptions`, poll one with `get_transcription`, read its exact candidate revision with `get_transcription_result`, and cancel through `cancel_transcription`. HTTP and MCP use the same durable task journals, including pre-admission cancellation.

To adopt text, call `plan_transcription_adoption` with explicit stable step targets and segment choices, resolve protected pronunciation/cue conflicts, then submit the returned plan to `apply_transcription_adoption`. The tool uses the same canonical transaction as Web and records agent origin; it cannot select the editor write path or bypass required review. Adoption does not change the selected voice or start synthesis. Task discovery reports corrupt journals as issues and marks old document identities or invalid current JSON as stale. Standalone stdio has no transcription authoring service.

For existing workspace audio, read `get_audio_authoring_capabilities`, then use `inspect_workspace_audio` with the saved source and a permitted same-document workspace-relative path. It returns the actual SHA-256, byte length and media metadata without inventing an asset identity. Pass its exact `file` object, source and a new change ID to `import_workspace_audio`; `inspect_document_audio` reads the resulting canonical asset, including audio not used by a clip. Web and MCP share one bounded receipt owner, media validation, atomic binary/document transaction and saved-file readback. Import is an authorized operation with agent history origin and required-review enforcement; it does not recognize audio, select a voice or create a clip. Retry receipts are process-local and require the saved result to remain current. Compiler-only stdio reports this workspace capability unavailable.

`adopt_recording` explicitly adopts a saved local audio asset as one stable step's whole-step recording through the shared HTTP/MCP service; see the [audio authoring boundary](../../docs/audio-authoring.md) and [actual recording-adoption evidence](../../docs/benchmarks/recording-step-adoption-2026-10-27.md). Studio’s Video **Original audio** card explicitly saves native recording candidates, selects saved audio and uses **Use as step voiceover** for the same adoption action; see the [UI evidence](../../docs/benchmarks/recording-step-adoption-ui-2026-10-27.md). Save does not adopt, and adoption does not transcribe or synthesize. Each effective step plays the whole file independently, with no word alignment or continuous cross-step allocation. MCP control of a recording client is still not connected.

For clips, `read_production_plan` accepts the saved source and optional expected IR revision. It reads an existing real cache-only snapshot; explicitly read `presmium://ir?document=…` first when preparation or refresh is needed. Use the returned binding with `validate_media_clip_change`, then authorize `change_media_clip` with an intent ID. Preflight retains no plan, and apply rechecks real audio and confirmed step ranges in the shared Web transaction. Removal needs only canonical source and keeps the original asset. Saved-source verification does not claim a new runtime is ready.

`get_voice_authoring_capabilities` reads configured engines, the default synthesis engine and installed voiceover/preview implementation without compiling scenes. `get_voice_catalog` reads the same actual catalogue as Web, with optional expected source, engine and language; source changes during discovery are conflicts. Configuration does not prove provider authentication, and an unsupported catalogue stays unavailable. These tools do not select a voice or synthesize speech; see the [voice discovery contract](../../docs/voice-authoring.md).

Workspace MCP shares Web's voiceover task owner. Read `get_voiceover_status` for the current source, IR revision and bound step targets, then explicitly approve `start_voiceover` with an intent and unchanged scope. Poll `get_voiceover_job` by task ID or intent, discover retained tasks with `get_voiceover_jobs`, and cancel with `cancel_voiceover`. Job reads and cancellation do not compile or discover providers, including when current JSON is invalid. Intents and jobs are process-local; compiled remounts retain the Workspace owner. If status has no real IR, explicitly read `presmium://ir?document=<directory>` first. The synchronous `lecture_synthesize` plugin tool is no longer advertised; the existing `presmium-lecture export` CLI is unchanged. Compiler-only stdio has no Workspace task owner and reports these actions unavailable.

`quote_voice_preview` checks a real sample or step audition without synthesis. After spending approval, `preview_voice` returns source, revision, provider, cache status, key, duration, byte length, SHA-256 and a `presmium://voice-preview/{id}?document=<directory>` audio resource. Read the resource for its actual MIME/blob; audio bytes are not dumped into tool text. Quotes expire and pin the selected execution instance, resources are bounded, and a generated preview does not prove that any client played it. Exact limits and [runtime evidence](../../docs/benchmarks/voiceover-task-owner-2026-10-27.md) describe the implemented scope.

`get_runtime` (also `presmium://runtime`) reads the author's open browser reports: timestamps, section and step, plugin/component failures and live execution status. It differs from the compiled recordings returned by `get_outputs`. Only editor/owner windows of the selected document contribute; closing a window removes its feedback. An empty list means no observed browser state, and earlier results do not verify a new source revision.

Workspace project management uses `get_project_capabilities`, `plan_project_change` and `apply_project_change`. Read the fixed plan before applying; deletion requires `confirmDeletion:true`. Web uses the same owner. Directory plans bind actual HEAD, configuration, file/template trees and classified references, with bounded replies and process-local retries. Retitle instead delegates the existing canonical DocumentEditor CAS, binds document source/version, and remains available for single-document and no-Git workspaces. Its receipt reports canonical source and only includes a Git snapshot/revision when a real commit exists. Capabilities report each action separately. Document-bound tokens may only retitle their exact bound document; they have no directory-management grant. Root-directory copy/move/delete and no-Git directory management are unavailable. Only the documented relative canonical references and official code anchors are transformed. Copy preserves a local pinned anchor/variant and its historical path as one tuple; renaming a directory touched by such a pinned reference is explicitly refused. Opaque/plugin parameters, data and scene source code, including external relative imports, are copied/moved unchanged; they are not detected or refused, and their relocated private dependency semantics are outside this guarantee. Remote/root-absolute/hash/query URLs are also unchanged. Capability discovery does not compile or validate a file tree.

Component parameter actions also use `plan_authoring_action` / `apply_authoring_action`: `component.parameters.patch`, `component.step-parameters.patch`, `component.step-parameters.reset`, and `component.definition.use`. Send bounded set/remove path changes for schema-declared editable fields, preserving unchanged large/unknown fields. Read-only ancestors/descendants are enforced by the shared service. Complete public array items may be deleted and exact whole-item reorders are allowed; ambiguous mixed replacements must be split. Step changes may affect inherited descendants; read the actual paged lists with `read_authoring_action_impact` instead of assuming a single-step effect. Only existing Definitions may be selected. Independent implementation copies remain unavailable. See [the parameter contract and limits](../../docs/rfc-mcp-authoring-actions.md#23-已实现的组件参数与已有-definition-选择).

Studio's explicit `component-drafts.inspect` and `component-drafts.read` actions use `request_authoring_client` and its terminal receipt. Start with the selected connected client's exact source, epoch, connection and revision; request inspect for bounded metadata, then read exact `{id,revision,token,blockId,stepId?}` UTF-16 JSON-text fragments. Reassemble and verify the full UTF-8 SHA-256 before parsing `presmium-component-parameters-json-v1`. Values include preserved unknown parameters; baselines and workspace/member identities stay private. Default client listings never inspect draft bytes. Latest session input shadows older storage after backup failure. `current` describes observed client revision and storage, not atomic cross-window consistency. Comment restore/discard and other unwired draft families remain unavailable. See [the contract and transport limits](../../docs/rfc-mcp-authoring-actions.md#93-已接入的显式组件属性草稿读取).

Component-property drafts also support explicit `component-drafts.restore` and `component-drafts.discard` through the same browser request. Inspect first: each item marks `current` for that client's bank. Restore a backup with its exact reference and `expectedCurrent` (the exact current reference or null); the existing owner strictly forks, preserves the current branch and returns only new metadata. Pending/session-only/IME input and changed targets are refused. Discard must specify the exact reference and `current` boolean; it retires only that version, preserving unselected recovery origins. These actions neither write canonical parameters nor navigate or focus. Review the restored native form, explicitly recheck stale source if needed, then use its ordinary Apply. Read terminal verification and actual state after disconnect or timeout; a committed but unadopted fork remains recoverable. Identical retained intent replay returns the original receipt without another mutation. See [the exact contracts and staged evidence](../../docs/rfc-mcp-authoring-actions.md#93-已接入的显式组件属性草稿读取).
