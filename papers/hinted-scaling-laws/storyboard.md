# 分镜：提示辅助的缩放定律（Hinted Scaling Laws，arXiv 2611.02270）

每个参与制作的 agent 开工前读这份文件，改动后再读一遍。讲稿在 `lecture.json` 的 `narrations` 里，这里的“讲稿要点”只是对照；数字一律来自 `scenes/data/hsl.json`。

## A. 简报

- **类型**：论文讲解视频，三分钟左右、最长六分钟（这一版讲稿约 1,500 字，火山引擎甜美桃子配音，成片 5:45），主要形式是配音视频（`lecture`），同时是网页（scrolly：画面固定，讲稿在旁边滚动）和幻灯片。
- **观众**：做大模型训练、评测或研究的人，知道缩放定律、预训练损失和基准测试，没读过这篇论文。
- **看之前**：以为下游准确率的缩放定律必须等到模型出现“涌现”后才能拟合；小模型准确率接近零时，无法预测大模型的准确率。
- **看之后**能复述：
  1. 问题：小模型在困难基准上的准确率接近零，标准缩放定律没有趋势可外推；
  2. 为什么重要：开发者和安全团队关心的是下游能力，而不只是损失；
  3. 办法：在题目前加入不同比例的参考解答（提示量 H）；准确率随 H 平滑上升，H 与算力可以互换；用一条联合定律拟合，并取 H = 0 曲线在目标规模处的预测值；
  4. 证据：只用不到目标千分之一算力的六个小模型预测 10²³ FLOPs 模型的准确率，误差不到 3 个百分点，标准方法低估 13 个百分点；19 组预测中 17 组更准；排序上一次提示辅助采样约相当于五次原题采样；
  5. 条件：提示应让不同能力模型的准确率差异清楚可见（每题直接给出最终答案的对照做不到这一点），每道题需要可靠的参考解答。
- **用户的固定要求**：开场白固定为“三分钟读完一篇论文。大家好，这里是翰林院传达室，今天给大家带来{单位}的{论文}。”；先讲问题、为什么重要、论文要解决什么，再展开；论文原图裁切后一次只放一张，配我们的动画讲解。

## B. 论点

看完后，观众明白：小模型准确率接近零时，在题目前加入一部分参考解答，接近零的准确率就变成随提示量平滑上升的曲线，用算力与提示量的联合定律就能预测大模型的准确率；因为他们看到同一排接近零的点长出一列列提示辅助准确率，等准确率线在算力与提示量平面上几乎平行，H = 0 曲线外推到 10²³ FLOPs 后，预测值落在实际值旁边。

ABT：缩放定律用小模型预测大模型的准确率，而且开发者真正关心下游准确率；但是小模型在难题上的准确率接近零，没有趋势可外推；所以在题目前加入不同比例的参考解答，在算力和提示量两个维度上拟合一条联合定律，再取提示量为 0 处的预测。

## I. 制作规则

- 场景的样子只由时间决定：只用补间（tween）和 `set`，不用 `onUpdate`、`call` 之类的回调。预览与导出按时间定位（seek）时 GSAP 会跳过回调，靠回调画出来的帧会停在旧状态。读数用 `textContent` 补间加 `modifiers` 格式化。
- 节拍用 `clock` 的 `T(k, f)`：状态 k 的比例 f 处；`tools/film.mjs retime` 把状态时长换成真实配音后，节拍跟着句子走。按讲稿里关键词的位置（字数比例）放节拍。
- 不用 SVG 的 `id` 和 `url(#…)`（同一页面上多个场景会互相冲突），箭头画成路径。
- 颜色变化不能补间 `var()` 或 `color-mix()`：用 `isDark`、`color()` 取实际颜色或预先算好 `rgb()`。
- 只有协调者改 `lecture.json`、`kit/`、`hsl.ts` 和 `data/`；每个 agent 只改分给自己的场景文件。保存前确认它能编译（`pnpm exec presmium check hinted-scaling-laws --json`，忽略“没有配音”那一条），一个编译不过的场景会让整份文稿的预览失败。
- 看结果用 `node tools/mcp.mjs capture_slides '{"document":"hinted-scaling-laws","section":"p-<页>"}' --out <目录>`，再用 `tools/sheet.py` 拼成一张看；亮色与暗色都要看（暗色：`capture_slides` 的参数见 `node tools/mcp.mjs list`）。
