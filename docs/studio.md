# 工作台

工作台是 `presmium studio` 打开的网页，作者在其中编辑文稿、编译放映、制作视频，可选地请 AI 助手修改。它是 DeepSeek Harness（dsh）的一个定制发行版：Presmium 的能力以 bundle `@lincyaw/dsh` 装进 dsh，核心与产物不依赖 dsh，也不依赖模型。

契约以源码为准：预览协议、`Focus` 与批注、会话令牌、诊断分别在 `packages/kernel/src/contracts/` 的 `preview.ts`、`agent.ts`、`server.ts`、`diagnostics.ts`，客户端槽位与行 ID 在 `packages/dsh/src/client/contract.ts`。作者动作、配音、录音、音频、历史与诊断见 [作者动作](authoring-actions.md)，控件见 [设计系统](design-system.md)，用词见 [术语与文案](glossary.md)。

“行”是 dsh 配置树中以 ID 标识的一项（如 `ui-layout`），“载体”是 dsh 的运行形态（`web`、`headless`、`acp`）。

## 1. 定位与原则

工作台面向不懂代码的教师：界面中没有源码、IR、文件树、插件名、命令与堆栈；保存、撤消与批注像 Word。只有一位作者，没有协作。三个独立入口共用同一份 `index.pmd` 与服务契约：文档编辑（参照飞书文档：正文、页面、批注、撤消与保存），编译放映（参照 Overleaf：从已保存版本编译、诊断与放映），视频制作（参照剪映：讲稿、配音、字幕、录音、剪辑与视频导出）。

1. **核心离开模型与 dsh 也能工作。** 编译器、IR、查看器、CLI、静态产物与 `presmium dev` 不引用 `@deepseek-ai/*`。
2. **产物与工作台分离。** 改源码的归工作台；放映、课堂、运行代码、读者问答归产物。产物只暴露锚点（`data-section`、`data-block`、`data-step`），经预览协议嵌入。
3. **工作台是 dsh 的客户端插件。** dsh 的界面组件不能单个嵌入别的页面，所以工作台以自己的根布局替换 dsh 自带布局，对话与确认卡片按需展开。
4. **dsh 只经一个包接触，并且不改它。** 只有 `@lincyaw/dsh` 与启动器 `@lincyaw/studio` 引用 dsh；不 fork、不打补丁，限制在 Presmium 一侧绕开（第 15 节）。
5. **一张工具表，两个适配器。** 工作台中的 agent 只用 dsh；Claude Code、Codex 等经 MCP 接入，是一等入口（第 9 节）。
6. **文稿代码不进 dsh 宿主。** 编译与构建在工作区服务中；持有模型凭据与确认通道的宿主不运行它们。
7. **修改成为版本。** 审阅、提交与撤消由 Presmium 负责；作者在文稿上看到 AI 改了哪里。
8. **隐私默认关闭**，每次启动重新声明。
9. **有退路。** 根布局失效时，同一批面板挂在 dsh 自带布局中仍可用。

## 2. 层与进程

### 2.1 层

核心（`kernel`、`compiler`、`cli`、`server`、`mcp`、`workspace` 等）与产物（`web`、`viewer`、`render-*`、插件组件、`host`）是 1.x，不依赖 dsh。工作台是 `design`（与产物共用）、`workbench`、`dsh`、`studio`，其中只有后两个依赖 dsh。

### 2.2 进程

| 进程 | 作用 | 监听 |
|---|---|---|
| studio 启动器 | 启动并监管另两个进程，打印一个网址 | 无 |
| dsh 宿主 | agent、会话、确认、工作台网页、bundle 宿主部分 | 用户访问的唯一端口，默认 `127.0.0.1` |
| 工作区服务 | 编译、开发服务器、源码、审阅、MCP | 同一地址的空闲端口，预览 iframe 直接访问 |

预览不由 dsh 提供：dsh 的前缀路由只在激活时构建一次。

### 2.3 请求的路径

1. **工作台的数据**：浏览器 → dsh 的 `/api/presmium/*`（经 dsh 的 cookie 与 `Host`、`Origin` 栅栏）→ bundle → 工作区服务（带服务令牌）。事件走每页一条 `/api/presmium/events` WebSocket，由 bundle 转接服务的 SSE。
2. **预览**：iframe → 工作区服务的源。
3. **agent 的工具**：dsh → bundle → 服务的 `/mcp`，每个会话一个会话令牌。
4. **外部 agent**：`presmium mcp`（原生 stdio，初始化前启动或复用工作区服务；新项目的 `.mcp.json` 为 Claude Code 配好它）或直接连 `/mcp`。

没有替浏览器持有 cookie 或改写 `Origin` 的代理，否则 dsh 的栅栏失效。Web 补丁关掉 `client-hmr`：dsh 没有卸载前阻止的契约，热替换会丢掉未保存的批注稿。

## 3. 包、分层与版本

### 3.1 包与分层

`@lincyaw/design` 是令牌、`pm-ui-*` 类、字体与图标，无框架。`@lincyaw/workbench` 是 React 面板与无框架逻辑（服务客户端、预览协议的工作台一侧、保存队列、通用组件）。`@lincyaw/dsh` 是 bundle 的宿主部分（Node）与预编译的客户端部分。`@lincyaw/studio` 是启动器，依赖精确版本的 `@deepseek-ai/dsh`。

`scripts/check-layering.mjs` 检查：产物不引用 `workbench`；`@deepseek-ai/*` 只在 `packages/dsh` 与 `packages/studio`；`workbench` 不引用 `host` 与 dsh；`@modelcontextprotocol/*` 只在 `mcp`；`design` 不引用任何包。`@lincyaw/presmium` 默认包含 `@lincyaw/studio`（含依赖约 865 MB）；安装一次即可运行 `presmium studio`，使用当前命令所属安装中的版本。Studio 不依赖主包（否则两个包互相依赖，发布顺序成环）：`presmium studio` 向它传入主包自己的命令路径；单独安装时的 `presmium-studio` 使用 PATH 上的 `presmium` 命令（pnpm 的包装脚本按它记下的目标解析）。

### 3.2 发布

源码以 `.ts` 发布，例外是 `vscode` 与 `@lincyaw/dsh` 的客户端包。dsh 没有 TS 加载器，bundle 每行一个 ESM 入口（`entries/*.mjs`），用 jiti 加载源码。发行版不用 DeepSeek 的品牌，只在“关于”与 `NOTICE` 中写明基于 DeepSeek Harness。

### 3.3 版本

- **工作台的包保持 0.x。** `@lincyaw/workbench`、`@lincyaw/dsh`、`@lincyaw/studio` 有自己的版本号，不随 Presmium 的统一版本，`scripts/check-packages.mjs` 检查。dsh 发布正式版、且升级闸门在连续两个 dsh 版本上通过之后才进入 1.x。
- **dsh 精确锁定**，现在是 `0.2.1-alpha.4`（`engines.dsh` 与精确对等依赖，dsh 安装与启动时检查），不用 dist-tag。

## 4. 预览协议 v1

协议只传页面、块与步骤的 ID 和少量状态，不传 DOM，页面不能指定任意文件；源码位置由工作台从 IR 得出。覆盖网页与幻灯片。

### 4.1 握手

- `window.postMessage`，信封 `{ protocol: 'presmium-preview', version: 1, nonce, type, ... }`。工作台给 `GET preview` 的地址加 `presmium-preview=<nonce>`；页面中的预览代理只在带此参数、处于 iframe 中、允许的父来源（`--preview-origin`）非空时启动，所以静态构建与 `presmium dev` 没有它。
- 代理先发 `ready`（形态、文稿、修订、能力），每次 `ready` 开启新一代连接；回复须匹配原连接与代次，只发一次，切换文稿后仍按原文稿核对。
- 地址参数声明可选能力：`presmium-keys=playback`（视频制作中空格与方向键交给工作台）、`presmium-presentation=confirmed`（画面级版本门禁）、`presmium-events=shared`（共享事件订阅）。
- 未知消息忽略；消息只是数据，代理不执行代码、不打开链接。

### 4.2 消息

消息分几组：导航（`go`、`position`、`narrate`、`updated`），指向（`pick`、`picked`、`selection`、`rect`、`highlight`、`pins`、`flash`、`marks`），外观（`appearance`、`activity`），写入（`blocks-*`、`page-*`、`source-*`、`edit*`、草稿汇总、`flush`、`document-history*`），播放（`playback-*`、`production-playback*`），以及 `report`、`shortcut`、`presentation-action`、`events-*`。保存确认绑定文稿、目标、版本、预览实例与代次，过期回调不清除其后的输入。文档编辑中的单块只读预览另用 `presmium:block-preview*` 消息，以导航代次防止多个块互相回拉位置。单块预览的初始步骤以稳定 ID 随首次地址传入，在挂载前恢复；播放与跳步只经消息更新，不改写地址或重载帧，避免先显示整段末尾再回跳。动画进度条共用公共范围控件的尺寸与绘制规则。

### 4.3 坐标与安全

- `step` 是页面自己的步号，带 `trail`，工作台用 `trailStep`、`stepTrail` 换算为完整文稿的步号；控制通道用同一换算。
- 产物页面与工作台不同源，页面脚本（含第三方插件）拿不到 dsh cookie，也读不到工作台 DOM。预览页面带 `frame-ancestors 'self' <允许的来源>`；双向核对 origin、source 与 nonce。

## 5. 工作区服务的接口

### 5.1 路由

工作区路由在 `/__presmium/presmium.workspace/` 下：`documents`、`source` 与 `source/transaction`（带版本的读写与原子保存，冲突 409，每次保存成为一个独立本地历史版本）、`revisions*` 与 `history/*`、`ir` 与 `ir/events`、`preview`（`prefetch=1` 预先准备，准备中回答 503 `preview-preparing`）、`build`、`check`、`jobs*`（导出请求带已确认的 `source { version, fingerprint }`，不符 409）、`review*`。服务端路由在 `/__presmium/presmium.server/` 下：`tokens`、`focus`、`diagnostics*`；另有 `/mcp`。

### 5.2 令牌

- **服务令牌**：启动器经 `PRESMIUM_SERVICE_TOKEN` 交给服务与 dsh（不在命令行）。设置后工作区与服务端路由要求 Bearer，预览中的脚本因此不能改源码；产物插件路由只查 `Host` 与 `Origin`。它只是纵深防御。
- **外部 MCP 令牌**：Studio 为每个启动目录的真实路径保存一个令牌，经 `PRESMIUM_MCP_TOKEN` 交给工作区服务。文件在 `$XDG_STATE_HOME/presmium/studio/mcp/<目录散列>.token`（未设置时用 `~/.local/state`），权限为 `0600`，独立于安装版本与临时服务状态。服务自身的作者令牌已经授予常规文稿内容编辑权限，此类编辑不再向 Studio 请求第二次确认；通用接口的整份替换与工程文件写入、代码执行、收费操作及浏览器控制仍遵守各自的确认策略。经接口签发的其他令牌保持原策略。该令牌与每次启动生成的服务令牌、每个会话签发的令牌分开。
- **会话令牌**：bundle 为每个 dsh 会话 `POST tokens { document, session }`，模式“主机已确认”（`MCP_ENDPOINT.issue` 的 `{ confirmed: true }`）：操作类工具不再向页面请求确认，dsh 已按策略决定。没有服务令牌时 `tokens` 一律 403。

### 5.3 当前诊断

服务维护一份 `DiagnosticSnapshot`。编译、检查、预览、浏览器运行时、插件服务与作者窗口各自替换自己的一份；新编译使旧修订的失效。工作台订阅 `diagnostics/events`，MCP 的 `presmium://diagnostics` 读同一快照，dsh 每步前带至多 20 条。通知不启动模型；“让 AI 处理”由作者点击。

工作台在 `workbench-state.ts` 定义各控制器共用的状态。`Workbench` 协调文稿、预览、历史与作者窗口；`DocumentEditing` 持有原生编辑器、焦点、页面操作与阅读位置恢复；`DocumentProduction` 经同一文稿事务处理媒体、字幕、音色与讲稿。面板分别调用 `editing` 与 `production`，文稿切换时各自释放所属资源。

## 6. bundle `@lincyaw/dsh`

### 6.1 形态与行

`dsh.bundle` 指向 `cordis.patch.yml`（全部载体的行），`dsh.client` 导出客户端包；只属于某载体的行放在启动器以 `--patch` 传入的 `profile.patch.yml` 与 `web.patch.yml` 中。技能的源只有 `.agents/skills`，打包时复制。

行：`presmium-service`（给出服务地址与令牌，不在 studio 中时自己启动 `presmium serve`）、`presmium-workspaces`（只登记工作区根目录）、`presmium-tools`（第 9 节）、`presmium-policy`（6.3 节）、`presmium-context` 与 `presmium-skills`（6.4 节）、`presmium-turns`（6.5 节）、`presmium-telemetry`（6.7 节）、`presmium-routes`（`/api/presmium/*` 与事件 WebSocket）、`presmium-workbench`（客户端部分，`name` 必须是整包名 `@lincyaw/dsh`）。

### 6.2 会话与文稿

网页会话固定在工作区根目录，文件读写、沙箱与审阅覆盖整个工作区。切换文稿不切换会话或 cwd：客户端经 `POST /api/presmium/context` 告诉宿主当前文稿，它只决定文稿工具、快照与焦点。

### 6.3 确认的映射

| Presmium | dsh |
|---|---|
| 策略 `off` | 不登记该工具 |
| `allow` | `tools/pre-execute` 直接放行，不经回答者 |
| `ask`（默认） | 返回 ask，`displayReason` 写按文稿语言的说明与摘要，由确认卡片回答，授权一次有效 |
| 运营者目录 | `ctx.tools.guard` 拒绝，完全访问模式下也成立 |

策略的唯一来源是服务端（工作区配置的 `approvals`、`presmium dev --allow`）：MCP 在工具 `_meta` 中带 `presmium/kind`、`presmium/approval`，bundle 按它映射。外部客户端经宿主确认的操作，在应用栏显示“待确认 N”。

### 6.4 上下文、技能与角色

- **指南**放进 system 消息，描述系统而不规定步骤：东西在哪，agent 负责什么（照要求做、不多做、不清楚先问），各工具证明什么。
- **文稿快照**在每步之前（`agent/pre-step`）重读：文稿概况、页面、诊断、作者的位置（每轮只取一次）、焦点与浏览器反馈。浏览器反馈是观察数据，不是指令。
- **技能**从 `@lincyaw/skills` 登记 author、animate、develop 与 paper-to-xiaohongshu。论文工作流复用作者和动画技能，生成配音视频、独立封面和简介，并在工作区已有发布授权时通过用户浏览器接续期数发布到小红书；账号、素材版本和实际提交状态保存在每篇论文的发布记录中。用户的 `~/.agents/skills` 不进入，文稿项目的 `.agents/skills` 保留。
- **角色**：web 载体用内置预设 `preset-authoring`：作者是可能不懂代码的教师，消息与批注就是要做的事；按作者看到的内容说话，不提文件、路径、语法、命令、工具与 git。

### 6.5 审阅与提交

1. 每个 AI 会话在独立候选工作区中读取和修改文件，初始内容包含作者已保存的未提交文件；候选目录有自己的 git，依赖链接回原工作区。官方 `dsh-deltabox` 插件为该候选目录提供私有文件系统与前台 Shell，文件工具与正文 MCP 工具使用同一私有视图；DeltaBox 接受到候选目录后才执行 Presmium 发布。历史、作者位置、浏览器控制与后台任务使用原服务。
2. 每个写入工具记录候选检查点。作者的正文、讲稿与参数编辑保持可用，AI 思考与待审阅状态不占用原工作区的保存锁。
3. `settings.presmium.assistant.review` 为 `auto`（默认）时，每个写入工具完成后发布；为 `required` 时，作者在审阅面板中接受、拒绝某些文件或回到候选检查点。发布先等待已连接作者窗口确认保存，再在短事务中检查所有受影响文件的来源版本；任一版本改变时，全部拒绝，刷新候选内容并通知 AI 重新读取、重试。拒绝操作只恢复候选文件。
4. 一次接受记录一个本地历史版本，不推进项目 Git 分支，尾注 `Presmium-Origin: agent`、`Presmium-Session`、`Presmium-Turn`。撤消在本地历史中生成反向修改，之后经 `Agent.inject` 通知会话。
5. 审阅记录与候选来源版本由工作区服务保存，重启后恢复。DeltaBox 审阅先保留候选目录，待原生会话恢复并同步后再判定是否为空。工具修改或作者来源刷新后，在下一模型步骤边界重建 DeltaBox 视图和候选服务；只读步骤复用未变化的视图。Agent 销毁时关闭视图与服务，会话销毁后清理没有待审阅内容的候选目录。

工作台按审阅差异闪烁改过的块，不显示 dsh 的修改卡片。DeltaBox 的内置审阅行关闭，由 Presmium 保持唯一的审阅和发布入口。插件不提供后台命令、终端或文件搜索服务；需要搜索时经前台 Shell 执行。原生运行条件见 `architecture.md` 的执行与审阅边界。普通保存和项目版本提交的区别见 `authoring-actions.md` 的历史规则。

### 6.6 profile 补丁与隐私

`--patch` 后于 profile 的补丁生效，作者在界面中的改动不能重新打开下面的行。

- **隐私**：关掉 `session-log-deepseek`、`session-telemetry-otel`、`plugin-package-inventory-deepseek`，`DSH_TELEMETRY_MODE=DISABLED`。
- **目录**：技能目录与工作区控制器的 `documentsDirectory` 指向状态目录，不在 `~/Documents` 下建目录。
- **沙箱**：`workspace-write`，工作区内写入允许，shell、网络与工作区外写入经 dsh 询问。
- **界面**：关掉 `ui-layout`、`ui-sidebar`（退路时重新打开）、DeepSeek 的品牌、账户、搜索、会话日志与插件设置页、预设选择、修改卡片。“实验插件”组没有可关的行，按 `data-plugin-group="extensions"` 隐藏。

### 6.7 观测数据

运营者在启动 `presmium studio` 的环境中设置 `PRESMIUM_TELEMETRY_URL`（OTLP/HTTP 日志地址，如 `http://collector:4318/v1/logs`）后，作者在工作台的操作与每个会话的 AI 轨迹持续上传并可互相关联；不设置时什么也不建、不发。`PRESMIUM_TELEMETRY_HEADERS`（`键=值,…`，值按 URL 编码）给出请求头，可选的 `PRESMIUM_TELEMETRY_USER` 成为 `user.id`。

- **会话轨迹**：每个 `session/event` 原样成为一条 `session-log` 记录，另带 `presmium.turn`、`presmium.document`、`presmium.workspace`。
- **作者操作**：`@lincyaw/workbench` 的 `OperationLog` 按顺序记录作者的每个操作与控件点击，批量 `POST /api/presmium/telemetry`，事件名 `presmium.workbench.<操作>`。
- **关联**：交给 AI 的请求（`agent.ask`）带 `dsh.session.id` 与 `dsh.request.id`，等于会话中对应用户消息的 `data.source.rpcId`；那个 turn 的记录就是 AI 为它做的事。

交付尽力而为。界面不提示采集，告知使用者由运营者负责。

## 7. 外壳的实现

### 7.1 根布局与退路

根布局声明 `root`，子槽位与 `ui-layout` 相同（`sidebar`、`main`、`rightbar`、`shell.*`），所以 dsh 的插件不改就能挂上；它重新提供 `ctx.layout`。顶部应用栏是标志与位置路径，右侧有待确认、AI 助手、设置与帮助；设置菜单统一通用、模型与语音服务、MCP 连接、插件和自动化任务的入口；左侧是工作区侧栏（第 24 节），对话记录从 AI 助手的“对话记录”打开，在同一位置替换文稿树，关闭它或隐藏 AI 助手后回到文稿树；中央是工作区主页或打开的文稿；AI 助手按需展开。应用栏在打开文稿时显示它的上级文稿路径，每一级可点击打开。只有一个工作区，对话中的工作区选择隐藏。

**退路**：重新打开 `ui-layout` 与 `ui-sidebar` 时，文稿与版本历史作为右侧坞标签页与 `main` 的全局面板出现。

### 7.2 复用与替换

- 复用 dsh 的对话、确认卡片、会话、设置与模型设置、终端、文件、jobs、插件管理；占用品牌槽位、`settings.onboarding`、`conversation.composer` 与 `turn-error`。
- 设置只给作者语言、外观、字号、“显示代码工作视图”、快捷键、“模型”与“语音服务”。`author-settings.ts` 把作者默认值写进 profile 自己的补丁层（写进 `--patch` 会让表单拒绝作者的修改）。
- `ctx.theme.overrideTokens` 把 `--dsw-*` 令牌映射到设计令牌的明暗取值，产物经 `appearance` 跟随。工作台文字跟随 dsh 的语言；对话首页标语经 `ctx.locale.addLanguage` 替换。写进产物的文字按文稿 `lang`。
- 客户端包用 esbuild 构建，外部依赖是 dsh 外壳模块表（React 18.3.1 由 dsh 提供），输出无文档的工厂格式 `__ModuleLoader__.load`；字体以 data URL 内联。

“语音服务”通过公开 `settings.section` 登记，配音区可直达。页首说明无需设置即可配音：默认使用微软 Edge 朗读的免费音色，试听与生成时文字发送给微软；火山引擎是可选的付费服务。填写火山引擎语音 API Key，或填写配套的 Access Token 与可选 App ID；不选择控制台版本，不需要 Secret Key。密钥与 App ID 不回显、不进讲义。留空保留已存配置；输入新密钥但不填 App ID 时使用 API Key。保存立即刷新语音服务，清除恢复启动环境配置。检查配置只读本机设置，服务权限在显式播放或试听时验证。

## 8. 焦点与批注

作者指向的一切都落到同一个 `Focus`：源码的一段（`source`，服务端读出的 `excerpt`）加它在文稿中的位置（`section`、`block`、`step`）与选中的文字（`quote`）。一条 `Annotation` 是一个焦点、一句要求与状态（`draft`、`sent`、`done`、`failed`）。没有选中时，当前位置是被动的焦点，对话时自动带上。

- **交互**：单击块或选中文字就是指向它：块被标出，旁边出现工具条，之后在对话中说的话都带着它；选区消失或切换文稿时清空。批注表单在工作台中，产物页面只画轮廓与编号，因为页面中运行着第三方插件的脚本。
- **文字批注入口**：悬浮工具栏仅在选中可映射到正文的文字范围时显示文字批注。只选中动画、图表等非文字内容块时，通过预览右上角的“本步批注”添加位置批注。
- **动画与图表**：预览块的工具栏有“本步批注”，可以选择整个内容块或 `stepOrder` 中的一步；批注保存为位置锚点。动画与文字共用原生批注卡片和“发布”操作，Enter 发布、Shift+Enter 换行；点击外部或 Escape 收起，未发布内容进入同一草稿库。发布后在原处显示批注，可回复、编辑和解决，不自动打开批注栏；工具栏的数量入口查看当前步骤及整个块的未解决批注。批注栏仍按文档顺序列出并标注步骤。动画工具栏保留批注、字幕与刷新；属性入口仅用于其他组件。
- **发给 agent**：结构化文字列出每处的页面、块、源码范围、摘录（超过 20 行只给首尾）、选中文字与要求，标签按文稿 `lang`。发送失败不丢内容。
- **保存**：工作台 `POST focus`，服务端用与 MCP `locate_source` 相同的函数换成源码范围，按文稿保存最近一次焦点；MCP 有可订阅的 `presmium://focus` 与 `get_focus`。批注保存在文稿的 `comments` 中。
- **漂移**：源码改动后先按块 ID 找，再按摘录重新定位，都找不到就标为“已失效”，不悄悄指到别处。位置锚点的步骤失效时留在块上，块本身失效时才变为无锚点。

## 9. MCP 与 dsh 的工具一致

“设置 → MCP 连接”选择给外部 AI 客户端使用的连接方式，默认 stdio。stdio 配置使用当前安装自带的 Node、Presmium 命令与工作区绝对路径，无需用户另装全局命令；连接按需发现并共享工作区服务。HTTP 模式在本机回环地址增加独立 MCP 监听，端口 0 自动分配，也可填写固定端口；先成功绑定并保存偏好，再关闭旧监听，端口不可用时保留原配置。切换不改变编辑器地址，也不关闭原有 stdio 会话。偏好保存在工作区 `.presmium/mcp-settings.json`；固定端口重启后被占用不会阻止工作区启动，设置页提示重新选择。此设置控制外部连接的偏好与附加端口，工作区内部服务仍为编辑器与 stdio 运行。

升级桌面应用不会替换其他 AI 客户端已经启动的工作区服务。旧服务缺少连接配置接口时，设置页提示更新 AI 的 Presmium 启动路径、重新连接并重新打开工作区；不把接口缺失显示成暂时网络故障。

设置页能复制通用 MCP 客户端配置，或复制给 AI 的配置提示词。复制前读取当前设置；配置导出是仅所有者可执行的显式操作，HTTP 导出只含 MCP 访问令牌，不使用启动凭据。HTTP 提示词只提供服务状态文件路径与读取 `token` 字段的方法，不包含凭据值。远程浏览器中说明这些本机路径属于运行 Presmium 的电脑，不能直接当作远程 AI 电脑的启动路径。

Studio 自建工作区服务时，HTTP MCP 默认地址为 `http://127.0.0.1:4321/mcp`，使用 Streamable HTTP。直接使用 HTTP 的客户端配置 `presmium studio --verbose` 启动时打印的地址（也在设置页与日志中）与 `Authorization: Bearer <令牌>`；从打印的文件路径读取凭据，服务状态 JSON 取 `token` 字段，纯文本令牌文件直接读取。同一启动目录重启或升级后，自建服务的地址和令牌保持不变。借用已有服务时保留该服务的地址和令牌。启动器不在日志中打印令牌本身。

`presmium studio --host 0.0.0.0` 允许其他机器连接，`--verbose` 输出的 `mcp` 地址使用本机局域网地址；客户端也可将默认地址中的 `127.0.0.1` 换成服务器的固定 IP 或域名。没有指定 `--preview-port` 而 4321 被占用时（例如另一个 Studio 正在运行），Studio 换用一个空闲端口照常启动，`--verbose` 时提示这次的 MCP 地址与默认地址不同；明确指定的端口被占用时启动失败。需要多个工作区都有固定地址时，每个工作区显式指定不同的固定端口；`--preview-port 0` 明确选择临时端口。带反向代理时，MCP 使用 `--preview-url` 下的 `mcp` 路径。

直接使用 HTTP 的客户端在 Studio 重启后重新建立连接，保留已保存的地址与令牌。外部 AI 工具默认使用原生 stdio，一次配置 `presmium mcp <工作区或文稿的绝对路径>`；显式路径使目标不依赖客户端的工作目录。项目生成的 `.mcp.json` 在该项目目录启动客户端时可省略路径。已经连接原生工具的 agent 直接调用它们，命令行 `mcp tools/call` 留给没有 MCP 客户端的脚本与流水线。

默认 stdio 在首次初始化完成前准备好工作区服务：向上寻找最近的 `presmium.workspace.yaml`，没有时使用文稿目录。服务在 `server.json` 中发布启动时捕获的主包版本 `version`，安装文件更新不会改写运行中服务的身份。同版本服务可共享；新版 Studio、MCP 或 `serve` 启动时先接管旧版服务，不复用旧运行时。Studio 遇到更新版本的服务时要求升级当前应用；stdio 作为协议转接器可以连接新版服务，并保留已见版本的下限，不重新启动更旧的宿主。

多个 stdio 客户端以工作区租约协调，只保留一个宿主。MCP 代管的服务在独立 Node 子进程中运行，每次选举都从当前安装的公开命令入口加载，避免长期存活的 stdio 进程重新使用旧模块。原生 stdio 连接与宿主的寿命分开，切换后后续请求与只读通知订阅连接新服务；已发业务请求不自动重放。启动服务的连接退出时关闭自有服务并释放租约，借用者不关闭已有服务；父进程异常退出时，标准输入管道关闭使代管服务自行清理。自动启动不扩大审批；`--allow` 只配置本次启动的服务，不改已有服务的策略。`presmium mcp --compiler-only <文稿>` 显式选择独立编译，不启动或复用工作区服务。

升级通过只有本机启动凭据可访问的 `POST host-upgrade` 请求，校验原进程身份与目标版本。旧服务有业务请求、代码执行、导出、配音、转写或素材处理时保持运行，启动器等待操作自然结束；服务空闲后原子停止接纳业务请求、占用工作区写锁，再关闭服务。替换者等待资源清理和写入租约完全释放后才能接管。尚未支持交接协议的旧服务先用原启动凭据验证本机端点，再对状态仍匹配的原进程发送正常退出信号；不强制结束进程或删除租约。

后启动的 Studio 仅在默认本机监听设置下借用同版本服务，通过独立的启动凭据创建 Harness 会话，不把 MCP 所有者令牌当作启动凭据；关闭 Studio 不关闭借用的服务。原所有者退出时借用它的 Studio 一同结束；已打开的旧版 Studio 不自动迁移到新版宿主，新版应用启动负责切换。显式指定 `--host`、`--preview-port` 或 `--preview-url` 时不借用，需先结束原服务，再按这些设置启动 Studio。缺少独立启动凭据的服务不能自动接管，需结束它后用当前版本启动。

- `@lincyaw/mcp` 导出一张工具表（名字、说明、JSON Schema、种类），按文稿列出时按策略筛选，加上插件的 `AgentTool`；作者事务（`plan_document_change`、`apply_document_change` 等）复用 Web 的 `DocumentEditor` 与历史，见 [作者动作](authoring-actions.md)。
- 适配器一是 `/mcp` 与 `presmium mcp`。默认 stdio 首次目录就来自已就绪的工作区服务；同地址、同令牌的重启按服务进程身份识别。服务中断时，已发业务请求固定在原连接，只返回原结果或明确失败；未知结果先查询保存历史或任务状态，传输层不重放业务请求。后续新请求使用发现或重新启动的宿主。只读通知订阅按原过滤器重新建立，确认恢复后提示客户端重新读取订阅的资源，直到客户端取消或关闭 stdin。显式 `--compiler-only` 的执行权限由 `--allow` 决定。适配器二是 `presmium-tools`：作为 MCP 客户端用会话令牌连接回环 `/mcp`，在宿主保留完整工具元数据，模型只登记共用精简目录的 `presmium__*` 入口；按需查询参数，调用前解析并校验目标工具，按目标 workspace 路由，再转成 `tools/call`，时限 10 分钟。结果中的图片（如 `capture_slides` 的截图）在会话最近一次请求所用的模型声明接受图片时存入 dsh 的附件，作为工具结果的图片交给模型；否则模型只得到文字（`capture_slides` 的文字列出每张图的文件），另有一行说明图片未附上。候选服务复用启动 Studio 的确切 Presmium 命令及其自带的渲染端和插件，不切到裸 CLI 或另一份全局安装。编译只在服务中做一次；每个会话只登记所属文稿的工具。
- MCP 默认目录与会话中的 `presmium__*` 使用同一精简目录生成器；会话完整元数据不传给模型。审批、展示文案、候选工作区路由与审阅检查点均按真实目标工具执行，模型侧参数保持原样，不改写 Harness 的冻结 execution。模型已登记的目标定义或文稿绑定变化时拒绝旧调用，下一步请求前或空闲后重装目录；`get_focus` 仍等于会话快照中的焦点。

## 10. 没有模型与没有 dsh 时

只装核心时，CLI、静态产物、`dev`、`serve`、VS Code 扩展与 MCP 都可用；装了 studio 而没有模型时，对话以外的全部可用。`assistant-setup.tsx` 读 `session/modelCatalog` 判断有无可路由的模型；没有时接管 `conversation.composer`，说明“AI 助手需要先设置模型”，唯一操作“设置模型”，已写的草稿保留。失败的一轮由 `turn-error` 按稳定代码以作者的话说明，原文收在折叠的“技术详情”中。

## 11. `presmium studio`

### 11.1 命令与目录

工作区服务打开空目录时自动建立本地版本历史的空基准，首页直接提供“新建文稿”，无需先配置工作区。首页的文稿按文稿树的顺序列出（[IR 第 7 节](ir.md#7-工作区与命令)）。工作区中有旧格式的文稿（`lecture.json`、格式版本 1）或工作区文件仍列出 `documents:` 时，文稿列表的回答带 `migration`，首页显示“这个工作区使用旧的文稿格式”与“升级 / Upgrade”；升级调用 `POST workspace/migrate`，与 `presmium migrate` 相同，每份文稿记一次修订，完成后刷新列表。此准备允许 Finder 的 `.DS_Store`，已有目录的文件、版本库、分支与索引保持原样。

`presmium studio [目录] [--port] [--host] [--public-url] [--preview-url] [--preview-port] [--verbose]`。`DSH_HOME` 是 `$XDG_STATE_HOME/presmium/studio`；每个安装有自己的 profile `presmium-studio-<散列>`，其 `node_modules` 链接到这个安装的 bundle，因为 dsh 只从 profile 解析插件。新 profile 继承最近用过的设置。

### 11.2 启动与监管

1. 选 dsh 端口：默认本机连接先尝试该工作区上次成功使用的端口，再尝试 4320，均占用时取空闲端口；成功后只保存端口号，减少重启更换浏览器源。显式 `--port`（包括 0）、`--host` 或公开地址保持其指定语义。
2. 生成服务令牌，读取或创建持久的外部 MCP 令牌，启动 `presmium serve <目录> --port 4321 --preview-origin <dsh 的源>`；`--preview-port` 可覆盖此端口。启动前检查端口是否可用：默认端口被占用时改用空闲端口，指定的端口被占用时失败。
3. 启动 dsh：`--profile presmium-studio-<散列> --port <端口> --no-open`，加 6.6 节的补丁，环境中带服务地址与令牌。`--host 0.0.0.0` 时 dsh 在一次性的回环地址上监听，Studio 在全部 IPv4 网络接口上代转 HTTP 与 WebSocket 请求。
4. 等标准输出的 `dsh web: <网址>`：启动令牌只从这里取得，它只表示后端地址就绪，不表示浏览器界面可用；3 分钟等不到时报错并给出日志位置。
5. 标准输出只打印 `studio  <网址>`（`--host` 时另有每个局域网地址的 `network  <网址>`），标准错误一行说明在浏览器中打开它、按 Ctrl+C 停止。`--verbose` 另外打印 `mcp  <固定网址>`、MCP 令牌文件与日志文件的位置，并转发工作区服务的输出。

多文档工作区首页提供“导入文稿 / Import Documents”。工作区所有者可选择 PowerPoint、Word、Markdown 文件或文件夹，每个文件生成一份文稿，目录、本地图片与幻灯片的规则见 [IR 第 7 节](ir.md#7-工作区与命令)。选中旧版 `.doc`、`.ppt` 时对话框提示先另存为 `.docx`、`.pptx`（只有这类文件时不能导入，服务端对只含这类文件的批次回答 `document-import-legacy`）。单次最多上传 1000 个文件、合计 32 MiB，转换后的文件同样受此限制。本批的顶层文件夹都未被占用时直接放在工作区根目录（导入一个文件得到 `<文件名>/`）；只有一个且已被占用时用第一个空闲的 `<名称>-<n>/`；有多个且其中有被占用的，一起放进第一个空闲的 `imported/`、`imported-<n>/`，文稿之间的相对链接不变。本批文稿按导入顺序放在文稿树顶层的末尾（各自的 `placement`），工作区配置不变；重新导入创建独立副本，不覆盖已有文稿。整个批次校验后通过文稿锁与本地编辑历史一次发布，失败回滚文件；发布后工作区服务让文稿索引立即读入新文稿（不等文件监听或定期扫描），工作台刷新文稿列表与文稿树，提示“已导入 N 份文稿”并附需检查的链接、图片和格式转换提示数量；只导入一份时直接打开它，多份时提示带“打开 / Open”，打开第一份。单文稿工作区与只读连接不提供此入口。

浏览器先显示统一的 Presmium 启动界面，文稿列表读入成功或得到可重试的列表失败后交接工作台；不等待 AI 会话恢复，也不按固定时间隐藏。早期导入或运行失败显示本地化说明与“重试”，30 秒未完成时提示仍在打开；“详细信息”始终可进入底层诊断。启动脚本与样式是同源外部资源，严格 CSP 下可用；JavaScript 不可用时仍可通过“详细信息”查看诊断。

启动入口在分派 Studio 后才加载其他命令的编译与导出依赖。已有 profile 的根配置、已安装依赖和额外 bundle 保留；仅内容改变时写清单，正确的依赖链接不重建。

输出写进 `$DSH_HOME/presmium-studio-<散列>.log`；`--verbose` 时标准错误另外转发工作区服务的阶段与耗时。Unix 子服务通过父进程看门狗与进程组退出；Windows 的进程树清理不采用 Unix 进程组保证，需要按该平台验收。

`@lincyaw/dsh` 直接依赖 Harness 使用的 `node-addon-require-builtin`。
启动器通过该包公开的 `package.json` 导出定位其依赖目录，加入 Harness 子进程的 `NODE_PATH`，并保留调用者已有的搜索路径。
共享原生加载器由此能在 pnpm 的严格依赖布局中找到平台预编译包，普通全局安装与项目安装使用同一启动流程。

### 11.3 模型、局域网与代理

- 只用 dsh 的模型设置。启动 Studio 的环境中的 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_SEARCH_BASE_URL` 原样传给 dsh；`PRESMIUM_MODEL_URL`、`PRESMIUM_MODEL_KEY`、`PRESMIUM_MODEL_PROVIDER` 三者齐全时映射为 `DEEPSEEK_*` 并优先；界面中保存的密钥优先于环境。
- `--host` 接受本机的一个具体 IP，也接受 `0.0.0.0`。通配地址启动时打印每个局域网接口的访问地址，并警告没有登录。
- 局域网 HTTP 支持文稿编辑、自动保存、正文与批注及组件参数的本地草稿恢复、AI 草稿读取和已有音频的导入。内容指纹统一为 SHA-256；有 Web Crypto 时使用原生实现，否则使用浏览器内的等价实现。麦克风录音仍取决于浏览器提供的 `getUserMedia`。
- `--public-url` 交给 dsh，`--preview-url` 交给工作区服务（可带路径前缀）。预览应与工作台不同源，代理不得注入 cookie 或改写 `Origin`。云端按此为每个用户运行一个 Studio，见 [云端](cloud.md)。

### 11.4 桌面版

`packages/desktop` 用 Tauri 2 把 Studio 做成 Windows、macOS 与 Linux 的桌面应用，不改 Studio 与 dsh。安装包带构建时的 Node（sidecar `presmium-node`）与 `pnpm deploy` 得到的 `@lincyaw/presmium`（资源 `runtime/`），用户不需要另装 Node 或 pnpm。

1. 安装包内含 `examples/gallery` 的完整源码快照：课程、功能合集、教程、小课、宣传片与动画参考，以及素材和已提交的配音缓存；技能效果集的软链接展开为普通文件，不含依赖目录与构建产物。没有最近工作区时，内置 Node 把快照连同初始 Git 历史复制到应用本地数据目录的 `gallery-workspace`，通过临时目录完成后原子改名，自动打开这份可编辑副本；依赖链接到内置运行时，不需要下载或安装示例依赖。已有副本和作者修改在升级后保留；副本配置与依赖链接有效时跳过准备子进程，应用移动位置后更新依赖链接；编辑与版本历史使用系统 Git。后续启动重新打开上次的工作区。启动页列出最近打开的工作区，“打开工作区…”选择文件夹，菜单“工作区 → 打开工作区…”随时切换。示例准备失败时启动页给出本地化说明与“详细信息”，仍可打开其他工作区。
2. 打开工作区时应用运行 `presmium-node runtime/…/presmium.mjs studio <目录>`，读到 `studio  <网址>` 后窗口转到该网址，3 分钟等不到时停止并报错。已打开且仍存活的同一工作区直接复用并聚焦窗口，不重新启动服务；从启动页返回时沿用首次导航的登录恢复逻辑。同一时间只有一个 Studio；切换到另一工作区或退出应用时先停止它（Unix 上发 `SIGTERM`，宽限后强制结束）。桌面应用保持 Studio 的标准输入管道，并设置内部变量 `PRESMIUM_STUDIO_PARENT_PIPE=1`；管道关闭时 Studio 退出，释放自己的服务，启动阶段也适用。该变量在启动子服务前移除。Linux 另由内核在应用被强制结束时停止 Studio。示例快照的 TypeScript 配置在打包时合并仓库基准，成为独立配置；已有示例副本中原样的 `../../tsconfig.base.json` 引用失效时，补入基准编译选项并保留作者自己的选项，其余自定义配置保持不变。
3. dsh 的登录 cookie 是 `SameSite=Strict`。窗口从启动页（另一个站点）转到启动网址时，跳转可能不带 cookie；首次加载得到 dsh 的纯文本登录错误时，应用从 Studio 自己的页面重新加载一次。
4. Studio 意外结束时窗口回到启动页，说明原因并提供“详细信息”（这次启动的输出）。
5. 启动页具有工作区选择命令；Studio 的页面通过 `DesktopHost` 仅能读取应用更新状态、触发原生签名更新流程、拖动及缩放当前窗口。Tauri 的应用命令全部显式加入权限表，启动页权限只给本地页面；远端能力只给主窗口的回环地址，并在每次命令调用中再次核对当前运行的 Studio 的确切来源与首页路径。其他窗口、预览、其他回环服务与外部页面不能使用这座桥，也不能取得启动页的文件与进程命令。桥由桌面端通过公共 Tauri API 注入，网页会话保持普通应用栏。指向本机的新窗口留在应用中，其他链接在系统浏览器中打开；下载存入“下载”文件夹并在文件管理器中显示。
6. 菜单与启动页的语言按系统语言（zh-CN 或 en）；Studio 页面的语言由 Studio 自己决定。
7. `.github/workflows/desktop.yml` 构建六个平台的安装包（Windows 的 NSIS `.exe`，macOS 的 `.dmg`，Linux 的 `.deb` 与 `.rpm`）。推送到 `main` 构建成功后，安装包替换滚动预发布 [`desktop-latest`](https://github.com/Lincyaw/presmium/releases/tag/desktop-latest) 的内容；发布 GitHub Release 时附加到该 Release。没有签名证书时，macOS 应用只做临时签名（ad hoc，`signingIdentity` 为 `-`），没有经过苹果公证；完全不签名的应用下载后会被 macOS 报为“已损坏”。

Linux 默认构建 DEB；随后 `pnpm --filter presmium-desktop bundle:rpm` 用已编译的二进制生成 RPM，不重新编译。RPM 元数据使用数字基础版本，预发布的 release 为 `0.<预发布标识>`，稳定版为 `1`；二进制与更新签名保留主包完整版本。CI 同时提供 DEB 与 RPM。

桌面应用版本跟随主包版本。正式构建启动时及每 6 小时自动检查；手动“检查更新…”始终保留在原生菜单中。应用栏与启动页只在已发现新版本时显示更新图标，正常状态不占位置。发现更新、正在下载、待重启及重试用对应图标或加载状态表示，完整说明、版本与下载百分比在悬停提示及可访问名称中提供。后台检查只更新图标，网络失败保持安静。点击更新图标开始下载；手动菜单检查仍可先询问下载。下载与编辑并行，完整校验通过后再提示作者保存文稿、处理未提交表单与录音并重启安装。作者选择稍后时保留当前候选包；再次点击时重新核对版本与签名，已校验的缓存可直接进入重启确认，旧候选缓存会清理。安装前停止应用拥有的 Studio，借用的服务在新版启动时按服务版本执行上述交接；签名验证、下载地址、缓存与安装均由原生进程掌握，网页不能指定更新地址或安装字节。

更新使用 Tauri updater 的版本绑定签名，公钥随应用发布，私钥由仓库 Actions 加密密钥 `TAURI_SIGNING_PRIVATE_KEY` 提供，密码可由 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` 提供。六个平台全部成功后，将最终包（DEB 重压缩后重新签名，并用应用内的公钥验证最终字节及版本）上传到对应版本 Release；已发布的同名文件不能改写为其他字节。固定 `desktop-updates/latest.json` 最后发布，列全 macOS app、Windows NSIS、Linux DEB/RPM 的架构与格式；较旧构建不得覆盖较新的更新。`desktop-latest` 是独立的滚动预览，不推进自动更新。尚无更新功能的旧版须手动安装一次支持更新的版本。

macOS 签名使用 `packages/desktop/src-tauri/Entitlements.plist`，保留 Hardened Runtime，为内置 Node 的 V8 引擎声明 `com.apple.security.cs.allow-jit`，并用 `com.apple.security.cs.disable-library-validation` 允许 Node 加载 sharp 等原生扩展及工作区插件。构建流程在签名后实际执行 JavaScript 并加载 sharp。启动日志记录无法创建进程的原因和后台进程的退出状态；即使 Node 在 JavaScript 初始化前崩溃，也能从“详细信息”定位。

## 13. 三条命令的分工

`presmium serve` 是工作区服务加产物（文稿卡片、各文稿页面、`/mcp`），`presmium dev` 是一份文稿的实时预览加“在编辑器中打开”，两者都没有编辑界面，也不需要 dsh。`presmium studio` 是工作台，需要 dsh，可以不配模型。

## 14. 安全与隐私

工作台只经 dsh 的栅栏访问 dsh（HttpOnly、SameSite=Strict 的 cookie，外来 `Origin` 或 `Host` 时 403），预览与它不同源（4.3 节）。同一 uid 能读的东西是残余风险（[架构](architecture.md)）。

## 15. dsh 的已知限制

- 品牌文案没有覆盖机制：语言包加逐行关掉，zh-TW 等仍显示原文。
- 布局契约只有 README，工厂格式无文档，客户端包不能带静态文件：启动审计、自己的 esbuild 插件、字体内联。
- 回答者看不到工具参数：`displayReason` 带摘要。预设的 persona 补丁按 ID 找不到：另声明 `preset-authoring`。修改摘要只在内存中：审阅记录由工作区服务保存。
- Linux 网页不许 Mod+Alt 组合：用应用栏按钮收起对话记录。

## 16. 作者看到的对象

文稿是唯一权威入口 `index.pmd`。页面是稳定 ID 的 `Section`，放映时是一张幻灯片。内容块是页内的正文、教学代码、动画或插件内容。步骤以稳定 Step ID 保存、`stepOrder` 定序，界面从 1 编号。讲稿是 `Narration`，由 `Step.narrationIds` 引用。配音由讲稿合成或录制，字幕由讲稿派生，转写文本与讲稿分开。编排是 `Production` 中的时机与停顿，时间线由讲授计划派生，不另存工程。BlockNote 状态、素材面板与时间线布局都不成为第二份文稿。

## 17. 三个入口

| 区域 | 文档编辑 | 编译放映 | 视频制作 |
|---|---|---|---|
| 工具栏 | 页面、撤消、恢复、保存、批注、导出 | 编译、预览、放映、诊断 | 播放、剪辑、配音、录音、视频导出 |
| 中间 | 连续的 BlockNote 文稿 | 已编译版本的页面与步骤 | 当前画面与三轨时间线 |
| 辅助面板 | 内容属性、批注、版本历史 | 编译状态与失败原因 | 步骤、讲稿、音色、字幕、素材 |

- 入口只由作者显式切换：编辑、保存、选区、打开面板与跳步都不进入放映或视频制作。每个入口各自保存面板、选择与草稿，切换保留返回点，不替另一入口提交输入。
- “阅读与运行”默认使用查看器的 `scrolly` 视图：整份文稿连续上下滚动，左侧动画固定在阅读位置，右侧按步骤展示对应字幕；双栏铺满可用画布宽度，窄屏上下排布。阅读中的代码修改只属于本次运行。切换前后工具按钮都位于工具栏右侧。第一个步骤从页标题定位，窄屏的后续步骤定位在固定动画下方，避免遮住正文。
- **图标优先**：工具栏、块工具、步骤导航与放映控件用 `@lincyaw/design` 的语义图标；阅读、放映、视频制作这些入口也是图标按钮；视频制作标题栏中带文字的主要操作只有“导出”。图标按钮有本地化的 `aria-label`，悬停与聚焦显示名称与快捷键；字段名、错误与破坏性确认保留文字。

## 18. 文档编辑

- **正文**：一个全篇 BlockNote 编辑器直接编辑结构化文稿，页面导航只滚动定位；公式、表格、图片等保存为类型化节点。编辑器占满整张纸，单击最后一块之下的空白处，光标落到文稿末尾的空段落（没有就在最后一页末尾新建一段）；每页末尾的空段落即使没有光标也显示输入提示。
- **页面**：页面栏的加号在当前页之后新建独立页面并选中它的默认标题，输入即替换标题，在标题末尾按回车进入正文的空段落；斜杠菜单的“新页面”在光标所在的块之后分页，同样选中新页面的默认标题；在空行中使用时，这一空行移到新页面作为它的第一行，除非它是原页面唯一的内容。第一页的标题与文稿标题相同时两者一起改（[IR](ir.md) 2.3 节），文稿树、路径与导出随之更新；块的加号只在本页插入块。重命名、复制、移动、删除各是一个可撤消的版本；删除前显示关联的讲稿数。
- **公式**：公式块与行内公式保存 LaTeX，选中时弹出 LaTeX 输入框，“确定”或 `Enter` 关闭；弹出框中的“可视化编辑”打开“编辑公式”对话框：上方是 MathLive 的可视化输入，下方是同一个公式的 LaTeX，两边互相同步，“确定”写回公式并把光标放到公式之后（公式块之后没有正文时添一个空段落），“取消”回到弹出框。MathLive 不在工作台的脚本中，由 Studio 在 `api/presmium/math-editor/` 提供，第一次打开对话框时加载；宿主没有提供时只有 LaTeX 输入。关闭的弹出框不在无障碍树与 Tab 顺序中。
- **生成内容**：作者经公开参数、对话或批注修改，不看实现代码。共享素材默认修改“仅此处”，选“所有引用”才改共享素材。处理中保持上次成功的画面。斜杠菜单的“用 AI 插入动画…”不插入任何内容：它把焦点设为菜单所在的块，打开 AI 助手并在输入框中写好指明该处（第几页、哪一段之后或页末）的请求，光标在末尾，由作者写明要演示什么再发送；没有模型时草稿留在“设置模型”提示之下。
- **字幕**：本步讲稿使用一个 BlockNote 编辑器，每个内容块对应一份讲稿。
内容块通过加号或 Enter 新增，通过内容块菜单删除，也可以用 Backspace 合并；新增、删除与文字共同保存，并由同一个编辑器撤消和恢复。
删除全部内容块后保留输入位置，文稿中的本步讲稿列表为空。
文档中同时提供配音开始时机，完整制作设置在视频制作中编辑。
- **批注与 AI**：BlockNote 原生的评论扩展，跨块跨页，可逐条或批量交给 AI。AI 的修改接受或拒绝都保持作者位置，新版本显示后短暂闪烁受影响的块。
- **材料到成稿**（目标，尚未实现）：作者提交一批材料，AI 分阶段生成，成稿以互相依赖的修改组为单位审阅采用。

## 19. 视频制作

桌面采用四个停靠区域：左侧页面／素材，中央画面及一组步骤和播放控件，右侧讲稿／配音／字幕属性，底部全宽时间线。三条分隔线可拖动、键盘调整或双击恢复默认；导出放在弹窗。窄屏标签切换保留编辑器与草稿。嵌入预览隐藏查看器自身控制栏，普通放映保留。

- **选择**：画面与放映共用查看器；时间线、步骤选择器与属性指向同一个当前步骤。
- **配音**：视频制作中点击播放即开始一个可取消的按需生成意图：精确缓存直接播放，遇缺失段落时暂停原播放器，经共享配音任务生成、缓存后在同一预览中续播。跨步提示使用页面范围；显式静音与原录音保留。暂停、跳步、开始其他音频、源码或工程版本变化会终止旧意图。“生成全部配音”用于批量准备，打开时范围是整份文稿，显示待生成段数、音色名称与讲稿的去向，开始后在同一窗口显示进度；打开、跳步、编译和普通放映不隐式生成。讲稿修改后字幕立即跟随，旧配音标为需要更新。
- **音色**：配音页显示当前音色的名称、性别与语言（“晓晓 · 女声 · 普通话”），不显示服务的音色标识。“选择音色”一次完成：列表先列文稿语言与地区的音色，未选择过时预选第一个；“试听”直接播放，窗口说明试听和生成时文字发送给哪个服务；“使用此音色”写入文稿默认，单独设置过声音的步骤保持不变，窗口事先说明用于多少步骤、保留多少。范围（本步、多个步骤、本页、整份文稿）、静音、跟随整份文稿、语速、风格与是否改写单独设置都在“更多设置”中；“本步单独设置…”打开同一窗口，范围为本步。音色按步骤、页面、文稿默认继承，只显示服务支持的参数。
- **录音**：先成为本步候选，试听后显式采用为本步配音；转写文本显式“采用为讲稿”才写入。
- **时间线**：画面、配音、字幕三条对齐主轨，播放头所在步骤是唯一的选择，聚焦讲稿前先暂停。配音时机 `during` 与动画同时开始，`after` 在动画结束后开始；时刻由讲授计划派生。`during` 的步骤中，动画场景的状态在预览与导出中延长到本步配音结束。缺失配音的区间显示估计值，播放在该音频边界缓冲；任意时间定位与导出仍需确认时长，未知动画时长不能按时间播放。讲授中没有的页面（内容都限定在其他形态、又没有讲稿与音频），时间线显示“不在讲授中”，讲授中有的页面上选中这样的一步时时间线下方说明这一步不在讲授中，预览也不显示别的步骤的字幕；在这样的页面或步骤上加载播放时，画面转到其后第一个讲授中的步骤（文稿末尾时为其前最后一个）。
- **剪辑**：停留、停顿、音量、导入音频的入出点都是可撤消的结构化属性，原文件保留；不切断程序动画。视频文件与字幕重新对齐尚未接入。
- **时机**：最短停留与结束停顿以秒显示与输入（一位小数），保存为毫秒。
- **字幕大小**：步骤属性的“字幕”页顶部的滑块设定整个文稿的字幕大小（70% 到 160%，每档 10%），写入 `production.captions.scale`，与步骤时机一样记为一次文稿修改；保存后画面重新准备，预览的字幕随之变化，导出视频中烧录的字幕也按它。

## 20. 位置、草稿与状态

- **位置**：目标以页面、块与稳定 Step ID 标识，序号不充当跨版本身份。选另一步时先暂停；无法对应时报告原位置失效，草稿不按新下标重绑。
- **保存**：输入停顿 600 ms 后排队保存，失焦立即排队，输入法组字期间不提交，`Mod+S` 立即保存。同源写入串行并按源版本校验；收到新版本时，将尚未保存的作者输入重放到新版本上，重叠字段采用作者输入，结构不兼容时保留作者完整文稿。恢复编辑器时保持光标位置。断网或无法确认保存时保留草稿并说明。未确认的草稿备份在 IndexedDB；版本历史将本地草稿与已保存版本分组列出，正文不显示草稿发现提示。桌面的版本历史入口显示草稿数，窄屏在“更多”的同一入口显示数量。每份草稿可以直接恢复或放弃，也可全部放弃当前列表中的草稿；退休标记只作用于点击时的确切版本，其它窗口的新输入保留。恢复后仍由作者检查并保存。摘要统一使用 SHA-256，普通网络 HTTP 地址与本机地址使用相同格式，兼容已有草稿。
- **撤消**：编辑器内由编辑器处理；焦点离开后工具栏的撤消作用于文稿版本。文稿页面内（正文、引用、同步块、内容块预览）按 `Mod+Z`、`Mod+Shift+Z` 只撤消、恢复编辑器自己的修改，编辑器没有可撤消的修改时什么也不做，不撤消已保存的版本；沿引用打开的文稿，光标落在它的正文中。格式升级与文稿的创建是版本历史的边界：不提供撤消，也不能撤消或还原到它之前（`history-format-boundary`），所以撤消不会留下旧格式的文稿或删掉文稿。
- **状态**：保存、编译、配音、导出各有状态；“已保存”不代表编译或导出完成，旧任务结果不覆盖新状态。编译失败保留上次成功的预览并标出版本。作者看到可读的诊断说明与“详细信息”：正文上方只有一行问题数，列表在“详细信息”打开的对话框中；同一原因的多条（例如多句讲稿缺配音）合并为一条，写明句数与所在页面。

## 21. 放映与演示者视图

- **观众视图**隐藏所有编辑区与 AI，底部一条控制栏：播放与暂停、上一步、下一步、总览、字幕、演示者视图、全屏、退出、时间码与进度条。进入时不自动播放、不合成；字幕浮在画布底部安全区内。只显示已确认修订的画面；新修订未确认时画面关闭，底栏仍可重新编译或退出。
- **演示者视图**有当前页、下一页、讲稿、计时与控制；观众窗口只同步画面、步骤、字幕与播放状态。

| 范围 | 按键 | 操作 |
|---|---|---|
| 打开文稿时任何位置 | `Mod+S` | 立即保存 |
| 编辑器外 | `Mod+Z`、`Mod+Shift+Z` | 撤消、恢复 |
| 放映与视频制作，输入框外 | `←`、`→`、`Space` | 上一步、下一步、播放与暂停 |
| 放映，输入框外 | `O`、`Shift+F` | 总览、全屏 |
| 浮层或放映 | `Esc` | 先关最上层，再退出放映 |
| 任何位置 | `Mod+K` | 搜索文稿与正文 |
| 文稿树 | `↑`、`↓`、`Home`、`End`、`←`、`→` | 移动、折叠与展开 |
| 文稿树 | `Enter`、`F2`、`Delete`、`*`、字母 | 打开、重命名、移到回收站、展开同级、按标题跳转 |
| 文稿树 | `Shift+F10`、菜单键 | 打开这一行的菜单（与“更多”相同） |
| 搜索对话框 | `↑`、`↓`、`Enter` | 选择结果，打开选中的结果（输入框中按 `Enter` 打开选中的或第一个结果） |
| 正文 | `@`、`[[` | 打开文稿选择列表，`↑`、`↓` 选择，`Enter` 插入引用，`Esc` 关闭 |

输入框、编辑器与菜单保留所有按键；预览获得焦点时经 `shortcut` 把意图交给工作台。

## 22. 导出

导出面板列出渲染端与插件可用的格式；文档编辑工具栏的“导出”与视频制作的“导出”是同一个列表（包括讲授与讲授视频）。导出使用明确的已保存版本，导出器重新编译后版本不同就拒绝；有待审阅修改或编译失败时说明尚未包含的内容。带配音的视频要求片段齐全有效。放映与视频消费同一讲授计划。

- **下载**：作者在本页开始的导出，完成后浏览器自动下载它的文件（网站为压缩包，其余为 PDF、PowerPoint、视频等主文件），并弹出提示“已导出…，已开始下载”，带“打开”（只对浏览器能直接显示的网站、PDF 与视频）与“下载”；离开导出面板也照样跟踪到导出结束，换到另一份文稿时不再跟踪。下载的文件以文稿标题命名（`?download=<标题>`，扩展名不变）。AI 开始的导出只出现在导出记录中，不自动下载。
- **网站压缩包**：网站类导出（主文件为 `index.html`）另按文稿自己的 `base`（默认根路径）再构建一次并打成 `<形态>.zip`（任务的 `archive`），可以解压后放到任意静态托管；导出记录中网站有“打开”与“下载压缩包”。
- **失败**：任务的 `error` 保留服务端原文（AI 与 MCP 读取它，并写入“详细信息”的最后一行）；作者看到的是按原因映射的目录文本：缺少 Presmium 自带的组件（重新安装 Presmium）、缺少浏览器组件、MP4 缺少 FFmpeg、还没有配音、磁盘已满，其余为“展开详细信息查看原因”。失败也以提示告知。

## 23. 视觉、窄屏与可访问性

- 控件外观、尺寸与热区由 [设计系统](design-system.md) 定义，业务 CSS 只负责布局。
- 比页面宽的表格与公式在原处横向滚动，有更多内容的一侧显示阴影。
- 768 px 以下单主区域显示，工具栏保持单行，次要入口收进“更多”，视频制作的画面与时间线纵向排列；切换不丢草稿。
- 状态不只靠颜色，触屏不需要悬停，尊重减少动态效果。亮色与暗色、桌面与 768 px 以下四种组合都看过才算完成。
- VS Code 扩展的日常入口是原生 JSON 编辑、诊断、预览与放映，按需在 Integrated Browser 中打开同一个工作台。

## 24. 工作区侧栏、文稿树、引用与同步块

- **侧栏**：工作区名称与文稿数、搜索（`Mod+K` 打开搜索对话框，按标题与正文搜索 `documents/search`，结果写明上级路径，正文匹配附上句子，`Enter` 打开到匹配的页面或内容块）、主页、最近打开（本浏览器记录的最近 12 份）、文稿树、回收站。768 px 以下，侧栏是应用栏菜单按钮打开的抽屉，选中文稿后关闭。
- **文稿树**：`GET tree` 读取，`tree` 事件（Studio 事件连接上的 `tree` 主题）到达时重读；树没有变化时保持原对象，不触发重绘。打开的文稿在树中选中，它的上级自动展开。行的悬停操作是“新建子文稿”（+）与“更多”（重命名、新建子文稿、创建副本、移动到…、移到回收站）；右键一行（或 `Shift+F10`、菜单键）在指针处（键盘时在行下方）打开同一个菜单，不选择就关闭时焦点回到这一行。双击或 `F2` 在行内重命名，`Enter` 确认、`Esc` 取消。拖动一行放到另一行的上部、中部或下部，分别放在它之前、作为它的最后一个子文稿、放在它之后，目标行显示放下的位置，不能放进自己的子文稿；`Esc` 取消。移动、移到回收站之后，底部提示说明结果并给出“撤消”（移回原处，或从回收站还原）。可见行超过 200 时只绘制视口中的行。
- **新建**：侧栏的 + 新建顶层文稿，行的 + 新建子文稿；新文稿打开，标题在树中处于重命名状态。
- **回收站**：列出移到回收站的文稿（含其子文稿数与删除时间；上级文稿也在回收站中的，写明单独还原时放在顶层），“还原”放回原上级（原上级在回收站中或已不存在时放到顶层，底部提示说明放到了顶层与原因），“永久删除…”先说明其他文稿中来自它的同步块会转为副本、指向它的引用会显示为已删除，再确认。
- **主页**：标题与文稿数，“空白文稿”“导入文稿”与“从来源材料写作”，需要处理，最近打开。需要处理按类各一条，每条写明数目，“查看”打开第一个有问题的地方：等待升级的文稿数与“升级”、上级无效的文稿、目标已删除或在回收站中的引用、原内容已删除或在回收站中的同步块（后两类来自 `tree/attention`，随 `tree` 主题上的 `attention` 事件重读）。
- **从来源材料写作**：作者选择来源材料（PDF、Word、PowerPoint、图片、文本等，最多 20 个文件、合计 32 MiB），可以写几句想要怎样的文稿；Studio 在文稿树顶层末尾新建一份文稿，把文件原样存进它的 `materials/`（`document/materials`，一条修订），打开它，再把“根据来源材料写这份文稿”的请求连同文件路径与作者的话发送给 AI（与“用 AI 改写”同一条路径）。文件存不进去时新建的文稿移到回收站。没有 AI 助手时不显示这张卡片；AI 助手的对话还在启动时卡片已在原位，暂不可点，启动后可用，主页不因它出现而移动；AI 助手还没有模型时，卡片说明需要先设置模型，点击打开“设置 → 模型”。工作区还有旧格式文稿时不显示空状态，而是说明有多少份等待升级。工作区服务没有文稿树路由时，主页仍是文稿列表与它的操作。
- **右栏**：标签页“目录”（页面列表与新建、重命名、复制、移动、删除页面）、“引用”（引用了本文：按文稿归组，每处写上下文句子，同一文稿的多处写明是第几处；本文引用与同步块：同一目标只列一行并写处数；每处与每行末尾有“在右侧打开”图标按钮，目标已删除时没有）。右栏的内容不超出它的宽度：卡片占满宽度、长标题换行，单行项目截断并在悬停时显示全文、“批注”。版本历史、字幕与导出仍从工具栏打开。宽度足够（文稿区不小于 `--pm-layout-roomy-width`）时右栏与页面并排并默认显示目录，否则浮在页面上并默认关闭。窄屏的引用是文稿末尾一行可展开的摘要。
- **引用**：正文中的引用显示目标当前的标题与文稿图标，目标已删除时显示最后已知的标题并划去。指针停留 500 ms（或键盘聚焦）后显示预览卡：路径、标题、开头一段、页数、步数与被引用次数，“打开”与“在右侧打开”；移开后 300 ms 内移到卡片上保持显示，选了其中的操作后卡片关闭。触屏没有悬停：轻点引用立即打开预览卡而不跳转，再点一次或点卡片以外关闭；鼠标的行为不变。预览在指针到达时开始读取，按目标缓存到树变化为止。单击或 `Enter` 打开目标，并定位到页面或内容块。在正文中输入 `@` 或 `[[` 打开文稿选择列表：还没有输入时列出最近打开的文稿，再按文稿树的顺序列出其余文稿（共 8 份，不含本文稿）；输入停顿 100 ms 后搜索，新输入取消旧请求，等待期间保留上次结果；最后一项“新建子文稿“…”并链接”在当前文稿下新建子文稿并插入引用，不离开正文。斜杠菜单另有“链接到文稿”“同步块”“子文稿”；“子文稿”与文稿树中行的 + 新建的子文稿名为“未命名子文稿 / Untitled child document”，打开它输入第一页标题即为它命名。
- **在右侧打开**：右栏换成目标文稿的只读内容，当前文稿留在原处可以继续编辑。标题栏是上级路径（点击其中一级在右栏打开它）、标题、“打开”（与预览卡的“打开”相同）与关闭；内容按页面列出（`GET document`，与同步块共用只读绘制），滚动到引用的页面或内容块并以浅强调底标出；引用整份文稿时从开头显示，不标出任何位置。其中的引用在右栏打开它的目标，替换当前的内容；同步块写“同步自”与来源，点击在右栏打开来源。`Esc` 或关闭回到右栏之前的标签页；打开另一份文稿时右栏的文稿关闭。目标在回收站中或已删除时说明。目标保存后（它的 `document` 事件，停顿 300 ms 后读一次，版本不变不读）与文稿树变化（标题、路径）时更新，新的目标取消仍在进行的读取，正文的输入不触发读取；长文稿分几帧绘制：第一帧 60 个内容块，之后按上一帧的耗时加倍或减半，任何一帧都不长时间占用页面。宽度足够时右栏加宽到 `--pm-peek-width`（不超过一半），否则与其他右栏内容一样浮在页面上，768 px 以下占满宽度。
- **同步块**：显示另一份文稿中一个内容块及其下级内容当前的样子（`embed/source`，按来源缓存），只读；标题栏写“同步自”与来源（文稿 › 内容块），悬停或聚焦时显示“编辑原文”（打开来源并定位）与“转为副本”（`embed-to-copy`）。来源在回收站中时仍显示内容并说明；来源不存在时说明原内容已不存在。加载期间保留固定高度。同步块在步骤中与普通内容块一样设定可见性。内容块菜单的“复制同步块链接”复制一个链接，粘贴到另一份文稿即插入同步块。
- **继承的设置**：工作台中显示的继承设置——字幕大小、音色与步骤的播放时机（配音开始、最短停留、结束停顿）——在文稿自己没有设定时注明值来自哪里：设定它的最近一级上级（“继承自“上级文稿””），或工作区 `defaults:`（“继承自工作区默认设置”）；`GET document` 的 `inheritedFrom` 给出每项设置的来源，服务没有给出时写上级文稿。文稿自己设定了字幕大小而上级也有时，“使用继承值”删除文稿自己的设定；音色在“选择音色”中选“继承”，步骤的时机用“使用继承的时机”。语言、插件、渲染端与插件配置、执行与检查在工作台中没有显示或编辑的地方，不加说明。
- **性能**：引用与同步块的节点按目标的原始值记忆，输入时不重绘；同一目标的标题来自共享的文稿树，预览与同步块来源各自只读一次。打开文稿不等待引用列表，右栏单独加载。
