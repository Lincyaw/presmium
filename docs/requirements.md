# Presmium 需求规格 v0.6

本文档定义 Presmium 的需求与实现选型。Presmium 是一个面向技术演讲与编程教学的演示系统：文稿以纯文本源码编写，与代码仓库共同版本管理，演示中可以引用、运行、讲解真实代码。

版本沿革：

- v0.1：47 条需求清单。
- v0.2：按“内核最小，功能全部插件化”重新组织。
- v0.3：确定以现成组件为基础，只集成和配置，不 fork。每条需求标注由哪个组件满足、需要多少自研。
- v0.4：新增阅读与检索（6.8 节）：同一份文稿既能放映，也能当笔记阅读、搜索和翻阅。
- v0.5：确定双形态：同一份源码，Slidev 渲染幻灯片形态，VitePress 渲染网页形态。
- v0.6：引入中间表示（IR）：源码（MyST Markdown）编译为 IR，所有媒介由可插拔的渲染端从 IR 生成；网页为主媒介；新增 notebook 媒介与编辑体验需求；编辑只在源码中进行。

原编号与新编号的对应关系见附录 A。

## 1. 设计原则

1. **依赖优先，降低维护成本**。能由现成组件满足的需求，直接依赖该组件，通过其公开的扩展接口做定制；没有合适组件时才自研。不 fork、不打补丁、不做二次开发。
2. **微内核**。Presmium 自己的内核只补齐宿主框架缺失的元能力：服务注册、锚点、检查命令、故障隔离。内核不认识任何业务概念，例如“代码”“学生”“题目”“课堂”。
3. **一切业务功能都是插件**。包括身份与课堂会话、代码引用、代码执行、测验、导出。官方插件与第三方插件使用同一套接口。
4. **插件之间通过服务接口协作**。插件 A 依赖的是服务接口（例如 `session`），不是插件 B 本身。同一接口可以有多个实现，可以替换。
5. **纯文本，可复现**。文稿、动画、交互、插件配置全部以纯文本声明。依赖版本由锁文件固定，同一个提交在任何时间检出，渲染结果一致。
6. **源码即产品，IR 为中心**。编辑只在源码中进行，浏览器中不编辑。源码编译为中间表示（IR），所有媒介由渲染端从 IR 生成；渲染端可插拔，网页是能力最完备的主媒介。源语法与 IR 的定义见 `ir.md`。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 中间表示（IR） | 源码编译后的媒介无关的文稿表示，见 `ir.md` |
| 渲染端 | 从 IR 生成一种媒介的组件，例如网页（VitePress）、幻灯片（Slidev）、notebook |
| 宿主 | 浏览器中运行插件组件的框架：网页渲染端为 VitePress，幻灯片渲染端为 Slidev |
| 文稿 | 一份讲义，由一个入口源码文件及其引入的文件组成 |
| 章节 | 文稿的一个单元，对应幻灯片的一页、网页的一节 |
| 节点 | 章节中的一个内容块 |
| 步骤 | 章节内的一个讲解进度单位；幻灯片中对应“点击”，网页中对应滚动位置或全部展开 |
| 光标 | 当前所处的位置，即（页，步骤） |
| 视图 | 文稿的一种呈现方式，例如听众视图、演讲者视图 |
| 作用域 | 插件生效的范围：全局、单页、单个节点 |
| 服务 | 插件对外提供的、以名称标识的接口，供其他插件调用 |
| 锚点 | 对某个内容位置的稳定引用，不依赖物理行号 |

## 3. 内核需求

内核需求是第一阶段（M0）的交付范围。“实现”一栏的含义：

- **宿主**：Slidev 直接满足，只需配置。
- **定制**：通过宿主的公开扩展接口编写少量代码。
- **自研**：宿主不提供，由 Presmium 内核实现。

### K-01 文稿源码模型

- 文稿由纯文本文件定义，支持多文件拆分与引入。
- 每页、每个需要被引用的内容块有稳定 ID。
- 节点保留源码位置映射，用于报错定位和“从预览跳回源码”。

**实现**：自研（编译器）。源语法为 MyST Markdown，用 `{include}` 引入多文件；章节 ID 取自 MyST 标签；IR 中每个块保留源码位置。见 `ir.md` 第 2 节。

### K-02 语法扩展点

- 插件可以注册新的语法与内容类型，不修改内核解析器。

**实现**：定制。插件注册 MyST 指令（`directives`），把指令转换为 IR 节点；浏览器端通过组件名渲染。解析器为 `myst-parser`（MIT）。

### K-03 渲染管线

- 内容类型到渲染组件的注册表；渲染产物是标准 Web 元素，可嵌入任意 Web 组件。

**实现**：宿主。插件目录下的 Vue 组件自动注册；Vue 原生支持自定义元素（Custom Elements）。

### K-04 步骤时间轴

- 每页由一组有序步骤组成，插件可以向页贡献步骤。
- 支持前进、后退、跳转到任意（页，步骤）。
- 步骤必须**可逆**：跳转到第 N 步后的页面状态，与从第 1 步顺序前进到第 N 步完全一致。
- 任意视图可以查询下一步骤。

**实现**：宿主。Slidev 的点击系统（`v-click`、`v-clicks`、点击区间、`$clicks`）以点击计数为状态，天然可逆。Presmium 规定插件约定：**插件的视觉状态必须由 `$clicks` 推导，不得在事件回调中产生不可回放的副作用**。

### K-05 视图

- 听众视图与演讲者视图可在不同窗口或屏幕打开，光标同步。
- 演讲者视图显示当前画面、下一步预告、计时、步骤备注。
- 支持全屏、页面总览、键盘翻页。
- 插件可以向演讲者视图添加面板，或注册新的视图。

**实现**：宿主满足前三项。演讲者视图的面板扩展为定制：在全局图层中按渲染上下文（`$renderContext`）只在演讲者视图中显示；整页新视图通过 `setup/routes` 注册。

### K-06 状态与事件

- 分作用域的状态存储；状态可以在本视图、本机所有视图、跨设备三个范围共享。
- 跨设备同步通过传输层接口接入，内核不绑定具体网络实现。

**实现**：宿主。`createSyncState` 创建同步状态，`addSyncMethod` 接入新的传输方式。Slidev 内置本机多窗口同步；网络传输由插件以 `addSyncMethod` 接入（见 P-61）。

### K-07 插件宿主

- **清单**：插件声明 ID、版本、兼容的 Presmium 内核版本、提供的服务、依赖的服务。
- **加载**：文稿声明使用的插件及配置，可分别作用于全局、单页、单个节点。
- **生命周期**：初始化、页进入/离开、步骤变化、卸载。
- **故障隔离**：单个插件出错时只影响它负责的节点，其余内容正常放映，并在演讲者视图提示。

**实现**：

- 插件的分发与加载：宿主。每个 Presmium 插件就是一个 Slidev 插件（addon），以 npm 包形式分发，在文稿头部 `addons:` 中声明。单页作用域通过页 frontmatter 配置，节点作用域通过组件属性配置。
- 生命周期：宿主。`defineAppSetup`、`onSlideEnter`、`onSlideLeave`、`$clicks` 监听。
- 清单中的服务声明：自研（K-08）。
- 故障隔离：自研。内核提供错误边界组件，基于 Vue 的 `onErrorCaptured`。

### K-08 服务注册

- 插件可以按名称提供服务、按名称依赖服务，内核负责依赖解析。
- 依赖的服务不存在时，依赖方按声明降级运行或拒绝加载，并给出提示。

**实现**：自研。规模预计 200 行以内。

**验收**：身份与课堂会话以 `session` 服务的形式由插件提供；测验插件依赖 `session` 服务，替换 `session` 的实现时测验插件无需修改。

### K-09 工作区访问

- 插件可以读取文稿所在仓库中的文件，并监听变更；可以把数据写回仓库（例如标注、代码修改）。

**实现**：宿主满足读取与监听：文稿放在业务仓库中时，仓库根目录即宿主允许访问的工作区根目录。写回为定制：通过 `setup/vite-plugins` 注册开发服务器端点。

### K-10 锚点接口

- 定义锚点的数据结构与解析器注册表。
- 解析结果分为四种状态：精确命中、已移动、模糊匹配、丢失。所有使用锚点的插件按同一套状态处理。

**实现**：自研接口。第一个解析器直接复用宿主的 `#region` 标记语法（见 P-10）。

### K-11 开发服务器与实时预览

- 保存源码后预览增量刷新，保持当前光标位置。
- 作者可以使用自己的编辑器；在预览中可以跳回对应源码。

**实现**：自研。`presmium dev` 监听源码，只增量编译受影响的章节，通过 WebSocket 把变化的章节推送给浏览器中的 IR 运行时，运行时只重渲染这些章节（`ir.md` 第 8 节）。浏览器中不编辑。

**验收**：保存源码后 300 ms 内画面更新；不刷新页面；当前视图、章节、步骤与滚动位置保持不变。

### K-12 构建与导出

- 产出可离线放映的静态网站。
- 导出为 PDF、图片等格式；每种内容类型在静态导出中有确定的降级形式。

**实现**：宿主。`slidev build` 产出单页应用，可启用 PWA 离线缓存；`slidev export` 导出 PDF、PNG、PPTX，按步骤展开为多页。

### K-13 可复现性

- 宿主、内核、插件的版本由锁文件固定。检出任意历史提交，按锁文件安装后渲染结果一致。

**实现**：宿主。使用 pnpm 锁文件。

### K-14 主题与布局

**实现**：宿主。Slidev 主题、布局与 UnoCSS。

### K-15 输入映射

- 键盘、遥控器输入映射为命名动作，插件可以注册新动作。

**实现**：宿主。`setup/shortcuts`。

### K-16 诊断与检查

- 所有错误附带源码位置。
- 提供 `presmium check` 命令，执行全部插件注册的检查项（例如锚点是否有效、引用代码是否漂移），可接入 CI。

**实现**：自研。编译到 IR 校验阶段，汇总编译诊断与各插件注册的检查函数。

### K-17 中间表示

- 源码编译为版本化的 IR（JSON）；IR 只记录语义与已计算的结果，不含任何媒介专属语法。
- 插件可以注册指令与编译步骤；编译步骤是 IR 上的有序变换。
- `presmium ir` 输出 IR，供调试与第三方渲染端使用。

**实现**：自研（`@presmium/compiler`）。IR 契约见 `packages/kernel/src/ir.ts`。

**验收**：示例文稿编译出的 IR 通过 schema 校验；同一提交重复编译得到相同的 IR。

### K-18 可插拔渲染端

- 每种媒介由一个渲染端插件从 IR 生成；文稿在 frontmatter 中选择渲染端。
- 渲染端声明对每种节点的支持程度（完整、降级、不支持），按 `ir.md` 第 6 节的规则降级，并在构建报告中列出未渲染的块。
- 网页渲染端是参考实现，必须完整支持全部节点。

**实现**：自研接口；网页渲染端基于 VitePress，幻灯片渲染端基于 Slidev，notebook 渲染端自研（输出 nbformat 4）。

**验收**：`presmium build --to web,slides,notebook` 从同一份源码生成三种媒介；去掉幻灯片渲染端后，其他媒介不受影响。

### K-19 编译时执行与缓存

- 带 `run` 的代码在编译时执行，输出写入 IR；静态媒介因此也有真实输出。
- 执行结果按内容哈希缓存在 `.presmium/freeze/`，可随文稿提交；代码不变则不重跑。

**实现**：自研编译步骤；执行器由插件提供（本地进程、容器）。

**验收**：第二次编译不重跑未改动的代码；删除运行环境后，依赖已提交缓存的构建仍得到相同输出。

### K-20 运行时视图与动态渲染

- 浏览器中的 IR 运行时直接从 IR 动态渲染，不依赖 Markdown 生成或静态编译。
- 同一份 IR 可在运行时切换视图（文档、滚动叙事、放映），切换不需要重新构建。
- 视图与节点渲染器可插拔：插件可以注册新视图，或为某种节点、某个组件注册渲染器。

**实现**：自研（`@presmium/viewer`）；网页外壳使用 VitePress 默认主题。

**验收**：在同一页面中切换三种视图，章节与步骤位置保持；示例插件注册的新视图出现在视图切换菜单中。

### 内核自研范围小结

Presmium 内核（`@presmium/core`，本身也是一个 Slidev 插件）只包含四项自研：服务注册（K-08）、锚点接口（K-10）、检查命令（K-16）、错误边界（K-07）。其余内核需求由宿主直接满足或少量配置满足。

## 5. 依赖选型

### 5.1 宿主：Slidev

| 项目 | 内容 |
|---|---|
| 版本 | `@slidev/cli` 53.0.0（2026-09） |
| 许可证 | MIT |
| 技术栈 | Vue 3、Vite、Markdown（markdown-it）、Shiki、UnoCSS |
| 发布节奏 | 2025 年以来发布了 51、52、53 三个大版本，约半年一个 |

选择理由：

- 直接覆盖第 3 节内核需求中的 12 项，以及第 6 节插件目录中约一半的条目。
- 公开扩展面完整：插件包可以提供组件、布局、全局图层，以及 `setup/` 下的 main、routes、shortcuts、transformers、code-runners、vite-plugins、shiki、mermaid、monaco 等钩子。
- 公开的客户端 API（`@slidev/client` 的入口导出）包含导航、幻灯片上下文、同步状态、自定义同步方式，足以支撑插件化。
- 已有活跃的第三方插件生态。

对比过的其他方案：

| 方案 | 不选的原因 |
|---|---|
| reveal.js（MIT） | 与框架无关、成熟，但实时预览、代码片段引用、代码运行、导出都需要自己补，自研量明显更大 |
| Marp（MIT） | 只做静态幻灯片，没有步骤、交互与插件化渲染 |
| 自研内核 | 维护成本最高，与本版原则相悖 |

### 5.2 已验证事项

在草稿环境中用 Slidev 53.0.0 做了最小验证，以下三项构建通过：

1. 本地插件以 npm 依赖形式接入，组件和 `setup/main.ts` 被加载，组件可以读取 `$clicks`。
2. `<<< @/路径#region名` 只引入标记区间内的代码，不依赖行号。
3. 备注中的 `[click]` 标记按步骤切分备注。

### 5.4 依赖准则

1. **只用公开接口**。只使用宿主文档化的插件机制与 `@slidev/client` 入口导出的 API，不引用其内部路径。宿主自己声明，入口以外的模块随时可能有破坏性变更。
2. **不 fork、不打补丁**。宿主或依赖不满足时，先在插件层绕开；绕不开就在上游提议，同时在插件层做降级。
3. **谨慎依赖小插件**。单人维护、0.x 版本的第三方 Slidev 插件，只在“出问题时一天内能用自研替换”的前提下使用；否则自研一个薄插件。
4. **不引入 AGPL 依赖**。例如 Shepherd.js、Intro.js 已改为 AGPL-3.0，不采用。
5. **只保留一套实时通信**。所有跨设备功能共用 P-61 的同步通道，不为单个功能再引入另一套实时服务。
6. **定期升级宿主**。锁定 Slidev 版本，每个大版本发布后集中升级一次，升级时用 P-53 做全量可视化回归。

## 6. 插件目录

“实现”一栏取值同第 3 节；“依赖”一栏列出所需的内核扩展点、服务或第 5 节中的组件。

### 6.1 演示基础（M1）

| 编号 | 插件 | 功能 | 实现 | 依赖 |
|---|---|---|---|---|
| P-01 | 基础内容 | 标题、列表、表格、图片、脚注、代码高亮 | 宿主 | — |

### 6.8 媒介与检索（M1、MR）

同一份文稿有两种形态：幻灯片形态用于现场讲授，网页形态用于自学、预习、复习和查阅。两种形态由同一份源码生成，插件组件在两种形态中共用。

两种形态的对应关系：

| 幻灯片形态 | 网页形态 |
|---|---|
| 页 | 章节，带锚点，可直接链接 |
| 步骤 | 文档式下全部展开；滚动叙事式下随滚动推进 |
| 演讲备注 | 正文 |
| 插件组件 | 原样嵌入 |
| 引导动画 | 滚动叙事式下随滚动触发；文档式下显示终态 |

| 编号 | 插件 | 功能 | 实现 | 依赖 |
|---|---|---|---|---|
| P-70 | 网页渲染端 | VitePress 外壳 + IR 运行时：每个章节一节，讲解为正文，上屏内容按序嵌入；`{only}` 限定媒介；默认文档式排版，适配手机；完整支持全部 IR 节点；支持实时更新与视图切换（K-11、K-20） | 定制 + 自研 | VitePress（MIT） |
| P-71 | 全文搜索 | 快捷键唤起，搜索标题、正文、备注、代码；支持中文；结果跳转到对应章节；离线可用 | 宿主 + 定制 | VitePress 本地搜索（基于 MiniSearch），配置中文分词 |
| P-72 | 快速翻阅 | 侧边目录、页内大纲、上一节与下一节、章节深链接 | 宿主 | VitePress 默认主题 |
| P-73 | 滚动叙事 | 单页声明后，幻灯片固定在一侧，正文在另一侧滚动，步骤随滚动推进 | 定制 | P-70、K-04 |
| P-74 | 形态切换 | 幻灯片第 N 页与网页对应章节之间一键互跳 | 定制 | P-70 |
| P-75 | notebook 渲染端 | 从 IR 生成 Jupyter `.ipynb`：讲解与上屏文本为 Markdown 单元格，代码为可运行的代码单元格并附录制输出，组件按 `fallback` 降级 | 自研 | nbformat 4 |
| P-76 | 幻灯片渲染端 | 可选的高保真渲染端：从 IR 生成 Slidev 项目（章节为页，上屏内容按步骤出现，讲解为演讲备注），用于导出 PDF、圈画标注、录制；日常放映与实时预览使用 IR 运行时的放映视图 | 定制 | Slidev |
| P-77 | 放映视图 | IR 运行时中的放映视图：全屏逐章节逐步骤、键盘翻页、演讲者窗口（当前步骤讲解、下一步预告、计时）、多窗口同步 | 自研 | K-20 |

**验收**：

- 同一份示例文稿同时构建出幻灯片与网页，网页中包含每页内容与备注。
- 在网页中搜索中文关键字，300 ms 内列出结果；点击结果进入对应章节，再切到幻灯片形态停在对应页。
- 插件组件（代码引用、代码运行、测验）在网页形态中可用。

## 附录 C：说明

### C-1 关于绑定 Vue

v0.2 曾以“避免绑定前端框架”为由不选 MDX。v0.3 选择 Slidev 同样绑定了 Vue。取舍依据是维护成本：Slidev 直接满足的需求数量，远大于框架绑定带来的长期风险；可复现性由锁文件保证，历史文稿始终按当时锁定的版本渲染。

### C-2 插件权限

v0.3 只要求插件在清单中声明所需能力（文件访问、网络、代码执行），不做强制隔离。是否引入强制权限控制，待第三方插件生态出现后再决定。

### C-3 待验证事项

以下宿主能力在 M1 前需要实测确认：

- `slidev export` 导出 PDF 时，代码片段中的超链接是否保留（P-50）。
- 宿主是否尊重系统“减少动态效果”设置、对屏幕阅读器的支持程度（N-06）。
- 演讲者视图中以全局图层扩展面板时的布局效果（K-05）。
