# Presmium 需求规格 v0.7

本文档定义 Presmium 的需求与实现选型。Presmium 是一个面向技术演讲与编程教学的演示系统：文稿以纯文本源码编写，与代码仓库共同版本管理，演示中可以引用、运行、讲解真实代码。

版本沿革：

- v0.1：47 条需求清单。
- v0.2：按“内核最小，功能全部插件化”重新组织。
- v0.3：确定以现成组件为基础，只集成和配置，不 fork。每条需求标注由哪个组件满足、需要多少自研。
- v0.4：新增阅读与检索（6.8 节）：同一份文稿既能放映，也能当笔记阅读、搜索和翻阅。
- v0.5：确定双形态：同一份源码，Slidev 渲染幻灯片形态，VitePress 渲染网页形态。
- v0.6：引入中间表示（IR）：源码（MyST Markdown）编译为 IR，所有媒介由可插拔的渲染端从 IR 生成；网页为主媒介；新增 notebook 媒介与编辑体验需求；编辑只在源码中进行。
- v0.7：新增执行环境（6.11 节：具名环境、执行会话、富输出、WebAssembly、浏览器 GPU、远端环境与部署模板）、智能体（6.12 节：Presmium 作为 agent 的环境，接入 DeepSeek Harness，学习者问答、批注修改、对话修改、修改历史）、工作区与文档管理（6.13 节）、讲授轨与语音（6.14 节：录制、回放、语音转文字、文字转语音、脚本化讲授）与仓库技能（P-82）；源码仍是唯一的事实来源，agent 的修改同样落在源码上（原则 6）。

原编号与新编号的对应关系见附录 A。

## 1. 设计原则

1. **依赖优先，降低维护成本**。能由现成组件满足的需求，直接依赖该组件，通过其公开的扩展接口做定制；没有合适组件时才自研。不 fork、不打补丁、不做二次开发。
2. **微内核**。Presmium 自己的内核只补齐宿主框架缺失的元能力：服务注册、锚点、检查命令、故障隔离。内核的运行时不认识任何业务概念，例如“代码”“学生”“题目”“课堂”。多个插件共用的业务服务契约（如 `executor` 的 `RunRequest`、`session` 的 `SessionService` 与角色）放在内核包中作为共享契约：服务的提供方与使用方是不同的插件，插件之间不互相引用，契约只能放在双方都依赖的包中；内核自身不使用这些契约（`architecture.md` 4.5 与 9.2 节）。
3. **一切业务功能都是插件**。包括身份与课堂会话、代码引用、代码执行、测验、导出。官方插件与第三方插件使用同一套接口。
4. **插件之间通过服务接口协作**。插件 A 依赖的是服务接口（例如 `session`），不是插件 B 本身。同一接口可以有多个实现，可以替换。
5. **纯文本，可复现**。文稿、动画、交互、插件配置全部以纯文本声明。依赖版本由锁文件固定，同一个提交在任何时间检出，渲染结果一致。
6. **源码即产品，IR 为中心**。源码是唯一的事实来源：所有修改都落在源码上，由作者在编辑器中修改，或在工作区中通过批注与对话由 agent 修改（6.12 节），并由 git 记录；浏览器不直接修改渲染结果。源码编译为中间表示（IR），所有媒介由渲染端从 IR 生成；渲染端可插拔，网页是能力最完备的主媒介。源语法与 IR 的定义见 `ir.md`。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 中间表示（IR） | 源码编译后的媒介无关的文稿表示，见 `ir.md` |
| 渲染端 | 从 IR 生成一种媒介的组件，例如网页（VitePress）、幻灯片（Slidev）、notebook |
| 宿主 | 浏览器中运行插件组件的框架：网页渲染端为 VitePress，幻灯片渲染端为 Slidev |
| 文稿 | 一份讲义，由一个入口源码文件及其引入的文件组成 |
| 章节 | 文稿的一个单元，对应幻灯片的一页、网页的一节 |
| 节点 | 章节中的一个内容块 |
| 步骤 | 章节内的一个讲解进度单位；幻灯片中对应“点击”，网页中对应滚动位置或全部展开 |
| 光标 | 当前所处的位置，即（页，步骤） |
| 视图 | 文稿的一种呈现方式，例如听众视图、演讲者视图 |
| 作用域 | 插件生效的范围：全局、单页、单个节点 |
| 服务 | 插件对外提供的、以名称标识的接口，供其他插件调用 |
| 锚点 | 对某个内容位置的稳定引用，不依赖物理行号 |

## 3. 内核需求

内核需求是第一阶段（M0）的交付范围。“实现”一栏的含义：

- **宿主**：渲染端的框架（幻灯片形态的 Slidev、网页形态的 VitePress）直接满足，只需配置。
- **定制**：通过框架的公开扩展接口编写少量代码。
- **自研**：框架不提供，由 Presmium 的编译器、内核、宿主适配或 IR 运行时实现。

v0.6 起源码先编译为 IR（K-17），网页由 IR 运行时渲染，Slidev 只是幻灯片渲染端（P-76）。以下“实现”说明两种形态各自如何满足需求；组件只依赖 `@presmium/host`，两个宿主适配（幻灯片形态的 `@presmium/slidev-addon-core`、网页形态的 `@presmium/web`）分别实现它（`architecture.md` 4.4 节）。

### K-01 文稿源码模型

- 文稿由纯文本文件定义，支持多文件拆分与引入。
- 每页、每个需要被引用的内容块有稳定 ID。
- 节点保留源码位置映射，用于报错定位和“从预览跳回源码”。

**实现**：自研（编译器）。源语法为 MyST Markdown，用 `{include}` 引入多文件；章节 ID 取自 MyST 标签；IR 中每个块保留源码位置。见 `ir.md` 第 2 节。

### K-02 语法扩展点

- 插件可以注册新的语法与内容类型，不修改内核解析器。

**实现**：定制。插件注册 MyST 指令（`directives`），把指令转换为 IR 节点；浏览器端通过组件名渲染。解析器为 `myst-parser`（MIT）。

### K-03 渲染管线

- 内容类型到渲染组件的注册表；渲染产物是标准 Web 元素，可嵌入任意 Web 组件。

**实现**：宿主。插件目录下的 Vue 组件自动注册；Vue 原生支持自定义元素（Custom Elements）。

### K-04 步骤时间轴

- 每页由一组有序步骤组成，插件可以向页贡献步骤。
- 支持前进、后退、跳转到任意（页，步骤）。
- 步骤必须**可逆**：跳转到第 N 步后的页面状态，与从第 1 步顺序前进到第 N 步完全一致。
- 任意视图可以查询下一步骤。

**实现**：定制。编译器为每个块计算出现的步骤与内部步数（`ir.md` 2.4 节）。幻灯片形态用 Slidev 的点击系统（`v-click`、`$clicks`），网页形态由 IR 运行时按视图（文档、滚动叙事、放映）推进步骤；两者都以步骤计数为状态，天然可逆。插件约定：**组件的视觉状态必须由 `useStepState` 给出的步骤状态推导，不得在事件回调中产生不可回放的副作用**。

### K-05 视图

- 听众视图与演讲者视图可在不同窗口或屏幕打开，光标同步。
- 演讲者视图显示当前画面、下一步预告、计时、步骤备注。
- 支持全屏、页面总览、键盘翻页。
- 插件可以向演讲者视图添加面板，或注册新的视图。

**实现**：幻灯片形态由 Slidev 满足前三项（演讲者视图、总览、全屏、键盘翻页）；网页形态由 IR 运行时的放映视图与演讲者窗口满足（P-77）。插件面板为定制：插件向宿主的 `presenterPanels` 服务登记面板，幻灯片形态在演讲者视图的全局图层中显示，网页形态在演讲者窗口中显示。新视图由视图插件注册（K-20）。

### K-06 状态与事件

- 分作用域的状态存储；状态可以在本视图、本机所有视图、跨设备三个范围共享。
- 跨设备同步通过传输层接口接入，内核不绑定具体网络实现。

**实现**：定制。`@presmium/host` 的 `useSharedState(key, initial, { scope })` 按作用域共享插件状态：`view` 只在本视图，`local` 在本机所有窗口，`remote` 跨设备。两种形态的实现相同（`architecture.md` 4.4 节）：本机多窗口之间用 BroadcastChannel，通道按文稿区分；不用 Slidev 的 `createSyncState`，它会忽略紧跟在本地变化之后到达的远端值。跨设备的传输通过宿主的 `syncTransports` 端口接入（接入 `remote` 状态；幻灯片形态另映射到 Slidev 的 `addSyncMethod`，同步导航与圈画），课堂会话插件提供网络传输（P-61）；跟随主讲通过宿主的 `navigation` 服务实现。

### K-07 插件宿主

- **清单**：插件声明 ID、版本、兼容的 Presmium 内核版本、提供的服务、依赖的服务。
- **加载**：文稿声明使用的插件及配置，可分别作用于全局、单页、单个节点。
- **生命周期**：初始化、页进入/离开、步骤变化、卸载。
- **故障隔离**：单个插件出错时只影响它负责的节点，其余内容正常放映，并在演讲者视图提示。

**实现**：

- 插件的分发与加载：定制。插件以 npm 包分发，在文稿头部 `plugins:` 中声明。包的 Node 端入口（`./presmium`）提供指令、编译步骤、执行器、渲染端扩展与检查项；浏览器端入口（`src/client/plugin.ts`）提供内核插件，两个宿主都从这里注册；包同时是 Slidev 插件（addon），幻灯片渲染端把它列为 Slidev 的 `addons`。
- 作用域：全局配置写在文稿头部 `presmium:`，章节配置用章节内的 `{config}` 指令，节点配置用指令选项或组件属性（`architecture.md` 5.2 节）。
- 清单：浏览器端插件声明 ID、版本、兼容的内核版本范围、提供与依赖的服务（K-08）；Node 端插件声明版本与兼容的内核版本，编译器拒绝不兼容的插件。
- 生命周期：自研。宿主在应用启动时按依赖顺序启动内核与插件，在页面卸载与热更新替换时停止内核并调用插件的 `dispose`；页与步骤的变化通过宿主的 `navigation` 服务与 `useStepState` 观察。
- 故障隔离：自研。宿主接口提供错误边界组件 `PmBoundary`，基于 Vue 的 `onErrorCaptured`；出错的组件显示占位，演讲者视图与启动报告给出提示。

### K-08 服务注册

- 插件可以按名称提供服务、按名称依赖服务，内核负责依赖解析。
- 依赖的服务不存在时，依赖方按声明降级运行或拒绝加载，并给出提示。

**实现**：自研。规模预计 200 行以内。

**验收**：身份与课堂会话以 `session` 服务的形式由插件提供；测验插件依赖 `session` 服务，替换 `session` 的实现时测验插件无需修改。

### K-09 工作区访问

- 插件可以读取文稿所在仓库中的文件，并监听变更；可以把演示中产生的标注写回仓库。
- 代码修改不写回：编辑只在源码中进行，渲染产物不回写源码（设计原则 6）。原定的代码编辑回写（P-25）已移出范围（WP-44）。

**实现**：读取与监听为自研：指令与编译步骤通过编译器的 `ctx.src`、`ctx.resolvers` 读取工作区文件，其他文件用 `ctx.watch` 声明，`presmium dev` 在它们变化时重新编译（`ir.md` 第 5 节）。标注写回为宿主：幻灯片形态用 Slidev 绘图的持久化，标注保存在文稿的 `.presmium/drawings/`（P-04）。本地环境插件的开发服务器端点（`setup/vite-plugins`）只用于在容器中运行与导出环境（P-22、P-26）。

### K-10 锚点接口

- 定义锚点的数据结构与解析器注册表。
- 解析结果分为四种状态：精确命中、已移动、模糊匹配、丢失。所有使用锚点的插件按同一套状态处理。

**实现**：自研接口。第一个解析器直接复用宿主的 `#region` 标记语法（见 P-10）。

### K-11 开发服务器与实时预览

- 保存源码后预览增量刷新，保持当前光标位置。
- 作者可以使用自己的编辑器；在预览中可以跳回对应源码。

**实现**：自研。`presmium dev` 监听源码，只增量编译受影响的章节，通过 WebSocket 把变化的章节推送给浏览器中的 IR 运行时，运行时只重渲染这些章节（`ir.md` 第 8 节）。浏览器中不编辑。

**验收**：保存源码后 300 ms 内画面更新；不刷新页面；当前视图、章节、步骤与滚动位置保持不变。

### K-12 构建与导出

- 产出可离线放映的静态网站。
- 导出为 PDF、图片等格式；每种内容类型在静态导出中有确定的降级形式。

**实现**：定制。`presmium build` 生成网页（VitePress 静态站点，带离线 Service Worker）、幻灯片（Slidev 单页应用，PWA 离线缓存）与 notebook。`presmium-export` 对幻灯片渲染端生成的 Slidev 文稿运行 `slidev export`，导出 PDF、PNG，可按步骤展开为多页。静态导出中插件组件显示 IR 中的 `fallback`（宿主的 `useStaticRender`），降级形式因此确定（`architecture.md` 5.8 节）。

### K-13 可复现性

- 宿主、内核、插件的版本由锁文件固定。检出任意历史提交，按锁文件安装后渲染结果一致。

**实现**：宿主加定制。依赖版本由 pnpm 锁文件固定；执行缓存、本地化的远程图片与锚点锁定文件随文稿提交（`.presmium/`），新检出的文稿构建时不访问远程服务；发布产物不含构建机器的路径。

### K-14 主题与布局

**实现**：宿主。Slidev 主题、布局与 UnoCSS。

### K-15 输入映射

- 键盘、遥控器输入映射为命名动作，插件可以注册新动作。

**实现**：宿主加定制。幻灯片形态用 Slidev 的 `setup/shortcuts` 注册命名动作（如讲台插件的黑屏 `b`、冻结 `f`）；网页形态的放映视图由 IR 运行时处理翻页键。

### K-16 诊断与检查

- 所有错误附带源码位置。
- 提供 `presmium check` 命令，执行全部插件注册的检查项（例如锚点是否有效、引用代码是否漂移），可接入 CI。

**实现**：自研。编译到 IR 校验阶段，汇总编译诊断与各插件注册的检查函数。

### K-17 中间表示

- 源码编译为版本化的 IR（JSON）；IR 只记录语义与已计算的结果，不含任何媒介专属语法。
- 插件可以注册指令与编译步骤；编译步骤是 IR 上的有序变换。
- `presmium ir` 输出 IR，供调试与第三方渲染端使用。

**实现**：自研（`@presmium/compiler`）。IR 契约见 `packages/kernel/src/ir.ts`。

**验收**：示例文稿编译出的 IR 通过 schema 校验；同一提交重复编译得到相同的 IR。

### K-18 可插拔渲染端

- 每种媒介由一个渲染端插件从 IR 生成；文稿在 frontmatter 中选择渲染端。
- 渲染端声明对每种节点的支持程度（完整、降级、不支持），按 `ir.md` 第 6 节的规则降级，并在构建报告中列出未渲染的块。
- 网页渲染端是参考实现，必须完整支持全部节点。

**实现**：自研接口；网页渲染端基于 VitePress，幻灯片渲染端基于 Slidev，notebook 渲染端自研（输出 nbformat 4）。

**验收**：`presmium build --to web,slides,notebook` 从同一份源码生成三种媒介；去掉幻灯片渲染端后，其他媒介不受影响。

### K-19 编译时执行与缓存

- 带 `run` 的代码在编译时执行，输出写入 IR；静态媒介因此也有真实输出。
- 执行结果按内容哈希缓存在 `.presmium/freeze/`，可随文稿提交；代码不变则不重跑。

**实现**：自研编译步骤；执行器由插件提供（本地进程、容器）。

**验收**：第二次编译不重跑未改动的代码；删除运行环境后，依赖已提交缓存的构建仍得到相同输出。

### K-20 运行时视图与动态渲染

- 浏览器中的 IR 运行时直接从 IR 动态渲染，不依赖 Markdown 生成或静态编译。
- 同一份 IR 可在运行时切换视图（文档、滚动叙事、放映），切换不需要重新构建。
- 视图与节点渲染器可插拔：插件可以注册新视图，或为某种节点、某个组件注册渲染器。

**实现**：自研（`@presmium/viewer`）；网页外壳使用 VitePress 默认主题。

**验收**：在同一页面中切换三种视图，章节与步骤位置保持；示例插件注册的新视图出现在视图切换菜单中。

### 内核自研范围小结

Presmium 的内核分为两部分：纯 TS 的共享内核 `@presmium/kernel`（服务注册 K-08、锚点接口 K-10、检查契约 K-16、IR 契约 K-17），以及宿主接口 `@presmium/host` 与它的两个实现：幻灯片形态的 `@presmium/slidev-addon-core`（本身是一个 Slidev 插件）和网页形态的 `@presmium/web`（错误边界 K-07、步骤状态 K-04、共享状态 K-06）。编译器 `@presmium/compiler` 与 IR 运行时 `@presmium/viewer` 承担 K-01、K-02、K-11、K-17 至 K-20。其余内核需求由渲染端的框架直接满足或少量配置满足。

## 4. 非功能需求

| 编号 | 需求 | 指标 |
|---|---|---|
| N-01 | 启动性能 | 100 页文稿首屏渲染 < 2 s |

### 5.4 依赖准则

1. **只用公开接口**。只使用宿主文档化的插件机制与 `@slidev/client` 入口导出的 API，不引用其内部路径。宿主自己声明，入口以外的模块随时可能有破坏性变更。
2. **不 fork、不打补丁**。宿主或依赖不满足时，先在插件层绕开；绕不开就在上游提议，同时在插件层做降级。
3. **谨慎依赖小插件**。单人维护、0.x 版本的第三方 Slidev 插件，只在“出问题时一天内能用自研替换”的前提下使用；否则自研一个薄插件。
4. **不引入 AGPL 依赖**。例如 Shepherd.js、Intro.js 已改为 AGPL-3.0，不采用。
5. **只保留一套实时通信**。所有跨设备功能共用 P-61 的同步通道，不为单个功能再引入另一套实时服务。
6. **定期升级宿主**。锁定 Slidev 版本，每个大版本发布后集中升级一次，升级时用 P-53 做全量可视化回归。

| P-104 | 执行后端：浏览器 GPU | 通过 WebGPU 在浏览器中运行计算着色器与张量代码，返回结果与计时；浏览器不支持 WebGPU 时回退到录制输出并说明原因 | 定制 | WebGPU；库选型见设计（WP-72） |

**验收**：

### 6.14 讲授轨与语音（M8）

一堂课的讲授以**讲授轨**保存：一条按时间排列的纯文本记录，包含“说了什么”（语音段的文字、时间与可选的音频）与“做了什么”（翻到哪一节哪一步、指针指向哪个块、高亮与聚光、点击、运行代码、组件操作）。操作锚定到章节、块与锚点（K-10），不依赖像素与屏幕尺寸，因此讲义改版、换设备、换窗口大小后仍能回放；回放时由讲授轨驱动真实的页面，而不是播放视频。

讲授轨有三个来源，回放方式相同：

- **录制**：老师放映时录音，同时记录操作；语音转文字得到带时间的文字。
- **讲义本身**：讲解本来就逐段绑定到步骤（`ir.md` 2.4 节），讲解文字经文字转语音即可成为讲授；讲解中可以用行内标记指定说到某处时高亮或点击什么。
- **脚本**：由作者或 agent（6.12 节）以纯文本写出什么时候说什么、做什么，例如整堂课由 AI 生成。

文字是讲授轨的主存储，音频可以由文字重新生成：换音色、换成 AI 音色、修改说错的句子，都只需改文字再合成。

| 编号 | 插件 | 功能 | 实现 | 依赖 |
|---|---|---|---|---|
| P-130 | 讲授轨 | 讲授轨的格式与存储：语音段（文字、时间、说话人、可选音频）与操作（导航、指针、高亮、点击、运行、组件操作）按时间排列，锚定到章节、块与锚点；纯文本、可比较差异，保存在文稿目录；可以导出 WebVTT 字幕与章节；`presmium check` 报告与当前讲义不再对应的操作 | 自研 | K-04、K-10；格式见设计 |
| P-90 | 讲授录制 | 放映视图中录制讲授：录音（不默认录视频，可选摄像头与屏幕），同时记录操作，生成讲授轨 | 定制 | 浏览器 MediaRecorder |
| P-131 | 讲授回放 | 由讲授轨驱动真实页面回放：音频与操作同步，字幕；按章节、步骤、句子跳转；倍速；任意窗口尺寸；学习者可以暂停后自行操作，再回到讲授 | 自研 | K-20、P-130 |
| P-132 | 语音转文字 | 把录音转写为带时间的语音段（中文、英文），默认在本机或浏览器中完成；转写结果可以修改，修改后重新对齐 | 定制 | 引擎可插拔，选型见设计 |
| P-133 | 文字转语音 | 把语音段合成为音频，可以选择音色（系统语音、开源模型、云服务）；换音色不需要重录；合成结果按（文字，音色）缓存并可提交，保证可复现 | 定制 | 引擎可插拔，选型见设计 |
| P-134 | 脚本化讲授 | 从讲义的讲解与行内提示标记生成讲授轨，或从单独的讲授脚本生成；agent 可以撰写脚本（P-110、P-111）；生成的讲授以课堂形式回放 | 自研 | P-130、P-133 |
| P-135 | 导出视频 | 可选：把讲授轨渲染为视频文件（无头浏览器录制页面并合成音频），用于只接受视频的平台 | 定制 | Playwright 等，选型见设计 |
| P-136 | 转写回写讲义 | 把录制讲授的转写交给 agent，按章节整理为讲解写回源码；作为一批修改提交，可以撤销（P-115） | 自研 | P-132、P-111、P-115 |

**验收**：

- 老师在放映视图中录制一段讲授（翻页、推进步骤、指向并高亮代码），得到的讲授轨中没有视频；在另一尺寸的窗口中回放，页面操作与音频同步，可以按句子跳转。
- 录音转写后修改一句文字，选择另一个音色重新合成，回放时听到新音色、新文字，操作时间不变。
- 不录音，直接由一份讲义的讲解与行内提示标记生成讲授并回放：说到标记处时对应的块被高亮。
- 修改讲义删掉被引用的块后，`presmium check` 指出讲授轨中失效的操作。
