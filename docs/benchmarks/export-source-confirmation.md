# 导出的保存版本确认

本次定向验证使用独立 Studio 17371、临时纯文字文稿和本地浏览器，不修改公开示例、用户的 4320 文稿或私有 17359 工作区。没有模型、语音合成或录制请求。验证脚本与原始记录在忽略目录 `.presmium/`，没有新增测试或运行测试套件。

## 真实缺陷与修复

正文 A 的真实保存请求已写盘，但 HTTP 回执被浏览器验证脚本暂缓；作者随后输入 B 并立即生成 Notebook。修复前任务直接启动，实际 `.ipynb` 只有 A，B 仍在草稿。修复后先等待 A 的确认，再保存 B，任务从 B 的保存版本生成。任务的 `source.version`、`source.fingerprint` 与实际文稿接口一致；IR `revision` 保持独立。

审阅还发现译本依赖缺口：只修改 `locales/en/lecture.json`，原文保存版本与主 IR 不变，旧网站任务被复用，实际英文产物仍是 V1。现在收集公开 `compileTranslations` 返回的译本源码和依赖；相同原文下再次生成得到不同任务与依赖指纹，实际产物包含 V2。已记录的工程输入在任务运行前后核对，变化时失败并移除此次产物。它不是整个文件系统的不可变快照，未登记为编译输入的外部服务状态不在此保证内。

## 实际验证

| 记录 | 结果 | 范围 |
|---|---|---|
| `export-save-before.json` | 7 项通过，成功复现缺陷 | held 保存回执期间输入 B；旧 Notebook 缺 B |
| `export-save-after.json` | 8 项通过 | 等待确认，实际 Notebook 含 B，任务记录精确保存来源 |
| `export-save-cases.json` | 15 项通过 | 等待保存时取消；组字拒绝；源版本、指纹与缺字段的服务端拒绝；切文稿；晚任务回执与新输入；四种显示组合 |
| `export-draft-gates.json` | 5 项通过 | 非法时机原值保留；离线保存失败；真实外部源变更引发 CAS 冲突，源与本地输入均保留且不启动任务 |
| `export-locale-before.json` / `export-locale-after.json` | 各 6 项通过 | 真实 Web 构建产物，译本单独变化的复用反例与修复 |

浏览器记录无运行异常。版本拒绝场景预期收到两次 409 和一次 400；它们不计作意外网络失败。四张实际截图为 `export-save-{1440,390}-{light,dark}.png`，已经逐张查看：等待状态、取消按钮、加载中的输出按钮与旧生成记录完整可读，无根页面或侧栏横向溢出。使用现有 `PmNotice`、`PmButton` 的 loading/disabled 状态，没有新增业务控件样式。

Figma 读取了 P27 `9:29`、I02 `40:4647`、I11 `40:4656` 的设计上下文及截图，复用现有 compact 按钮和状态反馈。Notebook 文本检查先按 Markdown 中的转义逐字匹配而失败，已改为读取实际 notebook cell 内容；晚回执脚本也曾误用 exact 文本定位，遗漏现有分隔符。原始失败记录保留，未据此修改产品行为。

## 边界

正文、讲稿与时机仍只有规范 JSON 文稿这一权威。开始生成后继续编辑时，旧产物保留其确认来源并显示与当前编辑版本不同，不自动替代新内容。等待保存阶段可以直接取消意图；已经交给服务的任务继续走原有任务取消接口。

本轮没有重跑视频、PDF、PowerPoint、收费配音、两个公开示例的全量构建或操作系统输入法验收。对任务排队/运行期间工程依赖变化的代码门禁，不等同于任意外部依赖和远程服务均已形成可复现快照。
