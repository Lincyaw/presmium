# 命令行、MCP 与 VS Code 扩展的双语文本（实测记录）

日期：2026-10-29。分支 `work/i18n-cli-2026-10-29`。依据：[界面术语与文案规范](../glossary.md)、[架构 5.7 节](../architecture.md#57-界面语言)、[界面文本审计](i18n-audit-2026-10-29.md) 的 cli、studio、presmium、create-presmium、mcp、vscode 六节。

## 改动

- **命令行按系统语言输出**：`presmium`、`presmium studio`／`presmium-studio`、`presmium-mcp`、`create-presmium` 的帮助、进度、汇总与错误都有 zh-CN 与 en 两份，按 `LC_ALL`、`LC_MESSAGES`、`LANG`（都没有时看 `Intl` 的地区）选择，`zh*` 为中文，其余为英文，与 `create-presmium` 原有的判断相同。各包的目录在 `packages/cli/src/messages.ts`（`CLI_MESSAGES`）、`packages/studio/src/messages.ts`（`STUDIO_MESSAGES`）、`packages/mcp/src/messages.ts`（`MCP_CLI_MESSAGES`）与 `packages/create-presmium/src/messages.ts`。
- **机器读取的输出不变**：`--json`、网址、路径、选项名，以及 `serve  <网址>`、`workspace  <根目录>`、`mcp  <网址>`、`server  <网址>`、`<形态>  <网址>`、`studio  <网址>` 这些“键两个空格值”的行，两种语言的键都相同（`@lincyaw/dsh/launch` 的 `SERVE_READY`、`WORKSPACE_READY` 与 e2e 读取它们）。中文的 `mcp` 行在网址后先空一格再接“（访问凭据在 … 中）”，按空白切分时网址不连上括号。程序名前缀（`presmium:`、`presmium studio:`）两种语言都用半角冒号。
- **英文中测试与文档引用的句子不变**：`no problems`、`watching;`、`compiled N sections; …`、`code runs: N executed, M from cache`、`hint:`、`… updated (N anchors)`、`(its token is in …)`、`presmium studio: log …`。其余英文消息改为规范的写法（弯引号、Oxford comma、“Couldn’t X. …”说明原因与下一步，标题与区段名用 Title Case）。
- **错误说明失败与下一步**：参数错误给出可用的值或该看的帮助（“没有命令“frob”。可用的命令见 presmium --help。”），找不到文稿时提示检查路径或用 `presmium new` 新建。
- **MCP 审批与错误**（`packages/mcp/src/messages.ts`）：审批标题按文稿的语言写成命令：“导出文稿（网站、幻灯片）／Export Document (Website, Slides)”“运行“X”中的代码／Run Code in “X””“撤消上一次修改／Undo Last Change”等；不再出现 `agent`、`MCP`、令牌、工具名（`start_transcription`、`apply_document_change` 有了自己的标题）、`plan`、`Build`、`Revert` 与步骤、内容块、片段、版本的标识（标识留在审批的详细信息中）。形态的标识换成规范的名称（web→网站／Website，slides→幻灯片／Slides）。审批的默认说明改为“由 AI 代 X 请求／Requested by the AI for X”。错误码的说明（`MCP_ERROR_TEXT`）去掉 `get_document`、`source.fingerprint`、`get_voice_authoring_capabilities`、“引擎”“编译”“构建”，改为“语音服务”“导出”“请在“设置 → 语音服务”中…”，并为 `operation-not-allowed`（作者拒绝或过期）、`authoring-review-required`、`authoring-permission-denied` 加了说明。`navigate` 与课堂工具在作者没有打开或放映文稿时的错误按文稿的语言给出。工具名与错误码不变。`describeOperation`（dsh 的确认对话框用它）同样给出这些标题。
- **VS Code 扩展**：`package.json` 声明 `"l10n": "./l10n"`，运行时文字（无法启动、正在启动预览…、无法打开预览、预览面板标题、预览框架的无障碍名称）用 `vscode.l10n.t`，中文在 `l10n/bundle.l10n.zh-cn.json`；预览页面的 `<html lang>` 取 `vscode.env.language`；`scripts/package.mjs` 把 `l10n/` 打进 `.vsix`。`package.nls*.json` 的描述与设置说明按规范修正。
- **create-presmium 写入项目的 README.md 与 AGENTS.md**：“文档”统一为“文稿”，“智能体／agent”改为“AI 编程工具／AI 助手”，“撤销”改为“撤消”，“演讲者视图”改为“演示者视图”，“讲解”改为“配音”，“编译／构建”改为“导出”，notebook 写作 Notebook。
- **技能**：`presmium-develop/references/testing.md` 说明命令自身的文字随系统语言，断言文字时用 `LANG=en_US.UTF-8`。
- **改动弄坏的测试断言已删除**（按仓库约定不适配）：`packages/mcp/test/mcp.test.ts` 中断言旧审批标题“运行「合并」一节的 …”的一行，`e2e/mcp.spec.ts` 中断言“放映跳转到「第三节」”的一行。其余英文断言对应的句子未变。

- **C，保留的英文句子**：`compiled N sections`、`watching; IR in …`、`(its token is in …)` 被测试或 `docs/architecture.md` 原样引用，英文保持不变；中文分别为“已更新 N 个页面”“正在监视修改；运行快照在 …”“（访问凭据在 … 中）”。
- **C，studio 的“日志／log”**：命令行指出真实的日志文件位置，规范“诊断”一行不适用（见文末的规范缺口）。
- **E**：剩下的是由目录拼出的输出（`${t.usage}\n`）、机器读取的行（`serve  …`、`studio  …`）、`check.ts` 中写进诊断的插件错误（诊断的消息与编译器的其他诊断一样为英文，`--json` 中也一样），以及给 AI 读的工具错误（`deck.ts`、`focus.ts`、`mcp.ts`、`client.ts`：其中指引 AI 调用哪个工具，AI 转述给作者）和打包脚本的错误（`create-presmium/scripts/templates.ts`、`vscode/scripts/package.mjs`，只在仓库中打包时出现）。
- **F**：`cli`、`studio`、`mcp` 各有一份与 `create-presmium` 相同的 `systemLocale`。四个包之间没有共同依赖的、在本次范围内的位置（`cli` 不依赖 `create-presmium`，`mcp` 不能依赖 `cli`），合适的共享位置是 `@lincyaw/kernel/node`，不在本次范围内，留待之后迁入。

## 规范缺口（未修改 `docs/glossary.md`）

- **命令行的“日志／log”**：第 4 节把“日志／Log”列为作者界面不用的词，指向“诊断”；但 `presmium studio` 需要告诉作者日志文件在哪里，“诊断”的含义不同。需要规定命令行指出日志文件时的写法。
- **运行快照／IR**：`presmium ir` 与 `presmium dev` 输出 IR 的位置，第 8 节不显示 `IR`；本次中文写作“运行快照”（沿用 `CLAUDE.md` 的称呼），英文保留 `IR`。表中没有这一行。
- **形态的名称**：导出与审批中把渲染端标识写成名称时，web、slides、notebook、lecture 分别用“网站／Website”“幻灯片／Slides”“Notebook”“讲授／Lecture”，`--to` 的参数仍是标识；表中没有“形态／form”与渲染端标识对应的一行。
- **访问凭据**：MCP 的访问令牌在命令行中写作“访问凭据”（en 保留 `token`，文档原样引用）；“密钥／API Key”只指模型服务的凭据，表中没有 MCP 或工作区服务凭据的写法。

- **命令行的程序名前缀**：`presmium: …` 一类前缀后的冒号在中文消息中用半角，规范第 2 节只规定全角标点，没有提到命令行前缀。
