# 暗色下文稿文字的背景色

2026-10-28。格式工具条选色菜单里的五种背景色（灰、强调、成功、提醒、危险，即 `background-muted` 至 `background-danger`）在暗色下几乎看不出来：底色与纸面的亮度比只有 1.12–1.25。本次调高这些底色的暗色取值，亮色不变。

验证用 `examples/animations/try.mjs` 准备独立的临时工作区（示例 `guide-content`），从本分支启动 `presmium-studio`，只用 4346 端口；修改前后各用一份全新副本。浏览器为 Playwright Chromium，中文界面，1440 × 900 与 390 × 844，亮色与暗色由浏览器的 `colorScheme` 决定。脚本 `run.mjs` 在第 1 页第一段依次选中“功能样例”“直接修改”“先阅读”“改一段文字”“同一份”，经格式工具条的选色菜单分别设为五种背景色，再读取编辑器中每段文字的计算颜色、底色和其后第一个不透明背景（纸面），按 WCAG 2 相对亮度计算对比度；1440 宽度另打开“放映预览”，在查看器的 iframe 里读同样的值。没有新增测试或运行测试套件。截图、原始数据与脚本在忽略目录 `.presmium/ui-evidence/dark-highlight-2026-10-28/`（`before-*`／`after-*`）。

## 修改

- `packages/design/src/tokens.css`：暗色的 `accent-soft`、`ok-soft`、`warn-soft`、`danger-soft` 调亮；新增令牌 `muted-soft`（亮色与 `sunk` 相同，`#efebe3`；暗色 `#3c3a35`）作为灰色背景。`sunk` 本身不变，它还是代码、公式块、输入框与悬停的底色，调亮会改变整个暗色界面。
- `packages/kernel/src/document-colors.ts`：灰色背景改存 `var(--pm-color-muted-soft)`；早先保存为 `var(--pm-color-sunk)` 的背景（例如示例表格的一格）在编辑器与编译后的查看器中都按 `muted-soft` 显示，文稿不改写。
- `tokens.ts` 的 `COLORS`、高对比度样式（`addon-publish` 的 `contrast.css`）、`docs/architecture.md` 与 `docs/design-system.md` 的令牌说明同步加入 `muted-soft`。

| 令牌（暗色） | 修改前 | 修改后 |
|---|---|---|
| 灰：`sunk` → `muted-soft` | `#2a2925` | `#3c3a35` |
| `accent-soft` | `#1d3330` | `#1f4a45` |
| `ok-soft` | `#1b2e22` | `#22482d` |
| `warn-soft` | `#3a2c19` | `#50421a` |
| `danger-soft` | `#3a211b` | `#61342a` |

## 测量结果（暗色）

纸面为编辑器与放映预览的 `surface`，计算值 `rgb(31, 30, 27)`；正文为 `ink`，`rgb(237, 234, 227)`。1440 与 390 两种宽度的计算值相同，编辑器与放映预览也相同。

| 背景 | 正文对比度 前 → 后 | 底色与纸面 前 → 后 | 同色文字在其上（后） |
|---|---|---|---|
| 灰 | 12.12 → 9.45 | 1.14 → 1.47 | `muted` 4.57 |
| 强调 | 11.14 → 8.23 | 1.25 → 1.69 | `accent` 4.71 |
| 成功 | 11.97 → 8.60 | 1.16 → 1.61 | `ok` 4.61 |
| 提醒 | 11.25 → 8.19 | 1.23 → 1.69 | `warn` 4.62 |
| 危险 | 12.37 → 8.60 | 1.12 → 1.61 | `danger` 4.72 |

- 正文在五种底色上都高于 8:1（灰为 9.45），远超 AA 的 4.5:1。
- 底色彼此之间的最小 RGB 距离从 11.2 增至 24.3（强调与成功最近，靠色相区分：青绿与绿；提醒偏黄、危险偏红）。
- 最后一列是 soft 令牌的其他用途（选中项、危险按钮、差异底色等以语义色写在自己的 soft 底上），调整后仍高于 4.5:1。
- 示例表格中保存为 `sunk` 的一格，编辑器暗色下的计算底色为 `rgb(60, 58, 53)`（`muted-soft`）；放映预览中该格的内联样式是 `background-color: var(--pm-color-muted-soft);`，计算值同为 `rgb(60, 58, 53)`（修改前为 `var(--pm-color-sunk)`、`rgb(42, 41, 37)`）。

## 亮色

修改前后计算值完全相同（1440 与 390、编辑器与放映预览）：纸面 `rgb(255, 255, 255)`，正文 `rgb(28, 27, 25)`，五种底色上的正文对比度为 14.48、14.49、14.65、14.63、14.15，底色与纸面 1.17–1.22。

## 截图

`before-editor-{light,dark}-{1440,390}.png` 与 `after-editor-*`：编辑器第 1 页第一段的五种背景色；`*-preview-{light,dark}-1440.png`：放映预览同一段；`after-legacy-cell-dark-1440.png`：旧 `sunk` 背景的表格格。暗色修改后五种颜色在桌面和 390 宽度下都能一眼分辨，亮色画面与修改前一致。放映预览的正文用衬线字体，缩小后的截图里笔画显得偏灰，计算颜色仍是 `ink`，祖先元素没有透明度或滤镜。

## 未验证

- 只测了 Chromium；Firefox、WebKit 与真实显示器的色彩表现没有看。
- 选色菜单本身（样本色块）在暗色下的样子只经令牌推断，没有单独截图。
- 工作台其他使用 soft 令牌的位置（dsh 的对话气泡、文件差异底色、危险按钮等）只计算了对比度，没有逐一打开查看。
- 网页形态（`presmium build` 的站点）与幻灯片导出没有单独构建；它们与放映预览共用同一查看器与令牌。
