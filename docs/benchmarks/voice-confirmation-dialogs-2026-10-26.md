# 配音确认对话框的真实浏览器验证

`VoicePreviewDialog` 与 `VoiceoverDialog` 复用公共 Dialog、按钮、字段、提示和范围选择，不新增控件样式。正式设计读取了 Figma 的试听确认 `128:908`、生成确认 `130:819`、源变更 `128:887` 的设计上下文与截图；桌面按钮使用公共 compact 密度，触屏热区由公共控件规则提供。

试听只在明确确认后提交报价 token、报价来源和运行 revision。`Audition` 在 effect 中创建，关闭、换报价或来源失效时停止并释放；缓存报价只说明命中缓存，不将其说成本机合成。生成默认当前稳定步骤，可明确切换到所选步骤、页面或文稿；确认前展示真实缓存／缺失／不可用片段数、音色与参数、服务来源及范围讲稿。静音与录音保持 canonical 来源，不改讲稿或制作设置。

生成状态只在对话框可见且有活动任务时轮询。范围切换不改变已存在任务的范围；源变化保留选择并禁用旧确认。明确启动的任务在关闭时请求取消，过期任务不能成为当前结果；完成状态采用前先停止试听并暂停播放，等待作者明确再播放。取消失败不能据此宣称服务已停止，后台仍以真实任务状态为准。

忽略目录 `.presmium/voice-dialog-consumer.mjs` 使用独立临时工作区、真实 `serveWorkspace`、`workspaceClient()` 和 `Workbench`，实际调用公开 API；同源适配沿用 DSH 的公开路由映射，工作区身份来自该真实服务。它没有启动或模拟 Harness。两个文稿分别为已有 8 份精确语音缓存的冒泡排序副本，以及只有讲稿与未配置 TTS 来源的最小文稿。没有改公共工作区或用户示例副本。

`.presmium/ui-evidence/voice-dialog-consumer.json` 的 20 项实际检查通过，浏览器异常、失败 HTTP 和外部网络请求均为零。

| 范围 | 实际结果 |
| --- | --- |
| 能力与缓存 | 没有已配置提供方时，已有缓存仍显示可播放；当前步骤默认范围准确，缓存齐全时不会提供无必要的生成调用。无服务文稿明确显示原因并禁用生成确认 |
| 范围 | 用户可明确选择多步、本页、文稿，保持稳定 ID；打开与切换范围只读状态，不发送生成 POST |
| 真实试听 | 打开报价不发送 POST；明确确认后真实缓存试听返回 200，原生 `Audio.play()` 成功后才显示正在试听；停止后可明确再播放 |
| 关闭与迟到回执 | 在真实服务返回缓存音频后暂缓传输回执，关闭时取消请求；放行后对话框与声音不会重新出现 |
| 来源变化 | 通过真实文稿 actor 修改并保存来源，旧报价立即失效、确认禁用，未采用旧来源结果 |
| 焦点与显示 | 1440 与 390 宽度、浅深色分别检查真实根节点主题和计算后的表面颜色；焦点位于公共对话框内，无横向溢出，四张截图已实际查看 |

截图为 `voice-generation-{light,dark}-{1440,390}.png`。这是独立消费者的公共控件显示检查；它没有 Settings 对话框，不能替代完整 Studio 中通过真实设置切换主题的集成验收。390 宽度来自 Chromium 视口调整，不代表真实触屏或系统输入法验证。

独立审查另发现部分缓存被误标为整个范围就绪。原消费者只覆盖缓存全部齐全的情况；随后在私有副本实际修改一段讲稿，形成 7 个可读缓存片段、1 个无服务可生成的片段，服务返回 `missing: 0`、`blocked: 1`。`voice-partial-cache-before.json` 的第三项确认旧界面仍显示绿色“当前范围已准备好”；增加 `blocked === 0` 门槛后，同一场景的 `voice-partial-cache-after.json` 四项通过，改为保留部分缓存的中性提示，原失败证据保留。没有调用合成或外部网络。

审查还发现，生成任务已经入队、202 回执未到达时，仅在界面知道任务 ID 后取消无法覆盖关闭请求。现继续调用公开 `WorkspaceClient.startVoiceover`，由客户端预分配 `intent`，取消或响应交付失败时通过独立请求按意图取消；对话框不再依赖拿到任务 ID 才能终止该请求。真实 held-202 复现与修复为 `voice-intent-before.json` 的 4 项及 `voice-intent-after.json` 的 13 项，详见[生成响应交付前的取消](voice-intent-cancel-2026-10-26.md)。它们使用真实缓存服务，没有为启用界面按钮而伪造提供方。

对话框记录明确启动任务的原范围和提交前缓存数。任务结束后，只有该范围的精确缓存实际增加、任务来源与 revision 仍当前时，才在暂停确认后调用公开 `refreshVoicePlayback`，每个任务只调用一次；暂停失败保留重试机会。该方法只刷新匹配当前保存版本的已有放映框架，拒绝时不创建或编译视觉预览，不自动播放。不会改变后来选择的范围，也不把旧来源的历史结果放进当前播放。

缓存采用接缝本轮完成了独立代码审查与既有播放器重载机制核对，没有将“生成新缓存后实际播放”列为浏览器通过项。额外隔离消费者未完成预览握手；换装纯观测客户端的 Studio 探针未完成 Harness root slot 启动，原失败记录保留。恢复正常客户端后，真实 Studio Settings 的四种显示组合再次 18/18 通过；这些不同验证不能相互替代。

本轮没有配置实际可合成提供方，因而没有从 UI 强行启用缺失音频的生成，也未调用付费服务。确认生成、任务取消及部分缓存结果的后端证据见[保存版本屏障与生成占用](voice-source-gate-2026-10-26.md)，不将这些后端检查冒称已覆盖完整 UI 生成流程。完整制作入口、设置保存、Studio Settings 四组合和真实提供方仍由对应集成验证验收。未新增测试或运行测试套件。
