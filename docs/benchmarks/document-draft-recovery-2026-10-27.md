# 草稿恢复与冲突提示

2026-10-27，以两份私有文稿和随机实际端口的 Studio 检查断网、重载、切换文稿及外部修改。直接切断浏览器网络，未伪造保存回应；外部修改实际写入同一私有 `lecture.json`。

## 发现与修改

离线输入可保留，重新打开后需要明确重试才保存；另一个文稿的输入独立保存，没有采用原文稿草稿。外部修改与本地草稿冲突时，两份内容分别保留，重试不覆盖新源，明确丢弃后才采用磁盘版本。

冲突草稿重载后同时具有 `restored` 和 `error`，`SourceDocumentPanel` 因此绘制了两条 Notice，各带一组“重试／丢弃草稿”。现在错误存在时只显示已有错误 Notice，普通恢复状态仍显示恢复 Notice。重试、丢弃、存储失败和领域诊断保持原有语义，没有改变 DocumentSession、保存契约或文字目录，也没有新增公共控件和样式。

## 实际结果

最终消费者有 11 条实际断网或取消的请求失败记录，属于有意的故障条件；浏览器异常与失败 HTTP 为零。中间一次外部修改与服务刷新交错，实际 CAS 返回 409，磁盘新内容及本地草稿均保留；这也是有效的冲突保护，不能要求所有冲突场景都没有提交尝试。最终确认以真实源文件、原生正文和草稿状态为准。

四组合复用同一真实恢复状态，通过浏览器设置切换主题、视口，并用 CDP 切换 coarse pointer。390 下原生媒体查询为 coarse，两颗按钮热区均至少 44；没有把它称为真实手机或操作系统输入法验证。四张截图已逐张查看，最终实际点击丢弃后采用外部版本，未进入放映。源码构建前后 SHA 一致，客户端 SHA 一并保存在原始记录；并行的字幕焦点修复由另一条消费者验证，本记录不据此宣称它通过。

初始观察全部独立保留：`initial-status-oracle` 误等 toolbar 的 failed 值，而真实错误已在 Notice、toolbar 显示未保存；`initial-conflict-oracle` 错误地禁止所有冲突 POST；`initial-touch-protocol` 使用了非法 CDP touch-point 参数；`narrow-open-navigation-observe` 在缩窄后未收起原先打开的导航，后台按钮被抽屉遮挡。最终使用正确状态条件、实际冲突结果、合法参数并显式关闭导航，没有为消费者修改产品交互。

脚本、原始 JSON 和截图在忽略的 `.presmium/` 与 `.presmium/ui-evidence/`。每次运行的浏览器、Studio、私有工作区和 fixture 都在 finally 清理，没有触及公共 4320／17407 或作者文稿。未新增 tracked tests、运行套件或扩大为所有浏览器和存储迁移验证。
