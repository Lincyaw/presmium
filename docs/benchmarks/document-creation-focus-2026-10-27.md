# 新建文稿与页面后的直接输入

新建文稿采用空白模板后，作者应能直接在正文输入；在窄屏导航中新增页面后，正文光标也必须可见。2026-10-27 在独立临时 Studio 与工作区进行了真实浏览器操作，没有修改公开示例。

## 两个实际原因

新建成功后，首页对话框会卸载。Radix 恢复焦点时，原触发按钮已不存在，于是转向工具栏；这次焦点变化正确取消了 Workbench 尚未执行的正文聚焦意图。不能为修复它而放宽所有新焦点和新用户输入的优先级。

首页现在仅在创建成功并明确交接给新文稿时，通过公共 Dialog 的 `onCloseAutoFocus` 阻止这一次恢复。Workbench 在源、原生编辑器和视口的身份与版本一致后，采用显式 `focus: 'body'` 意图。普通打开不抢正文焦点；用户更新的交互仍可取消尚未采用的意图。

窄屏新增页面原本已经通过原生事务插入并聚焦，但导航遮住了正文。`narrow-new-page-before.json` 实测光标坐标命中导航的 OL，而非正文。`createPage` 现在返回是否实际插入成功，导航仅在成功后复用现有选择回调：窄屏收起导航，桌面保持侧栏；失败或受恢复保护时不收起。

## 定向结果

原始证据在忽略目录 `.presmium/ui-evidence/`：

| 记录 | 结果 |
| --- | --- |
| `blank-document-creation-after-focus-handoff-before.json` | 保留严格焦点守卫后，四种显示组合的正文焦点与直接输入共八项失败。 |
| `blank-document-creation-after.json` | 修复 Dialog 交接后 29/29；四种组合均实际直接键入、确认服务端保存回执为 saved，并读取磁盘规范文稿。 |
| `narrow-new-page-before.json` | 窄屏新增页的光标被导航遮挡；第二页文字虽能保存，仍不算交互成功。 |
| `narrow-new-page-after.json` | 37/37；浅／深色 × 1440 桌面／390 粗指针，分别新建文稿、直接输入并确认保存，再打开导航新增页、确认原生光标未被覆盖、直接输入第二页并确认保存。 |

最终四轮均保持 Doc、单个正文 BlockNote、有效文稿 JSON，未进入放映或制作。窄屏导航关闭，桌面侧栏保留。四张最终截图已查看，浏览器异常、HTTP 错误与生成请求均为零。临时浏览器、服务和目录已清理。

37 项记录固定了当次十份源文件 SHA；随后仅为“同目录文稿 UUID 被替换”增加的打开守卫，以[返回点记录](document-return-point-2026-10-27.md)中的专门反例验证，不把旧 SHA 的结果冒充所有后续改动的复验。模板、CLI 与自定义模板的结果见[空白模板记录](blank-document-template-2026-10-27.md)。
