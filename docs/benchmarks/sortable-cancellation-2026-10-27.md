# 排序中断后的恢复

2026-10-27 00:51–00:55 +08:00，修复公共 `PmSortableList` 在拖动期间被禁用、随后重新启用时，首个 Space 无法重新启动排序的问题。验证使用独立端口的真实 React 消费者与 Chromium，没有重建或重启 Studio，没有访问作者文稿。

## 已确认的原因与改动

基线版本 `bd7acbb6` 中，已启动的手势被禁用后，公开 manager 会发出 `dragend` 并回到 `idle`；手柄重新启用且有焦点时，首个 Space 却没有新的 `beforedragstart`。全局禁用、loading、单项禁用与单项排序禁用均复现。这是原有取消流程的回收边界；稳定 callback ref 之前的版本也已独立复现，不能归因于性能改动。

另一组操作在公开状态为 `initializing` 时改变可用性。原实现直到 `dragstart` 才标记活动手势，遗漏了这一阶段，导致禁用后仍继续进入 `dragging`。

修复复用已有的 Session 生命周期：允许且尚未取消的 `beforedragstart` 即登记活动手势；活动期间可用性变化，与外部顺序／重置变化一样，建立新的 provider Session。正常放下先结束活动状态，因此采用移动结果或等待异步保存不会重建 provider。焦点恢复同时监听单项可用性变化，并沿用原有归属判断：用户转向正文或其它控件后不恢复旧手柄焦点。

没有修改依赖、传感器或按键时序，也没有增加可见说明文字。
