# 工作台讲义预览缓存：2026-10-21

返回最近访问的网页讲义已能复用原来的 iframe/window，新增脚本请求从约 340 个降为 0。小文稿实测 28–48 ms；CS336 前两讲在较低负载的一轮为 74–129 ms，最后一轮高负载为 157–288 ms。**真实讲义尚未稳定低于 100 ms**，首次访问也仍需秒级加载。以下各轮系统负载不同，不能据此计算缓存之外各项修改的独立收益。

## 保留的实现

- 每个预览面板最多保留两个已加载窗口，按最近使用顺序淘汰，闲置两分钟移除。只保留访问过的讲义，不提前启动整门课程。保留原生线程、libuv、V8 与子进程优先级预算。
- 网页新增可选的 `activity` 命令与确认。切走时卸载文稿、工具栏和覆盖层，停止内核插件、媒体、控制连接和预览观察器；确认停止后才启动另一文稿。返回时校验已发布 IR、重启内核、重建组件，不重载模块。
- 每个组件、viewer、client 或 Vite 注入来源包须声明 `presmium.preview.restartable: true`；内核插件还须声明 `PluginDefinition.restartable: true`。当前仅 core、content 包通过准入。缺少声明、模块失败、运行时错误、配置或语言变化、协议不支持、暂停超时均销毁重载；幻灯片继续使用重载退路。
- IR 端点支持 ETag/304；工作台保留最多两份已解析 IR，按响应文本 UTF-16 大小合计不超过 16 MiB。同一文稿并发读取合并，保存发生在读取期间时再验证一次；当前文稿仍有请求序号保护。
- Markdown 的纯 HAST 按 viewer、文稿对象、Markdown 节点、章节前缀和语言复用，每份文稿最多 256 项／4 MiB，按 UTF-16 JSON 大小软计量，通过弱引用释放旧文稿。缓存不保留 VNode、组件实例、DOM 或后台资源。新文稿对象使引用标题、脚注等重新生成。
- 修复选中缓存窗口后、等待另一窗口暂停期间被闲置计时器销毁的竞态，避免再白等 1.5 秒恢复超时。

这些计量上限不等于 V8 堆内存硬限额。插件与组件的后台任务必须经生命周期清理，包级声明也覆盖模块顶层副作用。没有采用保留所有运行中页面、全课程预加载或扩大线程池的办法。

## 测量

环境：Apple M5，10 个逻辑处理器、24 GiB 内存，macOS arm64，Node 22.23.2，Chromium。每轮只开一套隔离 Studio，先打开两份讲义，再交替返回。真实课程只复制 CS336 第 01、02 讲与图片，未执行完整课程构建。工作台客户端按次快照隔离，避免同仓并行构建触发 Harness 热替换。

`clickToReadyMs` 从浏览器真实点击开始，到父页面确认预览 ready 且显示该 iframe。另等待 iframe 首章节可见，并记录 Playwright 动作到断言完成的 `elapsedMs`；后者包含自动化动作与等待的开销，不能混用。协议确认发生在内容重建的 Vue `nextTick` 之后；此指标不包含全部图片下载或下一次物理屏幕刷新。不同轮次源码和系统负载均有变化，不是受控 A/B 实验。

| 场景／阶段 | 返回次数 | 点击到 ready | 中位数 | 返回时新增脚本 | 一分钟系统负载 |
|---|---:|---:|---:|---:|---:|
| 小工作台文稿，窗口复用 | 7 | 28.2–47.9 ms | 32.9 ms | 0 | 约 7 |
| CS336，条件 IR 之前 | 3 | 63.4–155.0 ms | 90.6 ms | 0 | 约 5 |
| CS336，条件 IR | 5 | 73.6–128.6 ms | 121.2 ms | 0 | 约 7 |
| CS336，条件 IR、请求合并与 HAST 复用 | 5 | 157.1–288.2 ms | 223.5 ms | 0 | 约 12 |

最后一轮首次访问两讲分别为 16.63／17.81 秒，加载各 341 个脚本；此前条件 IR 一轮为 8.98／10.53 秒。最后一轮返回共 18–20 个请求，主要是工作台数据、恢复控制流和少量图片；Playwright 总耗时为 279–402 ms。没有页面 JavaScript 错误。请求失败计数包含切换时取消的旧连接和资源请求，不能直接作为应用错误数。

纯 HAST 复用可以消除同一份 Markdown 的重复转换，请求合并可以避免同时重复验证；本记录没有隔离出二者的毫秒收益。系统负载升高时，剩余网络往返、页面重建、布局和线程调度仍会推高延迟。旧版反复加载 iframe 的观察见 [第一轮调查](workbench-preview-2026-10-21.md)，原始测量见 [JSON](preview-cache-2026-10-21.json)。

## 验证与复现

```sh
GOMAXPROCS=1 RAYON_NUM_THREADS=1 UV_THREADPOOL_SIZE=2 \
  node scripts/bench-workbench-preview.mjs /private/tmp/preview.json --cs336 --rounds 5
```

去掉 `--cs336` 使用两份小工作台文稿。脚本不启动模型，不输出服务令牌，退出关闭并清理所有本次服务与浏览器。

最终定向 Chromium 用例 `e2e/preview-cache.spec.ts` 通过（用例 28.9 秒，总计 34.5 秒），使用一个 worker 和独立输出目录，覆盖原窗口身份、零脚本重载、真正卸载、控制流关闭、304、隐藏编辑更新、两帧 LRU、无生命周期内核插件、无声明 viewer-only 包的销毁、快速 A→首页→B。此前按需启动媒介的 `e2e/preview-loading.spec.ts` 和服务端 `preview-forms.test.ts` 已通过。分层、技能与改动空白检查通过。全仓 TypeScript 检查仍有 Slidev、执行插件和其他并行改动的错误，未宣称整体类型检查通过。

没有运行全量测试、全量 E2E、完整 demo 或导出。下一步若继续追求首开与所有切换均低于 100 ms，应测量共享模块运行时和按视口渲染，并验证导航、源位置、搜索、跨章节引用及插件隔离；单纯扩大 iframe 数量或并发预加载会转移资源成本。工作台的文件树、历史等次要请求也可评估延后到预览就绪或对应面板打开后，再按真实延迟决定是否保留。

提交前另以 HEAD 加本轮改动块建立独立源码副本，缓存用例通过（25.9 秒），媒介懒启动用例通过（10.6 秒）。该验证剥离编辑器标签页、诊断订阅与 Node Vite 契约迁移等并行改动，沿用既有界面；补齐源检出可能缺少生成技能目录时的夹具处理，并纳入输出目录的真实路径规范化，避免 macOS 临时目录别名破坏幻灯片插件路径。未扩大测试范围。上述性能数据来自当时包含并行改动的工作区，不作为这一独立副本的受控性能对比。
