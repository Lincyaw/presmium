# 正文图片插入、上传与失败恢复

2026-10-27，随机端口的独立 Studio、隔离客户端和私有规范文稿。通过真实斜杠菜单、BlockNote 原生 FilePanel、文件输入和工作区服务操作；没有以模拟成功状态代替上传。原图接口与事务的独立验证见[图片导入记录](document-image-import-2026-10-27.md)。

## 空图片与编译

原来的斜杠“图片”先创建 `url: ''`，投影随即写入空地址 Asset，真实文稿 POST 返回 422，并显示九条诊断。`native-image-edit-before.json` 与截图保留此失败；当时没有上传 callback，原生面板只有“嵌入”。

现在空图片省略 `assetId`，保持稳定的块身份，不创建无效素材。`native-image-edit-after-placeholder.json` 确认实际 200、刷新后身份保留、素材库为空。替换实例时只改变该块的绑定，不改写其他块共用的原图。

`image-placeholder-compile.json` 9/9：省略绑定合法；显式空 ID、缺失 ID 和音频素材引用仍被拒绝。真实编译在中文、英文分别产生 `presmium.document.image` warning，定位 `/blocks/empty-image`，并生成可读回退。定向网页构建返回 0 errors、1 warning。最初消费者误读 validator 返回字段、缺少 renderer 的私有 fixture 分别保留，没有为它们改变产品或接口。

## 上传与后来输入

`native-image-upload.json` 的八项断言通过，六次真实 POST 均为 200，浏览器错误与 HTTP 失败为零：

- 原生上传选项使用同一文稿版本边界；原始 PNG 字节、SHA 和素材类型正确，浏览器实际完成解码。
- 将服务已成功保存 SVG 的真实响应暂缓交付，在正文继续键入，再交付回执；两张图和新文字均实际保存并可刷新恢复，讲稿未改变。
- 保存确认前后是同一个原生编辑器 DOM，没有以替换编辑器消除异步输入。

该八项只证明上传、后来输入和恢复，不代表快速插入位置全部正确。第二次极短间隔的“点击目标段→End→Enter→/image”把图片插到了下一页开头，规范结果与原生画面一致；原始记录保留此位置边界。后续失败消费者在真实动作之间使用 50 ms 观察间隔，另明确断言目标页；没有给产品增加延时。这与[剪贴板快速选区边界](native-clipboard-2026-10-27.md)相关，但本轮未证明二者是同一调用原因。

最初的真实 Studio 上传返回 404，原因是 dsh 代理未注册 `document/image`，已补齐。其他中间记录分别保留了消费者误选助手附件 input、过早删除 held route、误把富文本节点 ID 当作内容块 ID 的失败；它们没有被算作产品缺陷。

## 原生失败与素材地址

`native-image-upload-failure-retry-before.json` 确认无效文件被 422 拒绝、面板显示“上传失败”，正文还能保存；但关面板后，空图片一直停在 Loading，无法重新选图。公开原生 renderer 只处理上传开始，没有在结束后恢复空图按钮。适配器通过公开 `implementation.render` 与 `onUploadEnd` 持有空图的渲染边界：仍为空图时完整销毁、重建原生渲染结果。已有地址的图片原样委托；没有新增权威字段、修改源属性、重挂整篇编辑器或操作依赖内部 DOM。

下一轮 `native-image-upload-failure-asset-before.json` 已通过 17/18：实际关面板重试、丢回执后对账与去重、继续输入、切文稿隔离、后台保存和重开恢复均成立。但最后 HTTP 检查发现两次本地图片 404，不能写成全部成功。

`native-image-resolution-before.json` 只读追踪确认：重开文稿的 loading 阶段，当前会话暂不可读，旧规范内容已有正确素材，resolver 却回落裸地址；42 ms 后实际请求 `/assets/images/...` 返回 404。修复只在取不到当前文稿时使用该 resolver 闭包中同身份的规范内容，继续按原文稿目录构造素材代理地址，不借用活动文稿或重写原地址。

仅这一行修改后的 `native-image-resolution-after.json` 完成 6/6：初开、切到另一文稿、重开和刷新均实际显示两张本地图。仍观察到相同的 loading／当前会话不可读窗口，但所有地址都走正确代理；裸素材请求、HTTP 失败和浏览器错误均为零。没有把前一份 17/18 改写为重新跑过的 18/18。六次失败链消费者的十二个端口均已关闭，自有目录和进程清理在 `native-image-upload-failure-cleanup.json` 中逐项确认。

actor 的独立代码审查还补上 digest 前后的读代次／版本／slot 守卫，并在丢回执后的 GET 之前消费旧刷新标志，保留 GET 期间的新来源事件。晚回执只能采用经核实的素材新增，不能替换后来的正文；正常 600 ms 合并保存窗口保持。相应并发窄窗属于静态审查发现，不冒称均由浏览器强制复现。

## 原生撤消与恢复

最终源码的 `native-image-history.json` 完成 11/11。真实选取 160×80 SVG，保存后按 CtrlZ 回到同一个空图片块，素材库保留已导入原图；CtrlY 恢复同一块、同一素材和完整规范文稿，刷新后仍实际解码为 160×80。五次真实 POST 全部 200，HTTP 和浏览器异常均为零，各阶段均通过实际 kernel validator。
