# 文稿刷新与较新的输入

本轮真实浏览器发现并修复了两处异步读取问题。验证均使用独立动态端口的 Studio、原生 BlockNote、真实文件与工作区 CAS，没有替换框架或接口响应内容。

## 旧内容比较清除了新输入

在原生正文输入 `older`，另一次真实 CAS 保存相同的较早内容，触发文稿事件刷新。浏览器仍调用真实 `crypto.subtle.digest`；消费者只延后第二次摘要完成结果的交付，在这个窗口继续原生输入 `newer`，再交还已算出的原始摘要。

原实现比较的是较早的本地快照，却直接清除当前 `dirty`。实际出现“正文显示 older newer、顶栏已保存、磁盘只有 older、恢复存储没有新输入”，重载后 newer 消失。原始 `document-refresh-race-before.json` 的两项产品断言失败，过程与请求检查通过；不能将完整执行称为全部通过。

修复后，匹配的摘要只确认它捕获的输入修订。期间已有新输入或仍在组词，继续保留 `dirty`；采用已确认的源版本作为保存基线，不把新内容替回旧快照。最终 `document-refresh-race-after.json` 为 **6/6**：较新内容沿既有自动保存队列真实写入，顶栏随后才确认保存，重载仍完整，无前端异常与失败 HTTP。

## 迟到读取回滚了已经显示的新版本

消费者先让真实服务保存版本 A，抓取实际 GET 响应并延后交付；再保存版本 B，等待正文确实显示 B，最后交还 A 的原始响应。原实现将正文回滚到 A，磁盘仍为 B，`document-refresh-order-before.json` 对应产品断言失败。

每个文稿槽位现记录读取代次，并在异步摘要之后重新检查归属。较新的读取、返回缓存文稿和开始保存会使旧读取失效；已淘汰的槽位也不能向当前文稿发状态。`document-refresh-order-after.json` 为 **4/4**：迟到的 A 不再替换 B，真实请求与浏览器均无异常。

审查还提出“保存中切走，再回到缓存文稿”的候选竞态。另行操作真实原生输入，暂缓实际 POST，再抓取重开文稿的旧 GET，确认客户端已显示保存后才交还旧读取，6 项观测均通过；没有据此确认第三个缺陷，也没有把这个序列扩大为所有重开并发的保证。最初只等待 HTTP 200 的 5 项观察保留为 `document-cached-open-race-initial-before.json`，更严格的记录为 `document-cached-open-race-before.json`。

## 验证边界

原始消费者与 JSON 位于忽略目录 `.presmium/`、`.presmium/ui-evidence/`。全部工作区、浏览器和服务为自有临时副本，结束即清理，未访问或重启 4320、17407，未改作者文稿、触发模型或语音生成。

类型检查通过，覆盖 1168 个文件。延迟摘要场景使用 Latin 原生输入，本次没有新增操作系统中文输入法验证。未新增受版本控制的测试，未运行测试套件、全量 e2e 或完整示例构建。该修改不实现任意并发文稿的自动合并，也不把服务端版本冲突当作已保存。
