# 文档文字输入投影：2026-10-26

本轮针对普通正文逐键重建整篇规范文稿的开销。`lecture.json`、完整 DOM、一个原生 BlockNote 编辑器及立即持久草稿保持原边界；没有更改保存合并窗口、CAS、校验、计数或后台事务。未运行测试套件，未增加测试文件，未调用模型、语音合成或外部服务，也未修改用户文稿或公共 Studio。

## 测量方法

从真实默认 `lecture.json` 模板派生两份临时文稿，每页十个带稳定身份的正文块，每块一个约 230 字的真实段落，并保留页面、步骤、visuals 和默认时序。10 页为 100 个正文块、109157 字节；100 页为 1000 个正文块、1092299 字节。两份文稿均通过领域校验。

独立 Studio 使用私有工作区、私有 client build 与动态分配端口，构建在宿主启动前完成。Chromium 为 1440×1000、DPR 1，无 CPU 限速。每档三轮，按小、大／大、小／小、大交替；各轮新建浏览器 context。机器有 64 个逻辑 CPU，Node v24.22.0；原始记录保留开始时的系统负载和内存。本轮并行开发的完整新界面也进入了修复后的私有客户端，包括导航排序与粗指针批注适配，没有回退其他改动来改善数字。

打开时间从实际 pointerdown 到全篇所有页面和段落已附着、唯一编辑器可编辑，再等两帧。输入时间从实际 `beforeinput` 到相应文字可见后两帧。保存请求及回执取真实 HTTP 事件，源文件每 20ms 检查一次。保存等待包含原有 600ms 合并窗口，不作为纯网络或后台 CPU 时间。

| 顶栏原生 Undo 至画面 | 27.5ms | 22.5ms | 97.3ms | 69.4ms |

两组前后共十二个实际样本均完整通过，各组 28 项检查，浏览器异常和 HTTP 失败为零。所有页面、正文段落与原生编辑器数量逐轮断言；鼠标从上一页最后一段经过页标题拖到下一页首段，原生 endpoint 正确。Undo 去掉输入字符后真实源仍有完整页面和块；刷新后全文与保存内容保留。普通文档没有 IR、preview 或 iframe 请求，不把编译或动画成本混入正文输入。

## 因果与实现边界

原调用链为 `DocumentEditor.emit` → `nativeDocumentToProduct` → `DocumentSession.record`。即使只改一字，原适配器仍多次克隆整篇文稿、重建每个块、递归比较、重新捕获所有富文本基线；actor 之后仍需立即克隆和保存草稿。状态栏同时扫描全文字数。

真实正常 production bundle 的 CPU 采样显示，1000 块时原 `nativeDocumentToProduct` 及后代约 49.4ms，100 块约 6.3ms；actor 约 9.2ms，全文中文计数正则约 6.8ms。没有换装 Workbench observer。采样按实际运行脚本中的函数体对应源码；Profiler 的等待时间和读脚本开销未当作 JS CPU 或混入无 profiler 的前后延迟。

本轮只改 `document-editor/projection.ts`：

- 只有原生拓扑签名未变、修改目标是已有正文块的直接 paragraph／heading，且稳定富文本 ID 可以匹配时，才走局部投影。
- 未变更的 canonical 分支复用，替换对应正文块内的实际富文本节点，更新已有会话投影基线。没有新的持久化格式、异步草稿或依赖内部缓存。
- 页面标题、嵌套结构、列表、表格、未知节点以及增删移等非匹配变化仍走原完整投影与结构 Undo 恢复路径。
- 文稿 actor 的立即 sessionStorage、组字屏障、保存版本与 CAS 均未修改。最新兄弟字段、讲稿、Production、定义与批注沿同一 canonical graph 保留。

修复后独立采样中，逐键全篇克隆子树不再出现，新增局部路径只处理匹配节点。仍有原生编辑器、React、全篇字数统计与立即草稿开销；本轮不声称已完成所有大文档优化。

## 定向兼容证据

`text-projection-history-after.json` 为真实原生消费者，完成六项检查与五次文件保存：普通输入后删除未知组件子树，Undo／Redo／再次 Undo，页边界合并与 Undo，文件重开后继续普通输入。定义的完整 opaque data、子树 scope、Step 状态、发音、cue 目标与停顿、页面布局和步骤归属全部保留，并通过领域校验。首次扩充的消费者误用了 `speech` 而非合法 `spoken` 字段，失败原记录单独保存，修正的是临时输入，未绕过产品校验。

真实 Studio 的 `text-projection-studio-compatibility.json` 通过 11 项检查：100 页／1000 块全文、组字期间立即 sessionStorage 草稿而不写源、compositionend 后实际保存、暂缓真实旧保存回执期间继续输入且后继 CAS 使用上一成功版本、官方原生批注保存稳定段落锚点、继续正文输入保留线程及完整教学图、重载恢复全文和批注标记。两次 held 回执对应的 POST 均为 200；前端错误和 HTTP 失败为零。合成 composition 事件只证明保存屏障，不声称覆盖操作系统 IME 或编辑器被替换时的组字恢复。消费者早先漏匹配请求查询后缀，以及将多行 End 定位后的输入强行假设为连续 ABC，均保留原失败记录；修正的是请求捕获和文本／真实光标观测，没有改产品来迎合断言。

原始证据均位于本机忽略目录 `.presmium/ui-evidence/`，权限为 600：`document-performance-baseline.json`、`document-performance-after.json`、两轮 profile 及对应实际脚本、结构恢复和 Studio 兼容记录。消费者脚本同样在忽略目录。仅自己的临时文稿发生输入与事务，结束清理自己的浏览器、服务、源副本和凭据；公共服务未重启。
