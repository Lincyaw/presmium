# Video 转写校对与讲稿采用

2026-10-27。Video 接入共享转写服务与讲稿采用事务；Doc 继续只编辑字幕和配音开始。界面复用公共字段、选择器、按钮、提示与 Dialog，校对使用现有原生 BlockNote NarrationEditor。业务 CSS 只负责排列。

## 作者操作

作者可以导入音频，或选择已经保存的录音素材，再明确启动转写。引擎选择来自目标文稿的真实 Node 服务配置。能力只确认配置，不声称鉴权、识别或提供方取消已经验证；无服务时禁用“转文字”，仍允许查看既有候选。

任务保留自己的 intent、来源和递增 sequence。关闭面板不会取消后台任务；恢复只保存任务引用，必须重新向服务读取。应答丢失时查询原 intent，不能自动重发付费请求。取消、来源变化和错误以真实状态显示，不模拟百分比。

候选按稳定步骤、讲稿和 segment 选择校对，尚未采用的输入不会修改 canonical 文稿。发音与提示使用原生结构化节点和撤消栈；无法确定位置的原子须明确放置或移除。共享讲稿可以只分离当前步骤，或明确修改全部引用。单引用直接更新原 Narration ID。

“对照并采用为讲稿”先创建同来源、同草稿修订的预检，再由作者确认。旧预检应答不能覆盖新输入；保存后由同一文稿 actor 读回。采用保留出处，不改配音来源或原音，不自动合成。重新配音继续使用 Video 既有音色选择和显式生成入口。

四组合截图已逐张查看。390 上下文实际 `hasTouch`，coarse=true，无根页面横向溢出。首轮确认框把操作放在标题同行，窄屏标题被挤换行；随后改用公共 Dialog 已有 footer，未覆写控件样式。最终两张窄屏 footer 图已实际查看，标题不换行。34 项消费者的八份前端源码 SHA 在开始与结束一致；不把原四组合冒称为最后源的完整重跑。

四组合记录中三个 `tracks/script` 请求返回真实 409 `production-plan-unavailable`。私有文稿刻意包含无音频且位于文字内部的 cue，现有制作计划明确拒绝该时码；这些响应保留，未算作 ASR 或采用请求成功。采用事务均真实保存，浏览器没有 pageerror，未发生成请求。转写会话消费者使用无 cue 文稿，并未依靠该错误验证任务恢复。

最终扩展记录保留同一路由的一次真实 409，未声称 HTTP 全零；所有采用操作仍真实保存。各消费者的浏览器、服务和临时文稿已清理。Workbench 最后增加 owner 销毁释放，独立会话 22 项的旧 whole-file SHA 不包含这两行生命周期接线；最终 34 项使用最终 Workbench 源，不把前一份记录改写。

独立审查发现并修复两项可用性问题：单引用讲稿不应隐式 fork，避免删除 cue 时产生错误暂停清理；取消会话仍须能显式查看唯一的新完成任务。纯规则复审与真实消费者分别记录，不能互相代替。

连续采用的扩展旅程又确认一处阻塞：首次明确删除 cue 并采用后，旧草稿的 discard key 留在下一次预检中。成功回执现在清理已完成的删除决定，请求只发送当前原子的键；失败或未知回执继续保留草稿。真实再次采用已成功，当前来源新加的原子仍被规则阻止，不能借清理旧键静默删除。

中间消费者的无效私有 fixture、窄屏错误 tab 定位和主题切换后旧关闭按钮定位均单独保留，不称产品缺陷。扩展消费者首次在原生 Undo 的 React 更新前读取按钮，随后截图已显示正确原子决策；最终等待可观察状态。诊断路由的提前 unroute 曾使脚本退出，私有资源经单独审计清理，记录保留。刷新后工作台回到 Doc，消费者必须重新进入 Video／原步骤，不能把未重开面板的超时当作草稿丢失。

## 剩余门槛

尚无真实 ASR 成功、提供方运行中取消或新文字的真实 TTS 播放验收。界面目前一次采用一个步骤与一份讲稿，服务支持的多目标批量采用尚未组合成界面。录音二进制仍需明确保存，校对草稿的 localStorage 恢复不提供音频崩溃恢复。

没有新增 tracked tests 或运行测试套件。录音、共享服务和 MCP 的其他证据分别见[录音](video-microphone-recording-2026-10-27.md)、[采用事务](transcription-adoption-2026-10-27.md)、[MCP](mcp-transcription-actions-2026-10-27.md)。完整契约与后续范围见 [RFC](../rfc-recording-transcription.md)。
