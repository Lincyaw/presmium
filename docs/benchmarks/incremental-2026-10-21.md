# 增量编译与资源预算实测（2026-10-21）

Apple M5，10 个逻辑处理器，24 GiB 内存，macOS arm64，Node 22.23.2。这里的目标是缩短保存后的反馈时间，同时给其他应用留下计算资源。

## 同进程增量编译

两版编译器在同一进程内交替执行，共享依赖与插件版本；各预热两次，再测 21 次单行编辑，每轮比较完整序列化 IR 是否一致。旧版使用优化前保存的源码快照，其中保留了工作区原有的未提交改动，并非 Git HEAD。计时不含导入初始化、外部代码执行与渲染端构建。Node 使用 `--v8-pool-size=1`，Go 与 Rayon 线程预算为 1，libuv 为 2。

合成文稿每节包含普通段落、两个 slide 指令、代码围栏、公式和表格，使用 core 与 content 插件。修改发生在前部章节；后续轮次复用同一 Compiler。真实文稿取自 CS336 的第 1、8 讲。

| 文稿 | 修改前中位数 | 修改后中位数 | 修改后 P95 |
| --- | ---: | ---: | ---: |
| CS336 第 1 讲，37 节 | 10.25 ms | 6.93 ms | 10.11 ms |
| CS336 第 8 讲，73 节 | 7.42 ms | 5.68 ms | 8.05 ms |
| 合成 100 节 | 21.87 ms | 9.61 ms | 16.79 ms |
| 合成 500 节 | 240.91 ms | 34.31 ms | 67.02 ms |
| 合成 1000 节 | 908.79 ms | 65.71 ms | 102.57 ms |

1000 节的 CPU 时间中位数从 939.38 ms 降至 73.38 ms，说明改善来自减少计算，而不只是将等待转移到别处。原始逐轮数据见 [编译测量](incremental-2026-10-21.json)。测量时系统仍有其他负载，数值不是跨机器保证。

单独比较开发预览中的 IR 发布处理，同进程交替 21 轮、预热 KaTeX，并逐轮比较产物。这里复用未变化章节的发布结果，不包含文件监听、网络、浏览器渲染或 VitePress 冷启动。

| 文稿 | 修改前中位数 | 修改后中位数 |
| --- | ---: | ---: |
| 合成 100 节 | 6.39 ms | 1.03 ms |
| 合成 500 节 | 39.63 ms | 4.59 ms |

原始逐轮数据见 [发布测量](publication-2026-10-21.json)。包含本地资源、组件资源或原始 HTML 的章节仍重新发布，以检查源文件变化。

## 浏览器链路

通过真实 CLI 服务与 Chromium，各测 9 次段落保存；记录 IR 的 SSE 到达时间，并在观察到 DOM 修改后的两次 requestAnimationFrame 回调之后回报时间。这是画面更新机会的近似值，包含回传 IPC 延迟，并非显示器实际扫描时间。测量同时运行着单 worker 完整回归，机器还有其他负载，不作为前后版本的受控对照。

| 文稿 | 保存到 IR 中位数 | 保存到画面更新中位数 | 画面更新 P95 |
| --- | ---: | ---: | ---: |
| 合成 100 节 | 69.09 ms | 80.08 ms | 127.05 ms |
| 合成 500 节 | 250.94 ms | 326.36 ms | 662.16 ms |

本轮 CLI 服务就绪约 1.27 s，两份文稿首次预览各约 5.09 s、5.77 s，没有浏览器运行时错误。首屏包含首次编译与工具链准备；数据说明冷启动与大文稿端到端反馈尚未达到 100 ms。原始数据见 [浏览器测量](browser-2026-10-21.json)。另一轮 CPU profile 采样造成明显扰动，其延迟不用于上述结论。

## 正确性与边界

编辑、换行、围栏、列表、HTML、全局引用、脚注、MyST 块作用域与 CRLF 的 56 组新旧编译对照一致；另对 17 讲真实文稿比较 IR。集成测试覆盖外部 include 修改、公式编号、先前 IR 不被修改、插件节点身份、保存时取消过期结果、单文稿与工作区按需启动，以及预览图片文件更新。

100 ms 尚未覆盖所有场景：1000 节增量编译的 P95 已略超标，含全局定义的文稿保守地完整解析，插件步骤、外部代码执行、首次工具链启动和浏览器首屏也可能超过预算。编译耗时不能当作保存到画面更新的总耗时；真实浏览器链路还包含保存合并、发布、传输和 DOM 更新。

线程池上限与较低进程优先级属于软限制。默认常见原生池为 1 线程，libuv 最多 2，受管理 Node 子进程的 V8 后台池为 1；多媒介构建逐个运行渲染端，顶层编译串行并优先处理交互任务。这些设置减少资源争抢，但不能为任意插件或外部程序提供操作系统级 CPU、内存硬配额。实现与配置见 [架构说明](../architecture.md#11-增量编译与资源预算)。
