# 阶段 A：从首页新建到重载的正文旅程

2026-10-27，从 HEAD `16ded6c8` 开始，用真实 Studio、私有 Git 工作区和隔离客户端运行一条完整编辑主线。主线记录为 `.presmium/ui-evidence/stage-a-document-journey.json`，**32/32**；17 次 document/change 均为 200，所有 replacement 通过真实文稿 validator，前端异常和失败 HTTP 均为零。本轮未修改产品源码。

## 完整主线

消费者通过首页“新建文稿”表单创建文稿，使用正式默认模板，并自动打开文档；随后执行：

1. 在原正文的真实文本末尾输入，核对原文字与新增文字完整相接。
2. 点击“新建页面”，确认光标自动进入新段落后直接输入，保存真实页面、段落和步骤身份。
3. 直接编辑原生页标题；输入粗体段落、两项列表，并在明确的末项空列表项中再次 Enter 退出，输入列表后段落。规范文稿恰有正文、粗体段落、两项列表和后续段落，逐项文字与 ID 都核对。
4. 用顶栏操作原生 Undo/Redo，规范文稿完整往返；再通过页面菜单重命名、复制和上移／下移。复制内容等值，页面及内部实体使用新 ID。
5. 删除副本，使用文稿 Undo/Redo 恢复、再删除同一完整页面图。保存后的 canonical JSON 精确匹配对应状态。
6. 真实 document/change 已由后端写入并返回 200，但消费者暂不向浏览器交付回执；继续输入新文字。新文字先在原生界面可见，磁盘尚未含新文字；放行真实旧回执后，旧、新两段都被保存，未被旧 snapshot 清掉。
7. 重载并从首页重新打开，磁盘规范文稿与重载前完全等值，四页的全部原生标题、段落和列表项仍与 canonical 逐项一致。

主线包含十个编辑操作，整段模式观察只出现 `content`，没有正式放映 iframe，没有 `/ir`、`/preview`、jobs 或语音生成请求。正文一直是一个完整 BlockNote 实例。最终与重载前截图已实际查看，文字包含两项列表、粗体以及晚回执期间继续输入的内容。

## 显示与异步观察

全量显示检查按 canonical 页面顺序、每个原生节点 ID 和完整文本匹配；不会因为旧磁盘仍合法或只出现某个关键词就算通过。只在真实 DOM 满足条件后读取，不使用固定等待时间作为产品完成信号。

首轮在文稿删除 Redo 的保存回执后立即读取，拿到旧的五页 heading 数组；其后的原生文字与截图已经正确显示四页，文字没有不匹配。该失败记录保留为 `stage-a-document-journey-initial.json`。最终同一步记录的初始数组仍为五页，真实 DOM 在 65ms 后满足四页顺序及所有文字条件，检查才通过。其它全量匹配点的本次条件等待为 9–13ms；这些值包含浏览器读取开销，不是输入性能测量。

页面菜单移动后，保存回执也可能早于拖动按钮解除 disabled。后续动作读取实际按钮状态，不能用磁盘已写入推断交互已可用。

## 指针移动的独立对照

主线使用已确认的菜单上移／下移。指针另外只做一个稳定界面上的短手势对照，记录在 `stage-a-fast-pointer.json`：

- 实际导航与磁盘顺序一致，Summary 拖动按钮 enabled；可信 pointerdown 位于该按钮 `(23,217)`，随后两次 pointermove，可信 pointerup 位于 Intro 目标行内 `(28,142)`。
- 原生事件测得按下至抬起为 **74.6ms**。没有等待公告后才放下；最终出现目标“位置 1”公告，实际源顺序变为 Summary、Intro、Points，产生一次真实 200 保存。
- 三项前置／事件／错误检查通过，`observedMove=true`，前端异常和失败 HTTP 均为零。截图已实际查看；截图时仍有操作结束阶段的 loading 反馈，不能据此声称所有控件已完全解除 busy。

中间记录全部保留：`stage-a-document-journey-drag-initial.json` 的快速手势未提交，但旧消费者没有记录 move 坐标及当时 disabled，原因未确认；没有将其直接归为产品缺陷或消费者错误。两个 `announcement-initial` 记录等待“已拾起”文案而未执行 pointerup，公共 live region 实际只保留后续位置消息，不能当作完整 drop 失败。`stage-a-fast-pointer-paced-initial.json` 使用较多移动步数，首个 duration 还包含首页点击，不能用它声称短手势支持。

最终这一次 74.6ms 成功只证明该手势；未覆盖更快交错、所有传感器或取消组合，原有 RFC 极快交错边界没有据此解除。
