# 讲授构建与导出只读取配音缓存

`lecture` 渲染器原来调用 `synthesizeLecture` 的默认合成路径。视频导出内部又先构建 Web 与 lecture，因此导出可能在没有单独确认生成配音时向语音服务发出请求。只读检查也存在合成兜底：没有可选引擎时调用 `synthesizeClip`，配置了引擎时则直接跳过缺失缓存检查。

现在检查、讲授构建与视频导出都只读取匹配当前文字、音色、语言和参数的精确缓存。缺失缓存保留来源诊断，并明确提示先显式生成配音；渲染器失败，使任务无法把一个空讲授索引当作成功输出。错误与提示按文稿语言提供中文和英文。显式 `voiceover` 生成、经确认的试听与 `lecture_synthesize` 付费工具保留各自的确认边界。

## 调用边界

| 入口 | 实际路径 | 合成行为 |
|---|---|---|
| 读取讲授预览 | tracks GET → `synthesizeLecture(cacheOnly: true)` | 保持原缓存读取；缺失片段保留静音与字幕语义 |
| 检查 | `lectureCheck` → 每个实际步骤音色的 `synthesizeClip(cacheOnly: true)` | 只查缓存，存在提供方配置也不能跳过缓存检查 |
| 构建 lecture | `lectureRenderer` → `synthesizeLecture(cacheOnly: true)` | 缺少完整缓存时失败，不发布旧讲稿配音 |
| 视频导出 | `exportVideo` → Web / lecture 构建 → 缓存检查 | 缺失配音在录像和编码前拒绝，不自动补合成 |
| 显式生成 | confirmed voiceover POST / confirmed+quote 试听 POST / `kind: spend` 工具 | 仍可按既有明确操作请求服务；本次没有运行这些入口 |

## 实际验证

原始记录在 `.presmium/ui-evidence/lecture-cache-only-proof.json`，15 项全部通过。脚本 `.presmium/lecture-cache-only-proof.mjs` 使用真实 Compiler、lecture 渲染器、语音缓存与 direct video exporter，没有新增测试或运行测试套件。

- 只复制并构建冒泡排序一讲的 **lecture 单一形态**，不运行公开示例的全量构建；测试进程没有配置可用引擎。实际 8 条讲稿全部读取已有精确缓存，产物包含 8 个音频文件，规范文稿字节不变，检查通过。
- 修改复制文稿的一条讲稿后，旧音频不再被当作新讲稿配音。构建得到明确缓存诊断且没有成功的 lecture 输出；8 份原有效缓存的文件与内容均保留。
- 专用最小文稿配置了一个实际语音适配器声明，但没有任何缓存或已认证的语音提供方。只读检查仍报告缺失；lecture 构建失败并提示显式生成；直接调用视频导出也在录像前拒绝，没有产生视频或音频。
- 英文最小文稿收到英文缓存诊断和生成提示；中文场景使用中文提示。
- 测试进程对网络 `fetch` 设为拒绝策略，记录的尝试数为 **0**。没有调用付费合成、转写、模型或外部语音服务；此证据不表示任何实际提供方的认证或可用性已经验证。

## 未包含的范围

没有验证完整视频编码、录制采用、媒体裁切或混音；没有把 cache-only 静音占位当成真实音频或精确词级字幕。独立 Video 工作区、规范 JSON 音色作用域编辑、生成请求的源版本屏障及跨批次去重，仍是下一阶段明确接入和验收的内容。
