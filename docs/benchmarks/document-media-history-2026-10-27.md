# 音频操作后保留正文原生历史

在正文输入并保存，进入视频制作导入音频，再返回文档，Ctrl+Z 没有撤消之前的正文输入。未导入音频、只进出视频制作的对照可以正常撤消。

## 根因

`document-media-native-history-before.json` 保存真实 Studio 的两组原生操作，七项检查中导入后的正文撤消失败。正文 DOM 节点仍然相同，不能据此声称原生编辑器没有重建。

随后 `document-media-native-history-observe.json` 在独立客户端中给公开 `attachDocumentEditor` 加委托观察器，并通过 `getState`、`subscribe` 只读记录。未导入的对照始终为 reset 0、editor 1，原生 history 有可撤消项；导入后变为 reset 1、editor 2，新 history 为空。源版本和新增素材已正确保存，没有前端异常或失败 HTTP。

音频 RPC 完成后，通过 SSE 和权威重读采纳新源。`DocumentSession` 对所有干净的新版本都增加 reset，导致只增加素材也重建正文与讲稿编辑器。问题不在 BlockNote 的撤消实现。

## 修改边界

仅在干净的远程版本采纳处判断是否保留编辑器：除 `production.mediaClips` 与新增资产外，完整规范文稿必须等值；所有既有资产必须仍为 own property 且内容等值。复用既有排序 JSON 序列化作完整比较，不根据可见文本或数字步号猜测等值。

因此仅新增素材、采用或移除媒体片段可以保留 reset；正文、页面、步骤、讲稿、批注、定义、元数据、其它制作设置或既有资产改变仍重置。身份、版本、指纹、base hash 和诊断正常更新，没有三方合并或忽略源版本。脏输入、组词、显式替换与放弃草稿路径保持原有屏障。

正文回写每次从 source actor 读取最新规范文稿。纯文本路径保留最新顶层字段，结构历史也优先采用最新文稿；历史快照只补回被撤消删除的结构实体，不恢复旧资产或旧媒体设置。

## 实际结果

`document-media-native-history-after.json` 的同序七项操作全部通过；导入后仍为 reset 0、editor 1，Ctrl+Z 立即撤消之前输入，音频素材保留。

进一步的 `document-media-history-boundaries.json` 为 **22/22**：

- 只进出视频制作、导入音频、导入并明确采用片段三种实际流程均保留原生 editor 身份与正文历史。
- 返回后原生 Undo／Redo 产生真实 CAS 保存；磁盘上的当前 assets 与 production 完整保留，不能用“回执前还存在”代替保存后的判断。
- 修改既有资产标题、其它制作时机或正文的三个外部更新仍增加 reset 并创建新原生编辑器。
- 前端异常和失败 HTTP 均为零。

全部操作使用私有规范 JSON、真实原始 Ogg、原生文件输入和真实工作区服务。独立客户端的观察器只读并委托公开方法；源观察器设置阶段的一次模块查找失败单独保留，没有为它修改产品代码。自己的服务、浏览器和临时目录已清理，未改公开 4320 或作者文稿。

本次不改样式与常驻说明，不新增测试或运行测试套件。验证只覆盖上述采纳与原生历史边界，不把它扩展为任意外部 JSON 变更都保留编辑器。
