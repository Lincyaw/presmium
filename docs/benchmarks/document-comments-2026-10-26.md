# 已解决批注重新打开验证（2026-10-26）

修复前，创建批注、标记为已解决、刷新工作台、重新打开同一文稿，再打开批注栏，会导致整个工作台进入错误页。
单块选区的最小复现不需要撤消或恢复。

## 原因与修复

BlockNote 0.56.0 的已解决摘要在首次渲染时就读取解决者的用户信息。
传入异步 `resolveUsers` 函数时，首次渲染的用户缓存仍为空；摘要直接抛出 `User … resolved thread …, but their data could not be found.`。

`packages/workbench/src/document-editor/comments.ts` 通过公开的 `createUserStore`、`UserStore.setUser` 和 `CommentsExtension.resolveUsers` 接口，在挂载评论前预填文稿中已有的作者、解决者和回应者身份。
当前作者沿用中文“作者”和英文 `Author`；历史身份使用原 ID 作为显示名称，不修改 `userId`、`resolvedBy`、批注正文或锚点。
未修改依赖源码或通过内部路径导入。
