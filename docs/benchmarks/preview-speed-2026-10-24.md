# 预览打开速度：2026-10-24

作者反映幻灯片和文稿“编译、加载太慢”。本次逐段测量示例 `examples/animations` 的两讲，找出热点并修复。原始数据见 [JSON](preview-speed-2026-10-24.json)。

## 测量方法

- 工作区服务：`presmium serve`。冷启动用示例的新副本，依赖缓存是空的；热启动是同一副本的第二次启动。
- 浏览器：Chromium 像工作台一样在 iframe 中加载预览。计时从设置 iframe 地址开始，到第一节（网页）或第一张幻灯片可见为止。
- Node 进程：工作区服务、VitePress、Slidev 分别记录 CPU profile。
- 浏览器端：记录逐个请求的瀑布与 JS profile。
- Vite 的日志：用 `DEBUG=vite:deps,vite:time` 打开。
- 机器：24 个逻辑处理器，共享主机，一分钟负载约 11，前后各轮在相近负载下交替进行。绝对时间只作比较。

## 热点

编译不慢：请求预览地址（含编译）20～100 ms，一次保存到新的 IR 修订 23～35 ms。浏览器中的 JS 执行也不慢：网页加载时忙 0.2 秒，幻灯片 0.4 秒。时间花在开发服务器上：

1. **Vite 的依赖预打包分几轮完成，最后重载整页。**
   - 现象：网页的扫描阶段找不到依赖，浏览器加载后陆续发现三批，每批重新打包一次（各约 3 秒），第 11 秒左右整页重载。
   - 原因一：生成的主题与 `addons.ts` 用绝对路径导入插件模块，Vite 5 的扫描不跟进这种导入（`shouldExternalizeDep`）。
   - 原因二：动画插件的场景文件经虚拟模块加载，扫描读不到；GSAP、Three.js、React 等只在场景文件中按需导入。
2. **线程预算。** 工作区服务、VitePress 与 Slidev 都按后台进程启动：原生线程 1 个（esbuild 的 `GOMAXPROCS=1`），V8 后台线程 1 个，进程优先级降低。把预算放到 12 个，代码不变，一轮依赖打包从 2.9 秒降到 0.55 秒。
3. **代理连接。** 工作区服务转发数百个模块请求，每个都新开一个连接。
4. **Slidev 进程启动**约 1.1 秒；它的 UnoCSS 每次加载生成样式约 0.5～0.7 秒。

## 修改

- **按设备分配线程**：作者在等的进程（工作区服务、dsh、预览的开发服务器）按机器当前的空闲处理器与内存取线程，用普通优先级；构建与代码执行仍是后台档。规则见 `architecture.md` 1.1 节。
- **依赖预打包一次完成**：
  - 网页的扫描入口是生成的主题，主题的导入改为相对路径；
  - 动画插件在自己的 Vite 插件中把场景文件加入 `optimizeDeps.entries`；
  - 网页的开发服务器启动时预先转换主题（`server.warmup`）。
- **代理复用连接**：工作区服务的两个代理用 keep-alive 的连接池。
- **提前准备**：
  - 鼠标停在文稿列表的一项上，就编译它并启动它的网页开发服务器；
  - 网页上停留 1.5 秒后，在后台启动幻灯片；
  - 都只在机器有余量时进行。

## 结果

示例的两讲，作者的机器（单位：秒）：

| | 改前 | 改后 |
|---|---:|---:|
| 冷启动：网页可见 | 4.3（第 11 秒重载整页） | 1.8（不重载） |
| 冷启动：幻灯片可见（含启动 Slidev 1.1） | 7.8 | 2.8 |
| 热启动：网页可见 | 1.3 | 1.2 |
| 热启动：鼠标停 0.6 秒后点开，网页可见 | — | 0.6～0.85 |
| 切回打开过的讲义 | 0.79 | 0.3 |
| 依赖重新打包与整页重载（每讲） | 3 轮，1 次 | 0 |

完整工作台（`scripts/bench-workbench-preview.mjs --example --rounds 3`）：首次打开两讲 2.4 / 3.4 秒，切回 0.35～1.3 秒。2026-10-21 的记录分别是 5.3～5.9 秒（负载 4）与 18.7～19.5 秒（负载 25），当时的示例不同，只作参考。

仍然存在的成本：
- 热启动时，网页要转换 VitePress 自己的约 175 个模块，加上进程启动约 0.4 秒；
- Slidev 一次加载约 580 个模块，UnoCSS 还要生成两轮样式；
- 冷启动时，每讲各自预打包一次依赖，约 1 秒。工作区共用一份缓存时，各讲的配置不同，Vite 会互相删掉对方的缓存，所以没有采用。

- **原有，通过**：
