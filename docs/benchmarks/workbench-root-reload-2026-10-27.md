# 工作台根布局代码重载

2026-10-27，对此前浏览器记录中的 `renderSlot('root') before any 'root' registration (boot order)` 异常进行隔离复现。

## 已观察事实

使用真实 Studio、独立工作区、动态端口与隔离的客户端构建。首次进入首页后，只给隔离客户端的有效 JavaScript 产物追加一行注释，使现有 Harness 代码重载链采用新的产物。没有修改文稿或重启正在使用的公共服务。

`root-hmr-probe.json` 记录：

- 首次冷打开首页成功；启动图没有原生 `ui-layout`，根槽位由 Presmium 提供。
- 代码重载后实际样式节点已经替换，但原标签页出现上述异常；继续在同一标签页观察 10 秒，首页没有恢复。
- 同一服务上重新打开一个页面，首页正常。没有 HTTP 失败或文稿写入。

另外在隔离副本中，将布局服务注册从 `ctx.reflect.provide` 改为文档化的 `ctx.provide`，并在 Host 启动前完成构建。`root-hmr-provide-clean-probe.json` 再次得到相同结果：冷打开成功，原标签页重载失败，新页面正常。这项试验没有进入产品源码。

更早一次在 Host 启动后才替换注册调用的试验，首页打开前就遇到异常；它混入了初始图与重建的交错，保留原始记录，未用它判断两个注册接口的差异。

## 原先结论

故障已缩小到根布局提供者替换期间的生命周期边界。仅更换服务注册接口没有修复它；现有证据还不足以区分 Presmium 的根布局清理与宿主 renderer 重挂载各自的责任。没有修改依赖、保留失效插件的根槽位、增加延时，或伪装旧标签页已经恢复。

原先客户端代码重建后的交付需要手动重新加载页面，并以新页面的真实内容验收；这条操作不代表原标签页的自动代码替换已经通过。

原始记录位于忽略目录 `.presmium/ui-evidence/`。两个有效复现均使用同一存活服务和标签页等待结果后再结束；自己的浏览器、服务和临时目录已清理。未新增测试或运行测试套件。

## 根代码更新后的同标签页恢复

沿公开生命周期文档核查后，补读了与依赖同版的官方作者源码 `dsh-v0.2.1-alpha.4` 的 `packages/client/ui-renderer/src/client/index.ts`、`packages/client/web/src/mount.ts` 和 Client Modules 的替换流程，没有读取依赖编译产物。该版 renderer 的实际 `inject` 为空，启动时的挂载只依赖 `uiRenderer`；布局提供者撤回根槽位时，宿主不会先卸载原来的 React 根。README 所述布局依赖不能用于证明这个卸载屏障存在。业务插件也拿不到启动挂载返回的 disposer，重复调用 mount 会越过装配责任边界。

本次采用根代码重新应用时的标准整页更新。客户端只用一个页面内的原始值标记区分代码代次；同一代代码重复应用不会触发更新，也不保存旧根、上下文或 Workbench。旧 Workbench 正常释放资源并持久化既有草稿，另存一次性返回点。新代码确认返回点可以保存后，每次代码替换只重载一次。新页先核对实际工作区路径和文稿稳定身份，再恢复仍存在的页、步骤；进入文档编辑，不恢复自动播放。返回点不包含正文，也不代替文稿的草稿机制。

`root-hmr-recovery-before.json` 在原始代码隔离副本中记录：完整三页、单个 BlockNote 编辑器可以输入，未确认文字已进入既有恢复存储且未写到磁盘；代码更新后继续观察 15 秒，同标签页仍空白，出现一次根槽位异常。

`root-hmr-recovery-after.json` 的 21 项实际检查全部通过：

- 连续两次代码重建后，同标签页分别在 1627 ms、1294 ms 恢复完整单编辑器与未确认草稿，并保持第 2 页第 2 步。每次仅发生一次自动导航。
- 恢复稿没有自动提交；作者明确点“重试”后，实际磁盘才包含恢复内容及随后输入。普通原生输入、真实保存、切步均不发生整页导航。
- 再打开另一份文稿并更新根代码，只恢复另一份文稿自己的返回点，没有附上上一份文稿的草稿。
- 旧文稿身份、其它工作区的同名目录和未激活的返回点均未自动打开文稿；返回点只消费一次，新页面没有重载循环。

三次根代码替换的旧卸载阶段仍各记录一次原有根槽位异常，随后完成上述恢复；HTTP 失败为零。因此验收结论是**同标签页自动整页恢复**，不是无异常的局部 React HMR。异常发生在宿主装配边界，本次没有延时重试、修改框架或保留失效根注册。普通文稿 SSE、保存、切页与主题状态不进入代码代次判断；本次实际覆盖了输入、保存和切步，不把它们扩大为所有插件替换场景。

另按原首页基线运行 `root-hmr-home-after.json`，7 项检查通过：连续两次代码重建分别在 1340 ms、1453 ms 恢复同一标签页首页，各自动导航一次，之后新页面冷打开正常；无文稿写入和 HTTP 失败。两次旧卸载异常同样保留，没有把导航恢复记作无异常。

恢复仍受既有同源、同标签页的浏览器存储约束；存储失败时不自动导航，并输出明确错误，不声称该条件已经能恢复。首次恢复不保留原生 Undo 栈或精确光标，未保存内容继续需要作者检查并明确采用。一次中间消费者曾直接读取尚未提交的 React 状态和错误的本地化步号字符串，原始记录保留为 `root-hmr-recovery-initial-after.json`；最终检查等待真实 `data-step-narration` 目标，没有放宽页步断言。

仅在独立临时工作区和动态端口运行真实 Studio，宿主启动前完成隔离客户端构建。文稿写入只有临时副本中的明确恢复保存，没有修改公开服务、用户文稿或全局客户端产物。记录和日志权限为 600，隐藏凭据；浏览器、服务与临时目录已清理。轻量验证包括类型、分层与 diff 检查，没有新增测试或运行套件。
