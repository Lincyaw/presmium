# 工作台根布局代码重载

2026-10-27，对此前浏览器记录中的 `renderSlot('root') before any 'root' registration (boot order)` 异常进行隔离复现。

## 已观察事实

使用真实 Studio、独立工作区、动态端口与隔离的客户端构建。首次进入首页后，只给隔离客户端的有效 JavaScript 产物追加一行注释，使现有 Harness 代码重载链采用新的产物。没有修改文稿或重启正在使用的公共服务。

`root-hmr-probe.json` 记录：

- 首次冷打开首页成功；启动图没有原生 `ui-layout`，根槽位由 Presmium 提供。
- 代码重载后实际样式节点已经替换，但原标签页出现上述异常；继续在同一标签页观察 10 秒，首页没有恢复。
- 同一服务上重新打开一个页面，首页正常。没有 HTTP 失败或文稿写入。

另外在隔离副本中，将布局服务注册从 `ctx.reflect.provide` 改为文档化的 `ctx.provide`，并在 Host 启动前完成构建。`root-hmr-provide-clean-probe.json` 再次得到相同结果：冷打开成功，原标签页重载失败，新页面正常。这项试验没有进入产品源码。

更早一次在 Host 启动后才替换注册调用的试验，首页打开前就遇到异常；它混入了初始图与重建的交错，保留原始记录，未用它判断两个注册接口的差异。

## 当前结论与限制

故障已缩小到根布局提供者替换期间的生命周期边界。仅更换服务注册接口没有修复它；现有证据还不足以区分 Presmium 的根布局清理与宿主 renderer 重挂载各自的责任。没有修改依赖、保留失效插件的根槽位、增加延时，或伪装旧标签页已经恢复。

客户端代码重建后的交付需要重新加载页面，并以新页面的真实内容验收；这条操作不代表原标签页的自动代码替换已通过。普通文稿操作的编辑器生命周期由其它记录验证，本记录不扩大该结论。

原始记录位于忽略目录 `.presmium/ui-evidence/`。两个有效复现均使用同一存活服务和标签页等待结果后再结束；自己的浏览器、服务和临时目录已清理。未新增测试或运行测试套件。
