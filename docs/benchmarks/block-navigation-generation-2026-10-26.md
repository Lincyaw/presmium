# 文档内多卡片导航代次验证

日期：2026-10-26。使用私有 Studio 17359 的独立 JSON 文稿，未改公共 4320 或示例文稿。验证使用真实编译器、文件组件、Scene、原生编辑器与播放协调服务；通过暂存真实消息控制交错顺序，不模拟播放器或时钟。

## 修复前

- 捕获 Scene 发出的真实旧位置消息，父界面完成“第二步 → 第一步 → 第二步”后再放行，父位置从第二步回到第一步。
- 父界面打开当前第二步的讲稿，未改变步号；放行另一卡片的旧第一步消息，编辑目标仍会回到第一步。
- 独立审查在非安全 HTTP 来源运行真实 Workbench，发现新增的构造阶段 `crypto.randomUUID()` 不可用，工作台无法构造。

## 实现

全局位置提交产生独立导航代次。只读块的位置与播放请求回显代次，父端同时校验窗口、来源、文稿修订、源码版本和代次。父端采纳本地导航后用 `sync` 确认，不重新跳步或暂停该卡片；确认在途时的新输入会以新代次重新报告。

作者明确暂停或打开当前步骤的编辑区也推进代次，普通运行时重复位置不会推进。同一步暂停保留当前时间，目标不同时才重建指定画面。代次使用每个 Workbench 实例的随机前缀与递增序号，支持局域网明文 HTTP。
