# 字数统计与导航手柄更新成本

本轮从包含全部文档新界面的 `845e4e20` 建立新基线，沿用单个 BlockNote、完整规范 JSON、完整页面 DOM 和立即持久草稿。源变更仅涉及 `outline.ts`、状态栏字数钩子与公共排序行的手柄 ref；没有改动导航组合、拖动传感器、手势状态机、保存合并、CAS 或文稿数据。未运行测试套件、模型或语音生成，也未改用户文稿或重启公共 Studio。

## 方案比较与选择

实际浏览器用公开 `countWords` 和相同规范文稿，比较直接扫描、内容签名缓存、首帧后扫描，每档每种三次，共 18 个样本，结果逐项与原函数一致。1000 块直接统计为 `7.0 / 8.3 / 7.6ms`；试算缓存为 `2.3 / 1.4 / 1.5ms`；延后扫描仍需 `9.9 / 7.4 / 9.6ms`。这是函数 CPU／纯显示消费者，不作为 Studio 单键延迟。

最终选同步缓存，避免增加异步字数状态。缓存以文稿 identity 隔离、稳定块 ID 和页面 ID 索引，删除后清理旧项。签名只包含原统计函数访问的每个文本叶字符串，保留节点边界；代码值、扩展 data、样式和未计数的参数不进入签名。签名变化时才计算对应文本，标题同样按原语义统计。只保存计数及其输入签名，不作为正文写回或另一权威文稿；actor 深克隆不会破坏这种比较。

独立审查发现过一个必须修正的中间版本：对整个 rich content 序列化会扫描本不计数的代码和扩展 data。审查者实际 inline 探针的 5MiB 合法代码中，原函数中位数约 `0.00554ms`，中间缓存约 `15.86309ms`。这个 before 来源为当时工具输出，没有重造旧 class。最终公开 class 的独立 9 次原始采样中，1／5MiB 代码的 warm 中位数为 `0.0070 / 0.0061ms`；1／5MiB 扩展 data 加真实 fallback 为 `0.00654 / 0.00660ms`，全部通过真实领域校验且计数精确。相邻 Latin 叶 `alpha`、`beta` 保持两词，合并为 `alphabeta` 后缓存失效、变为一词，未通过拼接文本改变统计口径。

## 手柄回调的调用链证据

仅缓存还不足以达到目标。完整 Studio 的 CPU 采样显示，正文更新后 React ref 提交反复触发拖放注册表扫描：匿名注册表 effect、平台检测及指针传感器准备处于同一 ref 更新子树，约 37.6ms。源头是每个排序行每次渲染都重新创建手柄回调，100 页更新导致 DOM ref 反复 detach／attach。

公共行现通过稳定 `useCallback` 委托最新 `handleRef` 与 `onHandle`。没有 memo 冻结 actions 或权限，也没有改变键盘、取消、pending、scope 和焦点状态。对应实际采样中，该注册表子树未再出现。原始 CPU、实际运行脚本及汇总都保留；采样等待、Debugger 取脚本的开销不混入无 profiler 的单键结果。
