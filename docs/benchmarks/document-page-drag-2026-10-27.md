# 文档页面拖动与键盘重排

运行开始于 2026-10-26，北京时间跨至 2026-10-27。使用既有隔离 Studio 的示例副本，未重启公共服务，未改作者文稿。

## 实现边界

页面栏使用公共 `PmSortableList`，指针、触屏、键盘与取消由 dnd kit 负责。菜单中的上移／下移保留。每次有效放下只调用一次既有 `movePage(sectionId,beforeId|null)`；它先排空正文和字幕输入，再修改唯一文稿的 `sectionOrder`，继续经过版本检查和真实保存。

页面选择独立于排序；正文正在保存时仍能选择另一页。组字、恢复／错误状态、agent 锁及页面／历史操作期间不能开始新排序。文稿身份、页面集合或外部重置改变时，过期手势和回执不能修改新列表。排序过程的视觉顺序不会成为第二份权威文稿。

## 实际运行

`page-drag-workflow.json` 在最终隔离客户端中完成 **29/29** 检查：

- 在浅色、深色和 1440 桌面、390 真实触屏四个上下文分别复制真实课程。
- 选择第三页后，用真实键盘将第一页移到末尾；每次恰好一个文稿变更请求，第三页仍选中。
- 对比完整规范 JSON，除 `sectionOrder` 外，实体、页面、步骤、讲稿、素材定义及制作绑定完全相同。
- 桌面使用真实鼠标拖动还原顺序；触屏通过 Chromium 的真实触摸输入完成拖动还原。
- 桌面行与热区为 30px、文字 13px；粗指针下热区 44px、文字 16px。高容器中的三行没有被拉伸成整屏等分。
- 操作后仍为完整三页、一个原生正文编辑器，没有进入制作界面。前端异常、失败请求及生成请求均为零。

四张 `page-drag-{light,dark}-{1440,390}.png` 已实际查看。原有菜单提交边界的独立记录 `page-reorder-contract.json` 为 10/10：真实正文保存回执被延迟时启动移动、等待时选择另一页，放行后仍保留新选择；编辑字幕后立即移动也保留正确身份与输入。该记录不被当作拖动传感器的验证。

公共控件的手势取消、迟到 Promise、外部顺序变化、读屏与三种密度由独立消费者验证，见 [公共排序控件验收](public-sortable-2026-10-27.md)。Figma 21 个变体及明暗矩阵登记在 `figma-nodes.json`，所有样式来自公共令牌。

## 保留的观察与范围

最初消费者在拖动期间用同一个属性定位器重新查询按钮，匹配到原生反馈占位副本；该副本由库设置 `aria-hidden` 和 `inert`。随后改为向真实焦点发送按键，没有改变产品以迎合断言。

另一次不等待拾起状态、极快连发四键时未提交。最终消费者先观察真实 `data-dragging`，拾起耗时约 47–53ms，再以 40ms 的按键间隔移动；没有把它描述为快速连键问题已修复。原失败记录保留在忽略证据目录。这里的截图验收限于页面栏和正文编辑边界，不证明截图时仍在更新的动画已全部就绪。
