# RFC：文档编辑、编译放映与视频制作

状态：按三个独立入口分阶段实施，当前优先验收文档编辑；实施范围见第 10.1 节。更新日期：2026-10-27。

本文确定 Presmium 作者工作台的 UI/UX，供产品、设计、开发与验收使用。工作台以同一份权威文稿为来源，分为文档编辑、编译放映和视频制作三个独立、松耦合的部分。文档编辑参照飞书，编译放映参照 Overleaf，视频编辑、配音和录制参照剪映。先把文档编辑的完整体验做好，再依次验收后两部分。

本文覆盖 `design-dsh.md` 第 7 节中的旧界面方案，记录产品边界、目标契约与验收。Figma 的正式控件和交互状态、对应 JSON 与本文构成同一设计基线：视觉取值来自公共令牌，可见交互按 I01–I12 对照；发现冲突时先同步修正，再实施，不能由页面临时选择一种解释。dsh 接入、工作区服务与预览协议仍由 [工作台设计](design-dsh.md) 定义；可编辑文稿语义由 [文稿 IR RFC](rfc-document-ir.md) 与其引用的 schema 定义，派生运行快照由 [IR 规范](ir.md) 定义。本 RFC 描述目标行为，不表示当前服务已经完成迁移。

设计文件在 [Figma：Presmium 工作台](https://www.figma.com/design/CjQ5JFn3PuGXx0NgwYrCR8)，页面、状态与功能的对应关系见 [原型覆盖说明](prototypes/workbench/README.md)。第 01 页通过线框对齐功能，第 02 页固定公共控件，第 03 页固定交互状态；功能清单为 [screens.json](prototypes/workbench/screens.json)，交互规则为 [interactions.json](prototypes/workbench/interactions.json)。原型不实际执行合成、剪辑、生成或导出，也不以其中的按钮表示功能已经可用。

## 1. 决策与边界

作者可以直接编辑页面，也可以先提交一批材料，由 agent 调研、分析并生成内容，再通过对话和批注微调。文档编辑中的新建页、输入、格式、块操作、批注、撤消和保存始终留在文档。编译放映从明确保存的版本准备预览；视频制作独立处理步骤、讲稿、配音、字幕、录制和输出。三者共享文稿与版本契约，各自保存面板、选择和草稿状态；正文操作不会自动进入放映或字幕编辑。

| 参考形态 | 采用的交互 | 在 Presmium 中的边界 |
|---|---|---|
| [飞书文档](https://docs.feishu.cn/docs) | 块编辑、就地修改、批注 | 处理正文与内容块 |
| [Overleaf](https://docs.overleaf.com/navigating-in-the-editor/working-with-the-pdf-viewer/pdf-viewer-options-and-navigation) | 编辑与编译结果分离、定位和任务反馈 | Web 呈现内容与预览；工程文件留在技术编辑环境 |
| [剪映／CapCut](https://www.capcut.com/resource/how-to-use-capcut) | 预览、时间线、所选片段属性 | 处理步骤、配音与字幕的时序 |

保留 React、BlockNote、现有编译器和 IR。底层由代码根据步骤及步内时间绘制对应画面；Web 用内容编辑、属性和对话操作这些能力，不要求作者理解代码。通用控件经公开接口复用 Radix Primitives、react-resizable-panels 与现有设计组件；图标统一经 `@lincyaw/design` 使用 Lucide。此次设计不引入 Web 项目级 IDE、通用视频剪辑工程或 Vue 运行时。

正文编辑、步骤编排和画面预览不依赖模型。配音只在作者配置了对应语音服务并主动生成时使用该服务；AI 助手始终是可选工具。

文档编辑、编译放映、视频制作是独立入口，不是一个编辑画布中的隐式模式切换。进入放映或视频制作必须由作者显式操作；打开辅助面板、修改正文、保存、选区和动画跳步均不能代替该操作。视频制作中的编排是它自己的编辑视图；导出是对应部分的任务。尚未完成的入口不以空跳转或假状态开放。

### 1.1 Web、桌面与 VS Code

Web 面向非技术作者。常规流程不展示源码、IR、文件树、插件名、命令或原始堆栈；内容、素材、参数、生成进度、审阅和错误恢复足以完成创作。技术细节供 agent 读取，用户需要求助时可以复制诊断摘要。此前块内源码／预览／分屏与 CodeMirror 入口退出普通 Web 界面，不能通过改成小图标继续常驻。

Tauri 客户端复用同一 Web 界面、项目模型和操作流程，只适配文件访问、原生窗口和桌面任务等宿主能力。它不维护第二套文稿或单独设计一套剪辑界面；本轮原型展示这种复用关系，不承诺桌面版已经可用。

VS Code 由用户在原生编辑器中修改规范 JSON 文稿或引用的代码文件，Presmium 插件负责预览、诊断定位和导出。不在插件里复制 Web 的块编辑器、素材工作区、对话或时间线编辑。两种入口读取同一项目修订，预览与导出使用同一渲染和讲授计划。

### 1.2 单一权威输入

2026-10-26 用户确认取消 MyST 文稿入口，直接迁移为可编辑的教学文稿 IR，以 JSON 作为唯一权威输入，旧文稿迁移后删除旧入口。完整领域结构与实施边界见 [文稿 IR RFC](rfc-document-ir.md)。

文稿 IR 保存作者的内容、引用、步骤与编排决定；运行快照保存派生的数字步号、资源发布结果与播放计划。只有文稿 IR 可以被 Web、agent 和外部编辑器修改，三者共用结构、语义与版本校验。代码、素材和录制文件保持明确引用，与 JSON 作为工程文件事务一起采用和撤消。

文档工作区使用一个全篇原生块编辑器直接操作结构化文稿，编译放映独立消费运行快照。删除源码范围映射、语法保留和 Markdown 回写适配；不保留两种可写格式或 MyST 运行时兼容层。第 10.1 节记录当前实现，格式迁移与新链路验证独立提交。

## 2. 用户对象与统一术语

| 名称 | 含义与数据来源 | 界面约束 |
|---|---|---|
| 文稿 | 唯一权威入口 `lecture.json`，保存结构化内容及代码、资源引用 | 顶部显示文稿标题，不要求作者辨认文件格式 |
| 页面 | 以稳定 ID 保存的 `Section`，编译为 `IRSection`，放映时对应一张幻灯片 | 页面标题、编号和缩略图用于导航 |
| 内容块 | 页内的正文、教学代码、动画或插件内容，以稳定 ID 保存并派生 `IRBlock` | 正文直接编辑；生成内容经公开属性、对话或批注修改 |
| 来源材料 | 作者上传或引用的文档、图片、音视频和链接 | 标识处理状态、来源及使用范围 |
| 生成素材 | agent 根据材料生成、可引用的图表、动画、画面或其他内容 | 显示预览、版本与引用关系，代码作为内部实现 |
| 步骤 | 页面内以稳定 Step ID 保存的可定位视觉状态，由 `stepOrder` 决定顺序 | 显示序号，绑定讲稿与播放位置 |
| 讲稿 | `Narration` 中的结构化讲解，由 `Step.narrationIds` 显式引用 | 在步骤属性中编辑，字段统一叫“讲稿” |
| 配音 | 由讲稿生成或由作者录制的音频 | 显示来源、可用状态和实际时长 |
| 字幕 | 播放时显示的文字，由讲稿或录音对应文本生成 | 默认跟随文本来源，不重复维护一份可编辑正文 |
| 转写文本 | 识别录音得到的文本，属于录制轨 | 明确标识录音来源，与讲稿保存目标分开 |
| 编排 | `Production` 保存时机等作者决定，讲授计划和 `LectureTrack` 派生播放时间线 | 不另存可写的时间线工程 |

“逐字稿”“这一刻要讲什么”“我来试试”“回到讲授”退出工作台的常规文案。“讲授轨”等内部领域名保留在技术文档与协议中，作者界面按用途使用“配音”“录音”“字幕”。录音识别文本不能只改名为讲稿后直接覆盖文稿中的 `Narration`。

正文保存在文稿的内容块中；讲稿保存在 `narrations`，通过稳定 Step ID 绑定，不从正文或数组序号推断。字幕的显示文字由讲稿的 `text` 与 `pronunciation.display` 派生；`cue` 保留动作、目标和稳定身份，时序由 `Production` 保存。导入与迁移保留这些区分，不把正文、字幕和配音维护成相互竞争的文本来源。

派生运行快照的步号从 0 开始，界面从 1 开始；`IRSection.steps` 是最后一个步号，因此页面有 `steps + 1` 个状态。只有初始状态的纯文字页面也可编写讲稿，其单一步骤控件默认收起。完整文稿与特定媒介的步号通过 `trail`、`stepMap` 换算，不直接复用过滤后的序号。

## 3. 外壳与信息层级

### 3.1 固定区域

| 区域 | 文档编辑 | 编译放映 | 视频制作 |
|---|---|---|---|
| 应用栏 | 文稿路径、标题；助手、更多、设置 | 编译版本与返回文档 | 制作版本与返回文档 |
| 工具栏 | 页面、撤消、恢复、保存、批注与文档导出 | 编译、预览、放映与诊断 | 播放、剪辑、配音、录制与视频导出 |
| 中间 | 连续的 BlockNote 文档 | 已编译版本的页面与步骤 | 当前画面和三轨时间线 |
| 辅助面板 | 按需显示内容属性、批注或历史 | 编译状态与可定位的失败原因 | 步骤、讲稿、音色、字幕与素材属性 |
| 状态 | 文档输入与保存反馈 | 编译中、成功版本或失败 | 当前版本、生成任务与播放位置 |

文档编辑不常驻步骤时间线、字幕、讲稿或配音面板。页面栏用于滚动定位，连续显示完整文稿，不能把其余页面隐藏成丢失状态。编辑器可以按需加载，未加载页仍显示正文。内容、选区和保存事件只更新文档，不触发放映视图或视频制作入口。页面标题和编号保留文字；助手默认收起。

文档内按需展开的字幕编辑只提供字幕和配音开始时机；音色、继承、停留时长、结束停顿和发音工具放到视频制作。标签采用简短名称，不常驻解释模型、内容派生或内部保存方式；错误、未保存状态和需要确认的影响范围按需显示。

每个部分各自管理辅助面板和草稿；切换入口保留返回点，不替另一个部分自动提交未确认输入。普通 Web 展示内容、结果、任务与可理解的诊断；终端、实现代码和工程文件保留在技术入口。

素材导入与 agent 任务可以从项目起点进入，也可以在当前文稿中打开。任务进行时不阻止作者继续编辑无冲突内容；任务结果先成为可审阅的版本，不因回到工作台就静默替换已修改页面。

三个主入口使用清楚的名称。日常工具栏、块工具、步骤导航与放映控件优先使用图标按钮，颜色和边框表达状态。禁止用表情符号、临时字符或多套图标库代替统一图标。

图标按钮必须有本地化的 `aria-label`，悬停和键盘聚焦显示名称与可用快捷键，触屏有可点击的完整操作菜单。状态控件设置 `aria-selected`、`aria-pressed` 或相应语义；禁用原因可查看。禁止只靠图标颜色、悬停或快捷键暴露功能。

页面标题、字段名、选项含义、时间码、错误及破坏性确认保留文字。菜单和对话框允许图标配合短文字。用户不必通过猜图标来选择配音时机、确认删除或理解编译错误。术语和快捷键在工具提示、菜单及读屏名称中一致。

## 4. 内容工作区

### 4.1 页面管理

页面栏的加号在当前页之后创建独立页面，创建后聚焦新页正文。页级更多提供重命名、复制、删除和移动；拖动页面只改变页面顺序。块的插入加号在当前页插入内容块，不创建页面。斜杠菜单中的“新建页面”必须带页面图标，并明确创建页级对象。

新建页面前完成同一文稿的待保存输入；以规范文稿的页面、步骤身份和源版本插入页面。创建、复制、删除和移动分别成为可撤消的文稿修改。删除含讲稿的页面时说明关联内容；失败或来源边界不明确时保留原文和草稿。源事务确认新页已保存后才移动选择；正文编辑不等待编译成功，不能先显示一个尚未保存的假页面。

删除页面前显示关联步骤与讲稿数量。完成后选择下一页，没有下一页则选上一页；删除最后一页后保留一个空白页。只移除该页的素材引用，不删除共享原素材。撤消作为一次修改恢复原页及其绑定，失败时选择和原内容保持不变。

页面标题直接编辑，普通正文支持 BlockNote 的段落、标题、列表等块转换与排序。不能无损转换的插件块保留定义引用、类型和完整参数；转换菜单说明原因，不丢弃不支持的属性。纯文字页面、混合页面和动画页面使用同一套页面管理。

移动页面保留页面、块与步骤 ID。移动正文块时保留并校验显式步骤、讲稿、cue 和素材引用；不能安全完成时拒绝移动并说明原因。修改动画步骤结构时同步检查已有讲稿和草稿的绑定，不能按新的序号静默接到其他内容。

### 4.2 内容块与生成素材

生成内容默认显示可预览的画面，块头只保留类型图标、预览、属性、批注和更多入口。作者通过该素材公开的参数、对话或批注修改它，不切换到实现代码。教学材料本身需要呈现的代码仍可作为正文内容块编辑，不能与生成画面的实现源码混为一谈。

新增动画生成独立定义与正文引用，并作为一个可审阅修改交付；规范文稿与引用代码通过同一 `document/change` 事务原子保存和共同撤消。多个块引用同一生成素材时，以链接图标和数量提示共享关系，应用修改前显示受影响的页面与块。复制为独立素材必须是显式动作，不因编辑某个引用而默默改变其他页面。

共享素材的默认修改范围为“仅此处”，审阅中明确显示将创建独立副本并切换当前引用；只有主动选择“所有引用”才修改共享素材，采用前列出受影响位置。副本和引用变化作为一次修改共同撤消。删除素材时若仍有引用，默认保留原文件并定位引用，不允许留下不可恢复的空引用。

生成、修改与预览更新是不同状态。任务处理中保持上次成功画面，失败时给出对应内容的简短原因和重试、保留原版或交给助手的入口。技术诊断绑定当前块与源修订供 agent 使用，常规 Web 不展开代码文件和堆栈。接受结果后才将对应修改写入权威内容入口，不能用任务启动时的旧快照覆盖后来编辑。

### 4.3 位置标记与批注

文档编辑的块工具只处理插入、排序和内容操作，不混入步骤或讲稿入口。页与步骤标记属于编译预览和视频制作，使用图标、数字和简短范围，例如“2 · 3”或“2 · 3–6”。标记不进入正文、选择文本、字数、字幕和导出。

正文选择、输入和块工具保持文档编辑。作者可以显式打开本步讲稿辅助面板，纯文字页与空页也可使用；面板与文档内动画共用当前稳定步骤，不进入放映或视频制作。正文、讲稿及迁移内容均须完整保留，不因打开辅助面板而隐藏正文或改写其绑定。

正文编辑以原生选区的活动端同步页面和字幕目标，同页内移动保留已选步骤。光标仍在正文视口内时保留编辑位置；滚离光标后按实际阅读位置切页，滚回时恢复编辑页面。动画和字幕获得焦点后，旧正文光标不能覆盖它们的选择。打开侧栏、预览释放和布局变化本身不选择页面。

行内字幕使用当前聚焦字段的稳定步骤，聚焦引发的自动滚动不能改选其目标。返回动画后的新操作应继续同步父位置和字幕，不能依赖 iframe 再次触发 focus 事件。

正文选区、跨块跨页选择与评论线程使用 BlockNote 原生扩展，格式和批注操作通过公开工具栏提供，不由全局 DOM 选区桥接。运行预览的批注入口只保留一个新建批注图标，使用该预览的定位契约；`Esc` 先退出表单，再清除选区。AI 改写通过当前焦点或批注进入助手，不增加第二排悬浮操作。

### 4.4 材料、对话与生成闭环

作者可以一次提交文档、图片、音视频或链接，并填写目标、受众、时长和需要保留的材料。导入界面显示材料清单、处理状态、失败项和可重试入口；素材库区分原始来源与生成结果。材料的来源和引用位置可查，来源不足或互相矛盾时由 agent 标注，不能只交付没有依据的成稿。

agent 按“整理材料、调研分析、组织方案、生成内容、准备预览”报告进度。任务可以暂停、取消和从失败阶段重试；用户可以查看并修改方案，也可以允许 agent 连续完成后一次审阅成稿。普通作者看到结果和需要决定的问题，不暴露工具调用、代码差异或内部执行日志。

方案展示页面结构、主要观点、生成素材和预计步骤，成稿审阅展示新增、替换及保留内容，并可比较修改前后的画面。接受、拒绝或继续对话分别形成明确结果；拒绝保留当前文稿，接受沿用版本与来源校验。单个素材生成失败时可重试该项，不能要求整份材料重新导入。

“接受”以依赖完整的修改组为最小单位，相关内容、素材和引用原子应用；局部采用不能拆开互相依赖的变更。任何写入失败则整组不生效。任务所基于的内容或目标发生变化时，结果标为“已过期”，不能直接采用旧结果，须基于当前内容重新生成或评估新方案。

对话可以作用于整个项目、当前页面、内容块或步骤，输入区用紧凑位置标签显示范围。批注用于精确指向选区并描述局部修改；批量批注可以一次交给 agent。两种入口共用焦点、任务和审阅机制，任务完成后定位到受影响内容，保留未处理批注和用户输入。

## 5. 视频制作

本节规定独立视频制作入口的完整目标。它复用规范文稿中的讲稿与制作设置；文档编辑可显式打开同源讲稿辅助面板，但正文点击、选区和保存不自动进入视频制作，现有字段也不表示时间线、录制或剪辑已经完成。

### 5.1 选择与预览

编排中的画面与放映使用同一查看器、页面比例、主题、字体和步骤计算。下方的页面时间线、步骤选择器与右侧属性都指向同一个当前步骤。点击任一步骤立即定位并显示其画面，无须先播放前序步骤；正序、倒序和随机跳转的同一步骤结果一致。

定位后主动挂载该步骤所需的内容块，不能依赖正文滚动区是否可见。异步动画模块尚未就绪时显示加载状态，失败时提供对应步骤的诊断入口；不能把空白当作步骤已显示。

步骤导航使用数字按钮，空间不足时通过步骤图标展开完整列表。列表显示当前步骤、序号和可用标题，支持键盘选择；全部步骤都可到达。选择页面时恢复该页上次选择的步骤，没有记录时进入初始状态。纯文字页的讲稿入口仍然可用。

上一步／下一步在页首和页末跨到相邻页的末步或初始步；项目首尾不循环，越界操作禁用并保留当前位置。编排默认播放当前页，页末暂停；放映的自动播放可以跨页，项目末停止并显示“播放结束”。任何定位失败都保留上次有效位置，不前移属性目标。

选中某步骤后，正文或动画、讲稿、配音状态、字幕和时间线选中片段同时更新。尚无讲稿时显示空输入框，不复制相邻步骤，也不把整页正文当作默认讲稿。

### 5.2 讲稿与配音属性

右侧以“讲稿”为主要编辑字段，下面是配音时机、音色、字幕关系与配音状态。参数有简短字段名，常用操作使用图标。无讲稿、待生成、生成中、可播放、生成失败和内容已更新分别有明确状态。

正文和讲稿默认自动保存，讲稿通过 `Step.narrationIds` 引用规范文稿中的 `Narration`。`text`、`pronunciation` 和 `cue` 必须无损保留；`cue` 的停顿保存在 `Production.cueTimings`。编辑器未提供某项结构化操作时保留原实体并说明限制，不能压平成纯文本或转而覆盖其他步骤。

“生成配音”是显式操作，可选择当前步骤或整份文稿。打开工作区、跳步、打字、编译和进入放映只查询缓存与状态，不隐式调用语音服务。已有的服务提供方说明与外发确认规则继续适用；未配置引擎时就地显示设置入口与具体原因，不影响正文和画面预览。

讲稿修改后字幕立即跟随文本，旧配音标记为需要更新，不冒充新讲稿的音频。当前版本默认使用静音占位和新字幕，不自动播放过期配音；显式查看旧版本时，同时使用该版本的配音与字幕。新生成片段通过版本校验后替换旧片段，失败保留旧片段并标记过期。默认不提供独立的第二份字幕输入框；字幕样式属于显示属性。字幕译文沿用既有翻译能力，其来源关系保持可见。

已有真实词时码且显示文字能完整映射时，Web／VTT 与 Video 字幕轨现可共用可读句组；fine pointer 点击已确认句组先暂停并定位到实际词边界；粗指针使用步骤按钮与默认 44px 字幕片段动作选择器，允许同句中部再次返回起点，不扩大重叠热区。标点、顺序和发音显示文字保留，连续 ASCII 名称不按长度拆断。未对齐、比例估时、缺少独立词时码的译文或映射异常仍保留整段字幕；该自动分组不提供原音自动分句。Video 另支持作者明确的手动分段时间，见下文；Doc 仍只提供字幕和配音开始。范围与分阶段证据见[词时码字幕分段](benchmarks/timed-caption-segments-2026-10-28.md)。

Video 的“设置字幕时间”只针对当前稳定步骤：按规范讲稿换行明确分段，原文只读，作者填写步内开始／结束秒数后应用。有真实音频与已确认时长才可设置；手动时间标记为 `manual`，不生成词时码。Web、VTT 与实际视频烧录共用投影，段间可明确留白。讲稿／音频／本步时序变化会停用旧映射，保留原提案并要求重新检查；前序步骤位移只改变派生绝对时间。待应用输入按工作区 × 成员 × 稳定步骤保存在本标签页的 sessionStorage，离开 Video、刷新页面后恢复；Video 顶部列出有待应用输入的步骤，对话框可“放弃修改”；有待应用输入或备份失败时导出被拒绝并启用离开提示。它不跨标签页或关闭浏览器，不能当作正文或组件参数的 strict 草稿能力。实际范围见[手动字幕时间记录](benchmarks/manual-caption-timing-2026-10-28.md)与[待应用输入恢复记录](benchmarks/caption-timing-drafts-2026-10-28.md)。

录音在编排的更多菜单中作为配音来源管理。转写结果在标有录音来源的文本编辑器中修改，仍保存到对应录制轨。要将转写用于讲稿，必须显式选择“采用为讲稿”，显示目标页、步骤与已有讲稿差异，确认后沿用源码版本保存；不自动覆盖作者讲稿。

重录先形成当前步骤的候选片段，结束后可试听，明确采用前保留原录音。开始录音先暂停播放并固定目标，设备或权限失败不覆盖原录音；取消候选不删除原轨。采用录音与采用为讲稿是不同操作，替换范围在采用前可见并可撤消。

音色选择使用独立面板，显示音色名称、语言、简短特点、试听与选中状态，支持搜索和按语言筛选。没有可用音色、服务未连接、加载失败、试听中和试听失败均有对应原型状态。试听使用明确样本文本，选择音色不自动为整份项目生成音频。

项目有默认旁白音色，优先级固定为“步骤覆盖 ＞ 页面覆盖 ＞ 项目默认”；恢复继承后读取最近的上级设置。属性显示“继承页面”“继承项目”或“独立设置”。应用范围包括当前步骤、所选步骤、当前页和整个项目，批量应用默认保留已有独立覆盖，应用前显示更新和保留数量。语速和服务实际支持的风格可以设置，不默认展示所有服务都不支持的音高或情绪参数。提供方、音色与能力范围由服务返回，不在原型中假设任意音色可用。

试听先暂停编排播放并保留播放头，同一时刻只播放一个试听；换音色或关闭选择器立即停止，关闭后不自动恢复编排播放。选择音色不合成，当前讲稿试听由独立的显式动作触发。试听失败不修改已应用音色。

从讲稿属性发起生成时默认范围为当前步骤，默认只处理缺失和过期片段；批量范围由作者显式选择。结果按发起时的讲稿、音色与修订校验。新片段改变当前播放步骤的时序时先暂停，等待作者再次播放；旧结果不替换新版本，取消保留已完成且有效的片段。

### 5.3 时间线

底部默认显示当前页的连续时间线，步骤边界可以选择和跳转。画面、配音、字幕使用三条对齐主轨道，导入的媒体片段按需展开，轨道头以图标表示类型；配音使用波形，字幕使用文本片段，画面按步骤分段。颜色区分轨道，选中态另有轮廓与位置标记，不能仅靠颜色识别。

时间线支持选择片段、点击时间尺定位、拖动播放头、播放／暂停、缩放和适配当前页。步骤列表提供不依赖拖动的跳转。播放头所属步骤是画面与属性的唯一选择；播放跨步骤时，两者一起跟随。点击片段或步骤先暂停并定位到对应步骤起点，点击时间尺则暂停并定位到所选时间。聚焦讲稿或开始修改属性前先暂停、固定编辑目标，禁止自动播放在输入过程中切换目标。

首期不支持自由拖动讲稿到任意页面、把音频跨步骤拆散或任意剪断生成动画。配音起点由时机选项确定，字幕跟随文本和配音。时间线是既有讲授计划的编辑视图，不新增独立时间线文件。

| 配音时机 | 画面与配音关系 | 步骤时长 |
|---|---|---|
| 同步播放，`during` | 动画与配音同时开始 | 同时满足动画结束和讲稿播放结束条件，停顿沿用既有计划 |
| 动画结束后播放，`after` | 最长动画完成后开始配音 | 动画完成后追加讲稿播放，停顿沿用既有计划 |

多个动画使用该步骤声明时长的最大值；纯文字页面的动画时长为 0。配音时长来自实际片段，无片段时以明显不同的占位样式显示估算时长。上述关系用于说明时机，最终起止时刻始终由既有讲授计划的事件序列派生，包括讲稿 cue、段落间隔和 `Production` 中的显式停顿。不能另算一条互相冲突的时间轴。例如没有额外停顿时，动画 3 秒、配音 5 秒的两种模式分别占用 5 秒和 8 秒。

不能确定动画时长时标为未知，不把估算展示为精确结果；依赖结束时间的 `after` 配音和导出要求先提供有效时长。切换配音时机后，轨道起点、总时长、预览和导出计划同时更新。

### 5.4 基础剪辑

首期剪辑围绕步骤与引用素材，不把可逆动画切成一段段失去结构的视频。原型必须提供选择、拖动播放头、精确时间输入、缩放、适配范围与撤消；不依赖鼠标拖动才能完成操作。

| 操作 | 行为与边界 |
|---|---|
| 调整停留与停顿 | 静态画面停留、步骤间隔和讲稿停顿成为结构化属性，重新派生播放计划 |
| 调整配音时机 | 同步或动画结束后播放，画面、配音与字幕一起更新 |
| 配音音量与静音 | 作为输出混音参数，不改写讲稿；录音和合成配音有明确来源 |
| 裁切导入音视频 | 设置素材入点和出点，保留原始文件；显示原始范围、使用范围和时长 |
| 替换媒体或配音 | 展示被替换范围及关联字幕状态，接受后更新引用，可撤消 |
| 页面与步骤重排 | 页面作为整体移动；步骤重排需要稳定身份和绑定校验，契约完成前不开放自由拖动 |
| 动画参数调整 | 仅修改生成素材公开的参数；未公开的时长通过批注或对话请求修改 |

结构化停留、结束停顿与配音时机由 `Production` 表达。视频制作已接入同文稿本地音频的导入、区间、偏移、音量、静音与移除；真实预览和 WebM 导出消费同一片段设置，边界见[音频作者契约](audio-authoring.md)。Video 的“原音频”卡另支持明确 wholeStep 采用：保存候选或选择既有音频后，采用为当前稳定步骤的整段配音；不修改讲稿、不启动 ASR/TTS，不是媒体背景片段或跨步骤连续分配。已采用原音的本步源区间可在 Video 明确裁切，整步字幕保留且标为未对齐／待核对；真实播放和混音导出使用同一范围。视频文件和字幕重新对齐仍未接入。不得在原型中表现为任意拉伸程序动画、跨步骤散剪讲稿、自由剪断词语绑定事件或无限多轨剪辑。裁切录音影响字幕对齐时显示待重新对齐，不能保留看似精确但已失效的时间码。

新增的无配音静态步骤默认停留 4 秒，新增结束停顿默认 0.5 秒；这些默认值不迁移或重置既有文稿的播放计划。导入媒体初始使用完整区间，入点包含、出点不包含，必须满足 `0 ≤ 入点 < 出点 ≤ 原始时长`。拖动结束或数值提交形成一次可撤消修改；无效输入保留编辑值和上次有效计划，不能静默修正后保存。音量默认 100%，首期范围为 0–100%；静音保留原音量，取消静音恢复该值，不删除音频或字幕。

### 5.5 字幕与预览设置

字幕面板提供显示开关、语言、样式、字号、位置、安全区与断句预览。字幕文字默认来自讲稿显示层，校对仍回写同一内容来源；发音替换、译文与字幕样式分别保留来源关系，不新增游离的第二份字幕正文。录音转写沿用明确的录音来源。

字幕可以逐句定位到步骤和对应时间；过长、溢出、安全区冲突、缺少对齐和译文过期均有状态。导出提供内嵌字幕或独立字幕文件；预览中关闭字幕不静默删除字幕内容，也不替作者决定最终导出设置。

首期字幕样式默认作用于整个项目，不另提供每个步骤一套样式。播放器字幕开关只改变本次预览的显示，导出方式独立选择；修改字幕文字回写讲稿或录音转写来源，不建立第二份正文。样式修改可撤消，缺少对齐时不假装已有精确时间码。

## 6. 统一位置、草稿与编译状态

### 6.1 位置规则

工作台以项目、文稿、页面、可选块和稳定 Step ID 标识内容目标，另外保存派生运行步号、`trail`、步内播放位置与当前工作区。`Section.stepOrder` 决定步骤顺序，媒介过滤通过运行映射定位；界面序号和数组下标不能充当跨版本身份。正文、讲稿和属性草稿绑定实际内容来源、范围与读到的版本，Web 不要求用户理解这些内部标识。

| 动作 | 位置和播放行为 | 草稿行为 |
|---|---|---|
| 显式进入另一个部分 | 使用明确保存的文稿版本，保留各自返回点并停止上一部分的音频 | 各自保留草稿，不代提交另一部分的输入 |
| 选择另一页或步骤 | 暂停；定位目标页、步骤和起点 | 旧草稿按原锚点保留，属性立即显示新目标 |
| 查看素材、任务或辅助面板 | 保留文稿返回点，显式采用素材后才修改内容选择 | 保留正文、讲稿、属性与对话草稿 |
| 进入／退出放映 | 保留当前页、步骤、工作区返回点；进入时不自动出声 | 不隐式接受 agent 的待审阅结果 |
| 与当前步骤无关的编译更新 | 保留仍有效的位置 | 不覆盖草稿；采用对应修订的结果 |
| 当前步骤的画面或讲稿发生修改 | 暂停并保留页、步骤；该步骤的播放位置归零，等待显式继续 | 保存后更新相应来源和配音状态 |
| 页面或步骤被删除、重排后无法确认对应关系 | 暂停，报告原位置失效，由作者重新定位 | 保留原草稿，不按新数组下标自动重绑 |

切换选择后不允许出现“画面在新步骤、右侧仍编辑旧步骤”的状态。旧草稿通过未保存标记和草稿入口恢复。保存回调必须携带发起时的目标、源版本和草稿修订，不能取响应到达时的当前选择。回调只确认发出的文本快照；保存期间在同一目标继续输入形成的新草稿不得被旧回调清除，而应继续排队保存。

从文档进入放映前先确认当前正文保存，再编译对应版本；准备过程保留文档和输入。未提交的视频讲稿、字幕或属性草稿不被文档操作采用。保存或编译失败时留在原入口并显示恢复动作；如提供上次成功版本，须由作者明确选择。待审阅结果与外部草稿不自动进入放映版本。

### 6.2 保存与版本

正文、讲稿与普通属性默认在最后一次输入停顿 600 ms 后按目标排队保存，失焦立即排队；继续输入重新计时，中文输入法组词期间不提交，组词结束后再计时。agent 生成的修改通过审阅采用。切页、新建页面或接受同来源修改前，顺序完成该来源所有待写回编辑；同源写入串行校验版本和范围，不能让不同编辑入口互相覆盖。冲突时保留草稿并停止依赖该保存的操作。网络断开或 AI 持有编辑锁时说明状态，不能显示为已保存。

正文与字幕的未提交规范文稿使用浏览器 IndexedDB strict 事务备份，按工作区、文稿 UUID、来源版本和独立窗口 owner 隔离。事务完成前只显示备份进行中；读取失败与当前写入失败分别反馈。重新打开时先展示候选，由作者明确恢复或丢弃所选快照；恢复先确认新分支备份成功，不自动写入或合并服务器。旧 sessionStorage 副本只在 strict 迁入成功后删除。已完成事务的浏览器进程崩溃恢复已在 Chromium 实测；未完成事务、操作系统尚未提交的输入法预编辑及用户清站点数据不在保证范围。制作参数与录音 Blob 不在本片。实证与多窗口传输限制见[持久草稿记录](benchmarks/document-durable-drafts-2026-10-27.md)。

草稿按工作区、文稿、来源和锚点隔离，可本地恢复，但只作为未提交编辑状态。唯一可编辑文稿是 `lecture.json`；定义代码、素材和录制文件通过明确引用参与工程事务，派生运行快照不成为另一种文稿入口。BlockNote JSON、素材面板、时间线布局和字幕面板都不成为第二份文稿。

自动保存、生成结果采用、页面操作和 AI 修改沿用既有版本、冲突、审阅、撤消与恢复流程。输入框内撤消由编辑器处理；焦点离开输入框后，工具栏撤消作用于文稿版本。保存失败和外部变更不丢草稿，不自动覆盖新源文件。

### 6.3 状态与诊断

| 状态 | 表达与恢复 |
|---|---|
| 保存 | 已保存、保存中、本地草稿、冲突或失败；按受影响目标显示 |
| 编译 | 待更新、编译中、预览就绪或失败；标识正在显示的源修订 |
| 配音 | 待生成、生成中、可播放、过期或失败；显示实际或估算时长 |
| 导出 | 排队、运行、完成、失败或取消；标识产物所用修订 |
| 材料与生成 | 待处理、分析中、生成中、待审阅、已采用、已过期、部分失败、取消中或已取消；保留来源和任务范围 |

常态用紧凑状态图标，异常显示简短原因并可展开详情。“已保存”仅说明内容已写入权威来源，不代表编译、配音和导出已完成。后台旧任务的结果不能覆盖更新后的预览或配音状态。

编译期间继续编辑使准备版本失效时，沿用待更新状态和显式重新编译入口，不重复显示编译错误；真实编译、网络或服务失败仍保留可读诊断。

编译失败保留上次成功预览，清楚标识其版本；尚无成功预览时显示可恢复的空状态。语音引擎缺失等可预期失败不能使整个画布空白。预览中的静音占位明确提示，不伪装成正常音频。

诊断按块、步骤和任务定位。详情可复制错误、来源、修订、任务 ID 与相关日志；运行时错误、资源加载失败和语音失败均进入既有诊断快照，前端与 agent 可读到同一问题。日志不展示凭据。原始堆栈不常驻正文画布。

文稿技术验证包括 JSON、`schemaVersion`、唯一实体 ID、归属、步骤、组件、资源和讲稿引用；编译后另验证 `IR_VERSION`、媒介映射、动画时长与播放绑定。VS Code 展示文件诊断与预览版本，Web 转换成对应内容的问题。验证失败保留上次成功预览，明确导出是否可用；不把解析成功等同于可渲染，也不把旧预览等同于当前修改。

取消运行中的生成、配音或导出任务需确认；确认后显示“取消中”，服务端确认终止或完成可停止阶段前不能显示“已取消”。不能立即中断的阶段说明将等待当前阶段结束。取消失败保持实际任务状态并可重试；确认取消后的晚到结果不自动采用，已完成的有效结果继续保留为记录。

### 6.4 批注、助手与历史

批注保留选中文本、稳定实体与偏移、内容、时间和处理状态，保存到同一规范文稿的 `comments`；未提交输入按工作区与文稿隔离恢复。批注可逐条或批量发送给 AI，发送入口使用助手图标和未发送数量角标，完整动作在工具提示和菜单中说明；也可解决、重新打开或删除。未发送批注的编号和选区标记不进入产物。

助手请求先绑定当前文稿与焦点，再交给既有会话。打开助手、切换会话或定位关联内容不改变未提交草稿。AI 修改沿用审阅流程，接受或拒绝时保持作者位置；编译显示对应版本后，仅短暂标记受影响内容块。历史面板保留每次修改的来源、时间、撤消和恢复状态，查看旧版本不静默覆盖当前文稿。

### 6.5 已固定交互决策

[interactions.json](prototypes/workbench/interactions.json) 的 I01–I12 与 Figma 第 03 页逐项记录触发、行为、可见状态、异常和撤消路径，覆盖本节保存与任务规则，以及第 4、5 节页面、引用、编排、配音、字幕和剪辑默认值。这些是已固定的设计决策，不能把原型状态视为产品能力。规范文稿、步骤、时机、音色与本地音频的当前范围见第 10.1 节；实际语音服务、视频文件、录制采用和字幕重新对齐仍须分别验证。

桌面属性面板默认使用设计系统的 compact 密度，互斥选项横向排列，入点／出点成对，时间、语速、音量使用短数值输入，不铺满面板宽度。尺寸、字号、触屏热区和输入字号均以 [设计系统](design-system.md) 为唯一取值来源。核心规则发生变化时，同步更新 Figma、交互 JSON 与本 RFC，再开展实现，不能只改其中一份。

## 7. 放映与演讲者视图

### 7.1 观众画面

点击放映进入最终页面画面，隐藏页面栏、BlockNote、素材、时间线、属性和 AI 面板。工作台不显示独立的顶部版本／编译／退出工具栏；重新编译与退出均在底部统一控制栏，退出先暂停并同步位置后恢复原文档编辑器。已观察到的新修订尚未确认时，画面、字幕和插件交互关闭，原底栏仍保留可用的重新编译与退出；其余播放和导航控件禁用，不新增第二条工具栏。工作台不在预览下方另加“页面步骤”栏；翻页由放映画面的前后按钮和键盘处理；不提供“跳转步骤”菜单。画面底部使用小图标提供播放／暂停、上一步、下一步、步骤总览、字幕、演讲者视图、全屏和退出；播放与导航合并为同一控制栏，播放／暂停和字幕使用图标，播放、时间码、进度条与常用菜单全部在同一横排，进度条有明确的已播／未播区分，不另占上沿或第二行；倍速、字幕语言、字幕列表与章节收进更多播放选项，不再单独显示第二条播放器栏。回放控件不显示 AI 音色来源徽标，导出来源标记保留。底栏不重复幻灯片页脚已有的页码和步号；窄屏将前后翻页移入更多菜单，保持常用控件横排。

控件保留明确布局空间。字幕悬浮在幻灯片画布内的底部安全区，避让页脚；字幕出现、消失和换行不改变画面的大小与位置，不能在画面下方插入或移除独立字幕框。在所有步骤中都不显示的内容块不占放映布局空间；仍需缩小的内容在画布内水平居中。动画在放映中使用可用宽度，场景尺寸按变换前的 CSS 布局像素计算，不能将屏幕缩放再次写入动画内部坐标。按文稿比例将整张页面缩放到剩余画布，长正文与列表参与完整排版；无法在允许字号内容纳时给出溢出诊断与拆页入口，禁止只保留最后一行或让顶部越过边界。观众端不加载块编辑器和作者属性。

进入放映只准备现有播放数据，不自动播放、不自动合成。手动推进与自动播放共享当前位置。播放过程中手动跳步或操作互动内容时先暂停；继续播放从当前明确的位置开始。无需“我来试试／回到讲授”第二套模式。只有阅读场景需要完整文字时，提供只读字幕列表，列表不挂载编辑、转写或合成工具。

### 7.2 作者演练

从工作台放映时，讲稿图标可以暂停播放并展开当前步骤属性。该面板只显示在作者所在工作台，不进入观众窗口、静态产物或导出视频。修改后留在同一页和步骤，按第 6 节处理播放位置和配音过期状态；收起面板后由作者点击继续。

演讲者视图提供当前页、下一页、当前步骤讲稿、计时和播放控制。观众窗口仅同步画面、步骤、字幕与播放状态，不接收草稿、AI 对话或编辑控件。退出放映恢复原工作区、面板开合和有效位置，音频和订阅按需暂停或释放，不能叠加第二个播放器。

### 7.3 快捷键

| 范围 | 快捷键 | 操作 |
|---|---|---|
| 编辑器外 | `Mod+Z` / `Mod+Shift+Z`，Windows 兼容 `Ctrl+Y` | 文稿撤消／恢复 |
| 放映，输入框外 | `←` / `→` | 上一步／下一步 |
| 放映，输入框外 | `Space` | 播放／暂停 |
| 放映，输入框外 | `O` | 总览 |
| 放映，输入框外 | `Shift+F` | 全屏；`f` 继续保留给讲台冻结画面 |
| 浮层或放映 | `Esc` | 先关闭最上层表单或面板，再退出放映 |

快捷键不抢占文本输入、输入法、编辑器和交互组件已有按键。触屏用户通过图标、菜单和步骤列表可完成同样操作。

## 8. 导出与输出一致性

导出图标打开格式面板。常用格式以图标、格式名和简短用途显示，例如视频、PDF、PowerPoint、网页；实际可用项来自渲染端和插件，不硬编码当前文稿不支持的输出。高级格式放在展开区域，不能把导出器列表铺成常驻工具栏。

放映和视频消费同一讲授计划、步骤映射、字幕与动画时长。点击导出前，明确使用的已保存修订；有待审阅结果、外部未保存修改或失败编译时说明尚未包含的内容。请求经既有 jobs 流程执行；目标、范围、配置与修订一致时可复用排队、运行或成功任务，失败或取消后的显式重试使用新的任务身份。讲授视频导出把请求的精确 source 交给导出器，导出器重新编译后版本不同就拒绝（排队期间保存文稿时提示“已保存文稿发生变化，请重新导出”），不再把新版本的画面标成旧版本的产物，见[导出源版本记录](benchmarks/export-source-binding-2026-10-28.md)。展示真实进度、取消、失败原因和日志，未知进度不伪造百分比；完成后可以预览、打开或下载。

配置了配音的视频导出要求对应语音片段齐全且有效。缺失或过期时定位到受影响步骤并提供生成入口，不输出看似成功但缺音频的视频。作者可显式选择无配音输出，此时说明字幕和时间的处理方式。对外发布与学生版本继续沿用受众筛选，作者讲稿和工具不得因面板隐藏而误入产物。

## 9. 视觉、窄屏与可访问性

控件外观、默认尺寸、状态、字体、素材、图标、焦点、触屏热区及 Figma 第 02 页与代码的映射统一由 [控件与视觉实现规范](design-system.md) 定义，本 RFC 不另维护一套样式取值。低保真线框只用于功能对齐，不能作为正式控件的视觉验收；新增能力先在公共组件与 Figma 变体中补齐，业务 CSS 仅负责布局，触及的遗留控件样式按规范迁移。

桌面允许拖动分栏；断点、画布最小可用宽度和面板收起顺序遵循视觉规范。中等宽度将属性改为抽屉；窄屏单主区域显示，页面目录与属性按需展开，编排画面与时间线纵向排列。切换不丢草稿；不为了保留三栏而把画面缩成无法阅读的缩略图。时间线可滚动查看时间范围，步骤列表始终提供完整跳转。

图标优先同样适用于桌面，具体操作与可访问名称见第 3.2 节。布局不能削弱视觉规范要求的可发现性、有效热区、键盘操作、状态对比或减少动态效果支持。浅色／深色与桌面／窄屏都需实际查看，不能仅凭线框中存在控件判定完成。

界面文案按包维护 zh-CN 与 en，工具提示和读屏名称也须完整。工作台语言跟随 dsh，产物语言跟随文稿 `lang`，不改变原有规则。

## 10. 实现边界与取舍

| 边界 | 复用内容 | 本轮要求 |
|---|---|---|
| design / 通用组件 | `PmIconButton`、Radix、令牌、Lucide 语义图标 | 完善提示、选中态、热区和图标覆盖 |
| workbench | `DocumentEditor`、`DocumentStepNarration`、版本和诊断状态 | 文档、编译放映与视频各自保留选择和草稿，按明确来源与版本交换内容；普通作者不进入实现代码 |
| viewer / 预览协议 | 派生运行快照、`go`、`position`、`trail`、稳定步骤与块锚点 | 保持同一查看器实例，按步骤和素材定位；移除普通 Web 的源码编辑路径 |
| workspace | `document`、`document/change`、工程文件事务、`ir/events`、history、review、jobs | 保存顺序、冲突、最新修订与编译任务反馈 |
| addon-lecture / speech | 讲授计划、`LectureTrack`、`MediaClock`、合成缓存 | 音色、作用域、时序、字幕与合成状态；合成由显式操作触发 |
| dsh | 槽位、会话、助手、确认、设置 | 材料分析、生成任务和批注修改的可见进度及审阅，不承担第二份文稿 |
| VS Code | 规范 JSON 与代码的原生编辑、schema、实体定位和编译预览 | 插件保持预览／诊断／导出范围；实际窗口体验单独验收 |
| Tauri | 未来桌面宿主 | 复用 Web 界面和业务，适配本地能力，不另存项目模型 |

文档内讲稿、辅助面板和视频制作复用 `DocumentStepNarration` 和原生 `NarrationEditor`，只修改同一规范文稿；发布播放器的 `TranscriptList` 保持只读。视频制作具有独立的步骤、讲稿、音色、基础三轨时间线与本地音频片段入口；字幕逐词对齐、物理麦克风验收和视频文件仍需按真实服务能力实施。预览协议 v1 的制作请求显式携带 request 和来源绑定，不能把任意文件读写或组件私有状态塞进消息。

当前实现缺口包括：完整的材料处理与生成审阅状态、独立素材实现闭包与版本管理，以及视频文件、字幕逐词对齐和跨步骤分配。组件已有公开参数与既有 Definition 选择入口，实际范围见下表；这不等于任意生成素材都已具备编辑或复制能力。规范 JSON 的读入与安全写回、稳定步骤身份、页面复制与拖动排序、基础三轨播放头及本地音频作者链路已有实现。现有音色目录与参数契约不代表所有服务已经通过合成验证；现有讲授轨也不代表任意媒体剪辑工程已经成立。Tauri 宿主仍需适配，VS Code 仍需真实窗口体验验收。原型中的页面和状态仅确定产品需求。

| 备选方案 | 取舍 |
|---|---|
| 保持现有布局，仅替换文案和按钮 | 无法解决多套入口、不同文本保存目标和步骤选择脱节，放弃 |
| 同屏常驻文档、源码、时间线、属性和 AI | 暴露实现细节且压缩普通作者空间，Web 只呈现任务相关工具 |
| 以完整视频剪辑工程作为事实来源 | 与规范文稿的步骤、讲稿和制作设置重复持久化，保留派生时间线 |
| 改成只编辑源码、整份文稿离线编译 | 失去普通作者的块编辑和逐步骤调试，保留编译式预览与局部编辑 |
| 再换前端框架 | 无法直接修复交互与数据边界，继续 React 体系 |

成本集中在统一选择与草稿、材料到内容的任务闭环、讲授计划可视化、音色与媒体能力，以及同一规范文稿在各宿主中的适配。任意跨页多轨剪辑、任意切断程序动画和多个独立时间线工程仍在首期范围之外。稳定步骤身份与可编辑 JSON 文稿入口已经建立；制作面板继续消费同一文稿及派生播放计划。

| 工程入口 | 规范 JSON 加工程代码文件；Web 与 agent 进入同一校验及原子提交边界；VS Code 使用原生 JSON 编辑、公共 schema、实体导航与编译预览 | Tauri 宿主，以及真实 VS Code 窗口体验验证 |

未配置音色的项目仍按现有讲授契约判断播放能力，不创建虚构音色。`rate`、`style` 字段存在不等于服务支持所有值；现有音色目录不代表任意音色、参数或试听都可用；媒体裁切、字幕对齐和输出格式也按真实能力接入。

正文原生撤消使用会话内的结构历史恢复被删除的教学绑定；旁路讲稿和制作设置以最新规范文稿为准，不因正文撤消覆盖后来的输入。仅新增素材或修改媒体片段、其余规范内容与既有素材不变时保留原生历史；其他外部文稿替换使用明确的编辑器重置边界，见[真实验证](benchmarks/document-media-history-2026-10-27.md)。浏览器合成的 `composition` 事件用于验证保存屏障，不能代替操作系统输入法和组字中途卸载的实际验证。原 ProseMirror View 1.42.7 的[系统断词失败](benchmarks/document-os-ime-2026-10-27.md)保留；本仓库固定 1.42.6 后，真实正文与字幕输入、600 ms 保存等待及原生撤消／重做验证 13/13，详见上表回归记录。该结果只覆盖已测的 Linux/X11/IBus/Chromium 配置与词语，不代替其它环境、组词中途卸载或外部安装验收。

人声转写再配音按[录制转写设计](rfc-recording-transcription.md)分片实施：原音频、转写候选、讲稿采用与新配音分别记录来源和结果。Web 与 agent 的作者操作、任务跟踪、客户端应答和读后验证按[MCP 作者动作设计](rfc-mcp-authoring-actions.md)对齐。两份设计中的待实施接口不代表当前可用；录制和高级采用流程放在视频制作，文档仍只显示字幕与配音开始。

## 11. 实施顺序与验收

功能进入实现前必须在 [原型覆盖说明](prototypes/workbench/README.md) 中对应页面或状态，并在 [Figma 文件](https://www.figma.com/design/CjQ5JFn3PuGXx0NgwYrCR8) 中可找到。一个原型可以覆盖相关参数和状态，但不能只用一张主界面示意全部功能。关键入口、输入、结果、失败恢复和返回路径都需可辨认；首期未支持的动作明确标识，不提供看似可用的空跳转。

Figma 功能原型采用低保真方块、文字、图标和页面跳转；其中的播放、试听、剪辑和导出示意不调用真实服务。运行界面的实施范围见第 10.1 节，完整流程仍按下表验收。

| 阶段 | 交付范围 | 结束条件 |
|---|---|---|
| A：文档编辑，当前优先 | 新建文稿与页面、正文结构与格式、块操作、批注、原生撤消、保存、重载和草稿恢复 | 连续真实操作可完成，结构和源码一致，无意外跳转、丢字或跨文稿草稿污染；四种显示组合通过 |
| B：编译放映 | 明确版本的编译、预览、定位、失败恢复与观众放映 | 编译结果与所选保存版本一致，编辑不被预览状态打断 |
| C：视频制作 | 页面时间线、讲稿、音色作用域、字幕、录制、基础剪辑与视频导出 | 时序、配音版本和字幕一致，取消和局部失败可恢复，独立于文档编辑 |
| E：技术与桌面入口 | 同一规范 JSON 项目、VS Code 原生编辑与预览导出、Tauri 宿主适配 | 权威输入唯一，验证失败保留有效结果，Web 与桌面共用业务 |

以下是实施后的验收要求，不是本次文档修改已通过的验证。每个行为安排一到两个真实服务或浏览器场景，以专用小文稿检查。日常不新建测试、不运行测试套件；已有集成测试仅在作者明确要求时定向运行，默认单 worker，不自动扩大范围。验证约定以仓库根目录 `AGENTS.md` 为准。

| 验收场景 | 必须观察到的结果 |
|---|---|
| 页面与块 | 页级加号创建独立页面，块加号仍在本页；纯文字、混合页均可编辑、撤消和放映 |
| 正文和讲稿 | 输入多段正文后全部出现在页面；讲稿只在步骤属性编辑，不自动复制正文 |
| 材料与生成 | 批量材料逐项处理，来源可查；任务可暂停、取消和局部重试，方案与成稿可审阅 |
| 对话与批注 | 修改范围明确，局部或批量批注定位正确；接受、拒绝和继续修改都保留当前内容及草稿 |
| 生成块 | Web 用公开参数、对话或批注修改，不暴露实现代码；共享素材有提示，失败保留原版和上次画面 |
| 完整步骤 | 首末步骤、后四步、跨页及随机倒序均显示相应画面；完整与过滤媒介步号一致 |
| 时序 | 同步与动画结束后两模式改变实际配音起点；暂停、定位和视频导出使用同一计划 |
| 草稿和更新 | 旧目标保存响应不改写新目标；断网、AI 锁、外部编辑、撤消和编译重载后可恢复正确草稿 |
| 配音来源 | 打开和跳步不触发合成；缺失引擎只影响配音；录音转写不能静默覆盖源码讲稿 |
| 音色与参数 | 音色可试听并按明确范围应用，继承和覆盖可见；不支持的参数不伪装成通用能力 |
| 基础剪辑 | 可精确调整停留、停顿、媒体入出点和音量；保持原素材，字幕失配有提示，程序动画不被任意切断 |
| 字幕 | 开关、语言、样式、位置、安全区与导出方式可辨认，文字保持来源，缺少对齐或译文过期有状态 |
| 放映 | 没有作者侧栏或大文字工具条，正文无裁切；作者展开讲稿时观众屏不显示编辑器 |
| 返回与播放 | 工作区切换、讲稿更新和退出放映遵循第 6 节，只有一个有效音频时钟和当前位置 |
| 任务和诊断 | 旧修订不覆盖新结果；导出失败可定位，前端错误和后端原因进入同一诊断来源 |
| 图标和语言 | 图标可聚焦并有中英文名称，快捷键不抢输入，触屏无需悬停也可操作 |
| 显示组合 | 浅色／深色 × 桌面／768 px 以下均可操作，至少覆盖 390 px，内容、热区与浮层不裁切 |
| 单一文稿与多宿主 | Web、agent、VS Code 和桌面宿主修改同一规范 JSON 文稿与引用文件，不维护 MyST 或运行快照写入入口；不编辑 `dist/ir.json` 充当源文件 |
| VS Code 与 Tauri | VS Code 插件只提供预览、诊断和导出；Tauri 复用 Web 业务，不建立独立文稿或剪辑模型 |

实现完成的判断以真实工作台为准。交互草图、DOM 存在、缓存命中或结构检查通过均不能单独替代上述验收。
