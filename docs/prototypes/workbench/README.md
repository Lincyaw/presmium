# 工作台功能原型

这份原型用于逐功能对齐 Presmium 的作者工作台需求，覆盖 30 个功能单元、8 个失败恢复状态和 2 个窄屏变体。所有界面均为待实现的设计，不代表产品已经具备对应能力。审阅时可以用页面编号、状态编号和具体动作描述需要调整的位置。

运行代码的实施范围见 [RFC 第 10.1 节](../../rfc-workbench-uiux.md#101-当前实施状态)。P09 已接入新建、重命名与同一来源内的同级页面移动；复制、删除、跨层级和多来源重排仍需完成身份与引用保护，不开放原型中的对应动作。

从 [Figma 功能索引][P00]开始，或直接[播放原型](https://www.figma.com/proto/CjQ5JFn3PuGXx0NgwYrCR8?node-id=9-2&starting-point-node-id=9%3A2)。[完整 Figma 文件](https://www.figma.com/design/CjQ5JFn3PuGXx0NgwYrCR8)可查看各单元的可编辑图层和跳转关系。

## 原型与视觉规范的边界

功能线框用于确定区域、对象、动作、范围和状态，不是视觉定稿，也不表示全部高保真界面已经完成。按钮、输入框、时间线和预览在这里由方块、图标与文字说明组成；点击仅跳转到关联画板或展示控件语义，不实际上传、调研、生成、配音、录音、保存、剪辑或导出。

正式按钮、输入、选中态、禁用态、焦点、间距和图标规范见[设计系统](../../design-system.md)与 [Figma 第 02 页](https://www.figma.com/design/CjQ5JFn3PuGXx0NgwYrCR8?node-id=25-144)。实现前应先使用统一控件规范与设计资产，再组合页面；不得把线框的临时尺寸和颜色逐页写成样式，也不得在页面内另造按钮、输入框或图标。功能语义和状态规则见 [UI/UX RFC](../../rfc-workbench-uiux.md)。三者出现冲突时，应先修正规范和原型，再开始对应实现。

正式控件页包含 regular 87 个基础变体、compact 69 个变体、触屏输入 27 个变体，并提供横排 Timing、StatusChip 和 Menu、Tabs、Tooltip、Range、Dialog 示例。明暗色共用语义变量，输入采用清晰的 1px 中性边界和独立焦点。可直接对照[桌面 compact 浅色](https://www.figma.com/design/CjQ5JFn3PuGXx0NgwYrCR8?node-id=25-178)、[桌面 compact 深色](https://www.figma.com/design/CjQ5JFn3PuGXx0NgwYrCR8?node-id=25-268)、[触屏浅色](https://www.figma.com/design/CjQ5JFn3PuGXx0NgwYrCR8?node-id=25-358)和[触屏深色](https://www.figma.com/design/CjQ5JFn3PuGXx0NgwYrCR8?node-id=25-441)。这些是视觉与状态规范；公共 React 控件迁移、复杂选择弹层和完整交互仍按设计系统缺口表实施，不能把 Figma 变体数量当作已实现功能。

线框中的声音名称、服务提供方、素材、进度与时间均是流程示例。音色名称和提供方不代表已接入服务的真实音色目录；语速和朗读风格只在实际服务声明支持时提供。原型里的“试听”不会调用语音服务。

## 第 03 页：已固定交互决策

[Figma 第 03 页：交互状态总览](https://www.figma.com/design/CjQ5JFn3PuGXx0NgwYrCR8?node-id=40-4645)通过 I01–I12 共 12 块画板、30 个状态，展开触发、默认行为、可见状态、异常与撤消路径；也可[播放状态导航](https://www.figma.com/proto/CjQ5JFn3PuGXx0NgwYrCR8?node-id=40-4645&starting-point-node-id=40%3A4645)。对应数据为 [interactions.json](interactions.json)，规则说明见 [RFC 第 6.5 节](../../rfc-workbench-uiux.md#65-已固定交互决策)。它们覆盖保存、任务取消与过期结果、原子审阅、页面及引用保护，以及步骤、音色、试听、字幕和基础剪辑的默认关系。状态板是实施前约束，不是已经完成的产品功能或可实际执行的操作。

桌面属性区默认采用正式设计系统的 compact 密度：互斥选项横排、起止时间成对、数值输入保持紧凑；触屏热区和输入字号仍遵循同一[设计系统](../../design-system.md)，不从线框临时取值。核心交互或样式变化须先同步 Figma、相应 JSON 与 RFC／视觉规范，再进入实现；不能只改页面或只更新一份文档。

通用确认框还可对照[浅色](https://www.figma.com/design/CjQ5JFn3PuGXx0NgwYrCR8?node-id=48-502)和[深色](https://www.figma.com/design/CjQ5JFn3PuGXx0NgwYrCR8?node-id=48-551)示例：复用同一 Dialog，保留已完成结果，确认后等待服务停止。六个明暗阴影样式、组件数量和全部画板链接均登记在节点清单中。

| [S08 当前步骤画面加载失败][S08] | 从 [P17][P17] 的状态图标进入。 | 第 2 页第 4 步暂时无法显示。 保留其他可用画面，重试或通过对话修复此步骤。 处理问题 → [P12][P12]；返回当前工作区 → [P17][P17] |

## 窄屏与客户端边界

| 原型 | 需要对齐的行为 |
|---|---|
| [M01 内容编辑窄屏][M01] | 页面目录与辅助面板按需打开，正文保持可编辑；选择、草稿与返回位置不因收起面板丢失 |
| [M02 编排配音窄屏][M02] | 画面、时间线纵向组织，步骤属性按需展开；全部步骤与讲稿、音色入口仍可到达 |

Web 面向不懂技术的作者，只显示内容、素材、编排、任务与结果。Agent 可以在后台调研、分析和生成代码素材，Web 不展示代码、IR、工程路径或工具调用细节；来源依据与可理解的任务状态仍然可见。

Tauri 后续复用 Web 的创作界面和操作，不另建一套编辑流程。P29 包含本地素材与离线状态变体：已有本地内容可以继续编辑或预览，依赖联网的生成任务明确等待连接；具体可离线范围需实现时验证。

[VS Code 技术入口][P30]使用 VS Code 原生编辑器修改工程文件，插件承担预览、诊断定位和导出。原始 IR 编辑入口属于待实现设计；本原型不承诺 MyST 与手改 IR 可相互无损写回，也不把浏览器中的持久化模型改为另一套格式。

## 配音与基础剪辑的对齐点

- [P19][P19]与[P20][P20]区分音色选择、试听、项目默认继承和步骤独立覆盖；批量应用前必须说明影响范围及是否保留已有覆盖。
- [P21][P21]显式生成配音。讲稿变化后字幕更新，过期音频不能与新字幕混用；缺失音频的预览使用明确的静音占位。
- [P22][P22]分别设计静态画面停留、节目停顿、导入音视频的入出点和音量／静音。裁切保留原素材；生成动画按步骤调整，不用剪刀图标暗示可以任意剪断程序动画。
- [P23][P23]把录音转写与作者讲稿分开；“采用为讲稿”需要明确目标和差异，不能自动覆盖已有内容。
- [P27][P27]与[P28][P28]保持放映和导出使用同一有效版本、步骤和时序；缺失配音时可定位修复，或明确选择无配音输出。

## 如何记录需求反馈

反馈至少包含原型编号、所选对象和期望行为，例如“P20，应用到本页时，应保留其他页面的步骤覆盖”。涉及失败恢复时同时给出 S 编号；涉及窄屏时给出 M 编号。不要把线框中的配色或尺寸直接作为页面实现指令，视觉修改应回到统一控件规范。

| [interactions.json](interactions.json) | I01–I12 已固定交互决策及其触发、状态、恢复与撤消路径 |
| [figma-nodes.json](figma-nodes.json) | Figma 文件、原型播放入口与全部节点链接 |
