# 从文件到 LSM 的教师课程验收

用户指出旧体验仍以字典为核心，缺少可持续演进的数据库机制与真实性能测评。此次保留旧文稿，新增独立的八单元存储引擎课程：源稿在 `e2e/fixtures/database-course/`，可编辑、可运行的独立 Git 工作区在 `.presmium/database-course-experience/`。公开示例仍为 CS336。

## 课程交付

| 单元 | 真实实现 | 教师与学生的验收 |
| --- | --- | --- |
| 文件快照 | 临时文件写入、JSON 快照、原子替换 | 两个独立 Python 进程写入与读取，文件保留在 lab-data |
| 追加日志 | 长度、CRC32、JSON 批次、版本与删除 | 查看实际帧、覆盖版本与损坏证据 |
| 偏移索引 | key 到帧偏移和批次内序号 | 相同文件、相同查询轨迹，值仍从文件读出 |
| 持久提交 | none/fsync 策略、单帧原子批次 | 转账边界、1 与 32 条操作的提交粒度 |
| 恢复 | 不完整尾帧截断、完整坏帧拒绝 | 独立子进程异常退出、截断、CRC 损坏、删除不复活 |
| LSM | WAL、有限 memtable、排序 SSTable、稀疏索引、manifest | flush 前后故障与重开、文件集合的发布顺序 |
| 过滤与压缩 | Bloom、流式有序归并、墓碑、全量压缩 | 命中/未命中、范围查询、空间回收与维护成本 |
| 性能实验 | 固定随机轨迹、预热、多轮、SQLite 对照 | 原始样本、环境、源码哈希、反例及解释 |

`teacher-guide.md` 按单元提供时间安排、预测问题、逐步编码、真实文件命令、故障分析和提交证据。每单元 60–90 分钟含学生实现与实验，不把讲义阅读时间等同于授课时长。实现和 benchmark 仅依赖 Python 3.9+ 标准库。

网页、幻灯片、notebook 消费同一源稿。源码引用读实际实现，不复制一份漂移代码。浏览器参数面板确实写入虚拟文件并重新读取，用来演示应用字节量；正式磁盘性能只来自本机 Python。notebook 导入相同引擎并保存实际文件。恢复练习保留失败起始代码，学生修正后运行四项断言。

## 实测结果

本次运行耗时 279.1 秒；Apple M5、24 GiB、Python 3.9.6、SQLite 3.54.0、macOS 27.0.1、seed=3362026。40 种组合各一轮预热与五轮测量，共 200 个计入统计的轮次、82,790 个计入统计的事务延迟样本；含预热的原始样本为 99,348 个。相同 case 在不同实现中共用数据和轨迹，所有结果被消费并校验。源码四份 SHA-256 在测量前后相同。

| 对照 | 条件 | 中位吞吐比 |
| --- | --- | --- |
| JSON 全量重写到追加日志 | N=1500，none，单条写 | 141.69× |
| 顺序扫描到偏移索引 | N=4096，none，命中点查 | 3248.34× |
| 每条同步到每 32 条同步 | fsync，相同逻辑写操作 | 9.95× |
| Bloom 关闭到开启 | N=1500，none，未命中点查 | 33.73× |
| SQLite 到教学偏移索引 | N=4096，none，命中点查 | 0.56×，教学实现更慢 |

没有驱逐 OS 页缓存，不能外推冷盘或大于内存的数据；一次批次延迟包含整批事务，吞吐比不代表每个请求等待减少相同比例。范围读取不使用 Bloom，两组约 0.978 的吞吐比只能作为观测扰动，不能归因于 Bloom 的范围优化。

压缩包含 fsync 发布，维护耗时单列。索引文件从 977,160 到 193,512 bytes，正常重开从 44.56 到 8.35 ms，压缩耗时 24.49 ms；LSM 从 1,237,566 到 250,219 bytes，正常重开从 2.80 到 0.32 ms，压缩耗时 75.10 ms。LSM 测量前已 flush，WAL 为空，不能把这个重开时间说成长 WAL 崩溃恢复。

完整报告、原始 JSON、轮次 CSV、逐事务延迟 CSV 与来源哈希在课程 `results/`。`prepare_course.py` 先核对测量轮数及源码哈希，再派生讲义表格。修改引擎后必须重测。

## 正确性与审阅

`verify.py` 的 14 组和 `verify_lsm.py` 的 13 组真实文件验证通过；覆盖独立解释器、异常退出、代表性半帧截断、完整坏帧、墓碑与压缩，以及 flush/compact 在 manifest 发布前后的四个进程故障点。六个现场 demos 已使用独立进程与真实文件运行。

独立审阅在正式测量前发现并修复四个问题：none 策略下显式压缩缺少同步、manifest 缺失时误初始化并可能丢旧表、WAL 缺失时静默重建，以及 SST 数据在合法记录边界截短时缺少长度核对。正式 benchmark 已使用修复后的源码，测试与哈希检查均匹配。

仅承诺单进程单写者教学引擎，没有 SQL 解析、B+ 树、MVCC、多写者锁或隔离；进程异常退出验证不等于实际断电验证。ordinary fsync 的保证还受 OS、文件系统与设备影响。

三媒介构建通过，0 errors、0 warnings；构建保留一项关于 Slidev 导出应使用 presmium-export 的信息提示。技能检查与 diff 空白检查通过。浏览器与 notebook 的最终定向结果见本记录末尾；没有运行完整 pnpm test、verify、e2e 或全课程 demo。

## 本轮验收方式的调整

前一轮把可交互的小示例当成了完整教学案例。用户要求的是逐步构建真实存储、解释机制并测出收益，旧稿没有持久化链路的连续实现和可复算 benchmark。

复核了三种解释：用户只要演示界面、只需要增加一段文件代码、需要系统性数据库课程。前两种均被“真实存文件、逐步加各种机制、benchmark 到底提升多少”的反馈排除。因此本轮把跨进程文件、故障边界、同轨迹多轮采样和负结果作为交付验收，而不再以组件数量或按钮可点击代替课程深度。

投影验证还发现索引源码与三条实验要点挤在一页，超出屏幕。课程随后将快照、索引、恢复各自拆成原理/实现/实验步骤，封面详细课程表留在阅读版，manifest 源码与下一页 flush 实现分开；长讲解仍保留为备注。

## 最终定向结果

`e2e/database-course.spec.ts` 的构建/原生文件/notebook 用例已通过：源码锚点逐字对照真实文件，正式结果的 40 组、五轮、同轨迹与哈希一致，两个解释器共享实际快照，导出的 notebook 用本机 Python 执行选定单元并产生 manifest 和数据文件。

最后一次浏览器定向运行 1/1 通过（41.1 秒），只构建本课程三种媒介。八个单元的导航、四处关键源码、按实测数据计算的比值、完整报告的环境与哈希、参数从 100 到 200 的真实文件工作量、恢复练习从三个失败到 4/4 均通过。13 张风险投影页按上/下/左/右边界与页脚上缘检查，通过且目视代码尾行完整；页面运行错误为 0。课程封面通过 Slidev 公开 `wakeLock: false` 配置避免嵌入或无权限环境自动申请屏幕唤醒锁，未过滤异常。
