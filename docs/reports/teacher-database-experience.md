# 教师动态代码教学体验核对

本记录核对教师从零编写 Python 键值数据库的教学路径。私有文稿在 `e2e/fixtures/teacher-database/`，定向集成用例在 `e2e/teacher-database.spec.ts`。Studio 面向非技术教师的简单交互，专业代码编辑使用 VS Code 插件；此场景重点检查讲解、演示与 agent 能否取得足够的环境反馈，工作台整体操作由同次体验的其他记录补充。

## 教学场景

文稿从空字典的 `put`、`get` 开始，改为追加日志，再讲更新、删除标记、文件写入和重启恢复，最后让学生补全倒序查询。封面与 10 个章节都使用稳定标签，讲解段落同时充当讲者备注。代码只依赖 Python 标准库，编译时与浏览器中都能执行。

| 教师要做的事 | 文稿中的用法 | 核对方式 |
|---|---|---|
| 从真实源文件讲状态、写入和读取 | `code-ref` 引用嵌套区域，`steps` 依次高亮 | 检查真实 CLI 的锚点和构建输出 |
| 比较覆盖写与追加写 | `at`、`until` 原位替换两份实现 | 网页放映中前进、后退，检查实际可见代码 |
| 定义一次，后续继续操作数据库 | 引用代码和后续代码共用 `teacher-db` 会话 | 编译输出与浏览器实际顺序运行 |
| 先让学生预测最新值与日志长度 | `predict` 将答案和执行结果放到下一步 | 先保存选项，再运行并核对 `15 4` |
| 解释倒序扫描遇到最新值后立即返回 | 独立 `step-run` 查询，共 7 个执行步骤 | 幻灯片推进到打印，再回退一步，输出恢复为空 |
| 修改数据量，观察磁盘恢复结果 | `run-panel` 的 `updates` 参数；实际写入临时 JSONL 文件并重新打开 | 浏览器将 3 改为 5，核对历史记录数和恢复值 |
| 让学生补全函数并得到反馈 | `exercise` 覆盖最新值、缺失值、删除标记 | 先提交起始代码，再修正，核对 3 项校验通过 |
| 给学生可复做的材料 | 同源构建网页、幻灯片和 Python notebook | 检查 notebook 的源代码、参数赋值、录制输出和折叠答案 |
| 收集课堂中的理解情况 | 多选测验、问题框和理解度反馈 | 文稿可构建；多人课堂流程需连接课堂服务另行核对 |

测试先把文稿复制到独立 Git 仓库，引用 `code/database.py`。这一点保证教师编辑副本中的代码时，预览读取的也是副本，不会悄悄读取原仓库中的代码。此次代码演进使用可逆步骤，没有为演示额外制造提交历史。

## 教师需要知道的状态规则

浏览器中的共享会话需要按顺序运行。编译时录制的输出表示备课时的结果；它不会替学生初始化浏览器解释器。重置会话后要从初始化块重新开始。预测页再次运行会追加一条记录，日志长度随之增长，文稿明确说明了这一点。

逐行查询使用独立的 `lookup_log`，避免 notebook 共用解释器时覆盖主实验的 `log`。预测前的待运行代码只放在网页和幻灯片中，避免 notebook 从上到下执行时重复追加一次。练习的起始代码有意保留为未完成状态，学生补全后再运行校验单元格。

幻灯片中带逐步高亮的代码引用使用静态高亮和录制结果，不同时转成 Monaco Runner；因此本课完整的现场共享会话在网页中核对。幻灯片可投影同一份源代码、按步骤高亮和展示备课结果；预测揭示中没有高亮步骤的代码仍提供运行按钮。

删除标记使用 `None`，因此教学实现不把 `None` 作为合法数据。文稿同时指出它尚未实现并发控制、事务和损坏日志恢复，教师可以据此安排后续课程。

## 这份场景能提供的 agent 反馈用例

| 教师给 agent 的请求 | agent 需要看到的环境事实 |
|---|---|
| “把现在这一步讲得更清楚” | 当前文稿、章节 `append-log`、步骤、高亮的逻辑区域和当前讲解 |
| “把选中的查询改成返回最后一次写入” | 源文件 `code/database.py`、选区行号和代码、讲义中引用该代码的块 |
| “预览出错了，帮我修好” | 最近一次编译状态、报错文件与行号、错误原因；修复后重新编译的结果 |
| “这次运行为什么多了一条记录” | 执行代码、会话 `teacher-db`、本次是现场结果还是录制结果、stdout 与错误信息 |
| “按学生刚才没通过的地方加一个例子” | 练习源代码、校验结果和失败断言，再定位到对应讲义章节 |

这些是此场景对应的环境反馈验收输入，具体桥接的通过情况由工作台与 agent 集成验证记录，不把文稿可构建等同于 agent 已取得全部反馈。

## 已修复的教学阻断

| 原来的具体问题 | 修改后的行为 | 直接验证 |
|---|---|---|
| agent 只能读编译录制，看不到浏览器 Python 实际结果 | `get_runtime` 提供作者窗口的插件/组件错误、运行值、失败与会话重置；dsh 每步自动取得有限摘要 | 实际 Pyodide → STATUS → MCP；真实 dsh 服务与脚本化模型读取失败后修改 Python 文件并留下审阅 |
| 参数面板只显示 stdout，SQLite 查询最后表达式看起来为空 | 显示最终值与富输出，比较包含值，notebook 保留 MIME 输出 | 网页、幻灯片与 notebook 定向验证 |
| 参数面板的共享会话无法从头重做 | 重置会话并取消旧运行，不把重置前的晚到结果写回来 | 两种形态的 1→2→重置→1 |
| Studio 不能直接创建从零演示的 Python 文件 | 文件栏“新建文件”输入相对路径后打开同一编辑器，保留讲义和草稿 | 真实 API 的冲突/路径/符号链接/锁检查；窄屏新建、输入、保存 |
| Python 没有语言缩进，Tab 跳出编辑器 | 官方语言支持、四空格块缩进、Tab/Shift+Tab，Escape 后 Tab 仍能离开 | 真实课堂输入 class/def、保存与草稿切换 |
| 打开讲义后文件导航需要回首页，预览吃掉快捷键 | 小型快速打开/命令面板常驻；预览桥仅转发两个快捷键意图 | 跨目录文件、行号、取消后的焦点、窄屏未保存保护与 iframe 入口 |
| 第一次选中代码时关注条出现，编辑器位置发生变化 | 关注内容在编辑区底部按需显示，保留编辑器顶部位置 | 选择前后编辑器位置与选区反馈定向核对 |
| 讲义目录外的 Python 选区没有进入 agent 上下文 | 显式工作区焦点带路径、行号、磁盘摘录及未保存选区；清除/换讲不留旧焦点 | 真实鼠标选中 → 服务 → dsh 模型请求；路径/符号链接与范围拒绝 |

工作台保留简单的教学编辑流程，没有增加完整 IDE 的调试、扩展或终端体系。代码编辑的参照来自 [VS Code 的界面说明](https://code.visualstudio.com/docs/editing/getting-started/userinterface) 和 [基本编辑](https://code.visualstudio.com/docs/editing/codebasics)，主要沿用文件、快捷键和草稿保护习惯。

“先预测，再运行”最初在保存预测后没有运行按钮，也没有代码自身的录制输出。预测的揭示内容进入组件子块后，被两种渲染端误当作组件自行执行的代码。

组件 IR 新增 `ownsCode`，默认保留既有的组件自管方式；预测容器写 `ownsCode: false`，网页和幻灯片因此恢复子代码的执行控件和输出。执行面板、逐行执行与本地环境继续自行管理代码。幻灯片同时递归登记独立子代码的运行选项，保留会话、超时、录制结果与类型来源检查，并用组件路径区分子代码的键。

## 可选授课流程与核对边界

| 授课场景 | 现有入口 | 本次边界 |
|---|---|---|

| 暂停投影、冻结画面、讲解指向代码 | 讲台插件的黑屏/冻结、引导插件的聚光/提示 | 已定向验证网页黑屏/冻结、网页引导随步骤定位、幻灯片引导可逆回退 |
| 学生扫码跟随、预测和答题汇总 | 会话插件加课堂插件；静态学生站点另接课堂服务 | 本次未启动多人课堂；静态构建会明确提示尚未配置服务 |
| 录制课堂并发布回放 | 讲授插件的录制栏；保存轨迹及音视频后构建讲授资源 | 本次未申请麦克风、摄像头或屏幕权限，也未发起计费语音合成 |

| 每步导出 PDF | 发布插件与 `presmium-export --with-clicks` | 已加载发布插件；此次不扩大到 PDF 和所有导出格式 |

## 定向验证

使用 `pnpm exec playwright test e2e/teacher-database.spec.ts --project chromium --workers 1`，只构建该文稿需要的网页、幻灯片和 notebook。并行开发时用 `PRESMIUM_E2E_SLIDES_PORT`、`PRESMIUM_E2E_WEB_PORT` 指定独立端口，并使用独立的测试输出目录。

三个场景用例已全部通过：真实 CLI 检查、独立 Git 源引用、共享会话录制、notebook 在 Python 中从头顺序执行至练习前、网页与幻灯片各自的代码演进前进/回退及逐行回退、网页现场共享会话/预测/磁盘参数/练习纠错、幻灯片预测的提示/揭示边界和执行入口。

另从 `stage.spec.ts` 与 `guide.spec.ts` 定向运行四项既有用例，全部通过：讲者备注随步骤高亮、网页黑屏/冻结与讲者状态、幻灯片引导回退、网页引导随当前步骤定位。分层检查与技能检查通过。未运行全量测试、全部 demo 构建或完整端到端套件。

工作台和环境反馈的定向文件为 `e2e/workbench-editor.spec.ts`、`e2e/workbench-commands.spec.ts`、`e2e/workbench-shortcuts.spec.ts`、`e2e/exec-results.spec.ts`、`e2e/exec-feedback.spec.ts`，以及 `packages/workspace/test/source.test.ts`、`packages/addon-exec/test/outputs.test.ts`、`packages/dsh/test/runtime-feedback.test.ts`。dsh 的自动修改验收使用仓库既有的脚本化模型和真实服务，不表示已经用付费模型评估生成质量。`get_runtime` 的记录是上次浏览器观察，不作为当前源码版本已验证的证据。
