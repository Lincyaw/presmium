## 发现并修复

1. **媒体隐藏后继续播放。** 切到下一张幻灯片后，旧视频仍在播放；进一步补测发现网页放映中的 `at: 0 / until: 1` 视频已经 `aria-hidden`、DOM 仍保留，但 `paused` 在 3 秒内一直为 false。现在通过 Slidev 公开活动探针与宿主新增的 `useBlockStepRange()` 分别感知切页和块的显示范围；有效范围包含父块限制，原有块内步骤偏移不变。网页放映、幻灯片同页隐藏与后退，以及原有跨页视频/音频、隐藏播放阻止和自动播放恢复均已实测通过。手动媒体返回后保持暂停，自动恢复前重新检查是否仍启用 autoplay；普通阅读保留用户控制。
2. **首次脚本执行丢失结果。** 开发服务器在首次加载脚本 Worker 的 `sucrase` 依赖时重新优化并刷新整页，运行面板回到空闲、没有结果。现在通过现有 Vite 公开配置提前预打包，实际首次 JS 输出 42，且没有主框架文档导航。
3. **脚本 Worker 离页后残留。** 运行中的 JS/TS Worker 在 `pagehide` 后 5 秒仍有一个。执行器现在跟踪活动请求，释放时取消、结束 Worker、清理计时器和监听器；释放后的实例拒绝新运行，恢复页面使用新实例。
4. **Python 旧队列释放后复活。** 原来的瞬时 Worker 数为零检查不足。加强用例确认 Python 已进入等待，再排队另一个任务；页面暂停后，旧队列仍执行并输出 `queued-42`。现在在释放前标记实例已结束，队列真正开始时检查该状态，排队任务以取消结束，不创建新 Worker。复查同时检查两个面板结束、没有成功输出、Worker 创建数不增加，以及恢复后只有一个新 Worker。

普通 Python 取消、超时与会话重置仍允许后续运行；只有已释放的实例永久停止。脚本结束处理是幂等的。源码与回归另做了独立只读复核。

## 未覆盖的条件

- 本轮浏览器只用 Chromium。没有跑 Firefox、WebKit、完整 E2E、全量包测试或消费者安装测试。
- WGSL 用真实 Chromium 的 SwiftShader 软件适配器计算，另启动禁用 WebGPU 的浏览器验证回退；没有物理 GPU、Python GPU 桥、JSPI 或 jax-js 验证。WASI 本轮仅覆盖 C，未覆盖所有语言。
- 执行器生命周期用真实 Worker 和宿主事件处理器，但 `pagehide/pageshow` 由测试派发；没有验证真实导航进入与恢复浏览器 BFCache 的完整流程。
- 没有真实麦克风/摄像头录制、语音转写/TTS、付费模型服务、视频或 PDF 导出、直播 YouTube、Docker/GPU 部署矩阵与额外课堂后端矩阵。
- 未验证已在网页阅读页播放的媒体在进入保留阅读页的放映浮层时停止；普通阅读仍保留用户对屏幕外音频的控制。修复范围限于本次实测的切页、步骤范围、隐藏实例播放和卸载。
- 课堂练习本轮验证提交、检查与统计；个人笔记的持久化通过，不把它表述为练习草稿持久化。
- 新范围 helper 的嵌套空交集及运行时取消 autoplay 的标记清理做了源码复核，没有为这些分支增加浏览器用例。

## 定向复现

使用单 worker 和相同线程预算，按文件与用例名筛选。新增用例为：

- `e2e/exec-lifecycle.spec.ts`：开发网页、真实 Python/JS/TS Worker。
- `e2e/exec-webgpu-smoke.spec.ts`：复用 shader 小文稿，只构建 WGSL 部分。
- `e2e/publish-smoke.spec.ts`：仅 core、publish，下载源服务自行创建并关闭。
- `e2e/content.spec.ts` 中 `leaving a media slide`：切页与显示范围的单条生命周期回归。

本轮 Playwright 使用独立临时配置：继承仓库配置，仅保留 `chromium` 项目，清空全局 `webServer`，`workers: 1`、`maxFailures: 1`、`retries: 0`，跟踪产物放在各批自己的临时目录。避免为了一个组件启动无关回归服务。命令共同使用 `--project chromium --no-deps --workers=1`；新文件可直接按文件筛选，旧文件只选择上表的具体行为。包内 3 项使用：

```sh
pnpm exec vitest run --project integration packages/addon-classroom/test/notebook.test.ts packages/addon-classroom/test/predict.test.ts --maxWorkers=1 --no-file-parallelism
```

所有批次设置 `OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 NUMEXPR_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 BLIS_NUM_THREADS=1 GOMAXPROCS=1 RAYON_NUM_THREADS=1 UV_THREADPOOL_SIZE=2`。仅使用自己启动的服务和文稿；测试辅助的清理均已完成，进程核对没有匹配的本轮临时服务，独立临时配置与跟踪产物已清除。机器可读结果见 [JSON 记录](./components-validation-2026-10-21.json)。
