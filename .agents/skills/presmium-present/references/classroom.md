# 课堂互动

用于学生扫码加入、跟随讲者、答题和提问。先准备学生能访问的讲义站点，再配置课堂同步；只有讲者自己能打开的本机预览不能作为学生链接。

## 准备站点与服务

文稿列出 `@presmium/slidev-addon-session`、`@presmium/slidev-addon-classroom`；代码练习校验还需要执行插件。给学生构建静态版本，受众标记见 `presmium-author`。

需要独立课堂服务时安装 `pnpm add -g @presmium/classroom-server`，在文稿目录运行：

```sh
presmium-classroom-server --port 1234 --deck .
```

服务打印可用的网络地址。把学生能到达的地址写进文稿头部，下面的 IP 换成服务所在机器的实际地址：

```yaml
presmium:
  presmium.session:
    server: ws://192.168.1.10:1234
```

配置会写入产物，随后运行 `presmium build --audience student --out dist-student`，静态站点的服务方式见 [发布、导出与离线](delivery.md)。主讲也使用带同一课堂服务配置的讲义；完整版与学生版通过稳定标签换算位置。

课堂服务默认监听所有网卡，没有 TLS 和身份认证，拿到链接的人可加入；按授课网络部署。HTTPS 站点应使用可从浏览器访问的 WSS 服务地址。学生访问的是静态站点与课堂服务，不是作者工作区。

`presmium dev` 与 `presmium serve` 内置同步可用于作者本机演练。不要为了给学生开课而暴露作者工作区：能访问该服务的人具有作者权限，且拿到完整文稿。

## 实际走完一堂课

1. 主讲打开讲义，在网页导航的“课堂”或幻灯片演讲者面板中创建课堂。把站点的网络地址用于加入链接，避免 `localhost`。用学生设备或另一浏览器扫描二维码加入。
2. 验证默认跟随：主讲翻到另一节、推进一步，学生到对应位置。学生点“自主浏览”后可以自己翻，点“回到主讲进度”恢复。学生版没有的教师步骤不要求学生看到。
3. 测验先“开放作答”，学生提交，主讲“关闭作答”后才揭示正确答案。练习提交后查看通过情况；提问、投票和理解度在“互动”中汇总。
4. 下课先结束，再归档。归档保存到课堂服务 `--deck` 目录的 `.presmium/classroom/<课堂号>.json`；此后不能再加入或写入。个人笔记不进入归档，归档默认被 git 忽略，需要保留时单独备份。

课堂在服务内存中，未归档前重启会丢失记录。主讲窗口意外关闭时，在同一浏览器、同一讲义地址重新打开，选择“以主讲身份回到课堂”。

## 预测与问答怎样揭示

`{predict}` 在网页文档视图中让学生先保存预测再看后续内容；放映和幻灯片仍由主讲推进揭晓。需要使用时实际验证学生那一侧，不能只看投影画面。

启用助手插件并配置模型时，主讲可为提问生成 AI 回答，先在自己窗口查看，再点“发给课堂”。模型配置保存在主讲浏览器，学生不需要模型密钥。不要把生成完成当作已分享给课堂。

## 无法加入时

先分别验证学生设备能否打开静态网页、能否连接课堂服务。检查地址、端口、WS/WSS 与站点协议。修改配置后重建并重启静态服务器，再生成加入链接。
