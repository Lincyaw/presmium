# Editable document format

`index.pmd` is Presmium's versioned domain document, not an editor's private state. The installed `@lincyaw/kernel` exports `DOCUMENT_ENTRY`, `DOCUMENT_SCHEMA_VERSION`, `DOCUMENT_JSON_SCHEMA`, `validateDocument` and the TypeScript `PresmiumDocument` contract. Use that contract and validator for exact fields.

A document has `schemaVersion` (2), `id`, `placement`, `metadata`, `sectionOrder`, `sections`, `blocks`, `steps`, `narrations`, `assets`, `definitions` and `production`. Metadata includes the title and optional language, plugins, renderer settings, execution, checks and translations. Credentials belong in operator settings, never metadata.

Documents form a tree inside a workspace. Every `index.pmd` below the workspace root is a document (translations in `locales/<lang>/` follow their original); `presmium.workspace.yaml` does not list them. `placement: { parent, rank }` puts a document under another document's `id` (`null` is the top level), ordered among its siblings by `rank`, a fractional index that sorts as a string. A move changes only the moved document's `placement`; folders never move. Document IDs are unique in the workspace, and everything that points at another document uses its ID, never a path.

A child inherits settings it does not set itself: the workspace's `defaults:` → the top ancestor → … → the parent → the document. `lang` (default `zh-CN`), `plugins` and the caption size take the nearest value; `presmium`, `renderers`, `execute` and `checks` merge key by key, nearest wins; `production.defaults` merges field by field. Title, description, tags and translations are never inherited. Write a setting into a document only where it differs from what it inherits.

A document of the older format (schema version 1, file `lecture.json`) is rejected with `document.schema-upgrade`; `presmium migrate` (or Upgrade in Studio) converts it, keeping every setting explicit.

Sections contain a title, ordered child block IDs, ordered step IDs and a layout (`stack`, `columns`, `canvas` or `scrolly`). On the reading page a `scrolly` section keeps its figures in place while a track of its steps scrolls beside them, each step showing its narration, so that narration is read as well as heard ([Writing](writing.md), section 6). Blocks are typed `text`, `container`, `image`, `code`, `component` or `embed`. Containers own child IDs; component instances reference a definition plus their own parameters; image blocks reference an asset. An `embed` (synced block) is `{ id, type: 'embed', source: { document, block } }`: it shows another block and its content as they are in the source now, owns no content or children, and is edited only in the source; its steps stay its own. The current version shows a placeholder with the warning `embed.unresolved` where it stands.

Text blocks contain structured `paragraph`, `heading`, `list`, `blockquote`, `code`, `math` and `table` nodes. Actual editing units and list/table children retain IDs. Inline content is `text` with marks, `link`, `math`, `break` or `reference`. A `reference` is `{ type: 'reference', target: { document, section?, block? }, label?, fallback }`: it names a document, one of its pages or blocks by ID (the document may be this one), shows `label` or else the target's current title, and keeps `fallback`, the last known title, for when the target is gone. Until sites link documents, a reference to another document reads as plain text; rich text is adapted through BlockNote's public API. Do not put Markdown source in a string field to imitate this model.

Authored IDs must not equal `page:<Section ID>` for an existing section: that exact ID is reserved for the section title's comment anchor. Referencing it in a comment `blockId` remains valid. Other `page:` IDs are ordinary IDs; do not rename them merely because of the prefix.

A comment anchor is either a text range (`from`/`to` text points with UTF-16 offsets) or a place `{ blockId, stepId? }` naming a block, optionally at one step of its section. A preview block's toolbar can comment on the whole block or one step; the step must belong to that block's section. If the step disappears the anchor keeps the block, and only a missing block leaves the thread unanchored.

A step belongs to one section and has `visuals` and `narrationIds`; optional `inherits` refers to an earlier authored state. Omitted blocks are invisible. `visuals` explicitly name block visibility, a declared component state and optional state parameters. Arbitrary step selection must reconstruct the same state without playing earlier steps.

Narrations are structured `text`, `pronunciation { display, spoken }` and `cue { id, action, target?, parameters? }` nodes. The target uses stable `blockId` and optional component element. Captions, spoken text and cue alignment derive from this one structure.

`production.defaults`, optional section overrides and `stepOverrides` own narration start, minimum hold, trailing pause and voice source. Voice sources are `none`, TTS with an actual provider voice, or a recording asset with an optional source range. Change an adopted recording range through the shared audio authoring action with the actual asset SHA and duration; it affects only that step instance and never edits original bytes or narration. Captions remain unaligned whole-step text. Cue delays live in `production.cueTimings`. Media clips reference source time ranges and a step attachment. Absolute playback times are generated, never copied back from a snapshot.

Definitions retain implementation references (`file`, `module` or `plugin`), parameter Schema, declared states and versioned plugin data. For source-bound parameter edits, use the shared component authoring actions: base parameters, stable-step overrides, explicit current override reset, or selection of an existing Definition. Send only changed schema-declared editable parameter paths; arrays and objects are valid values. Read-only ancestors/descendants cannot be bypassed by replacing a parent. A complete public array item may be deleted, and pure reorders retain exact complete items; split ambiguous mixed reorders and edits. Read actual inherited-step impact before applying the original plan reference. Preserve unknown values and all unrelated overrides. Independent implementation copies are unavailable until a complete dependency closure can be copied atomically; cloning a Definition or TSX alone is not isolation. A migrated numeric state has an explicit `legacyIndex`; a number is not a semantic state name. Assets keep a location and optional fingerprint/media type, with large files outside JSON.

Validate references, unique IDs, tree ownership, parameter/state capability and media ranges before saving. Agent and Web edits enter the same transaction validation with `baseDocumentVersion`; runtime output uses a separate snapshot identity. Old replies must not clear new edits.
