# Editing with the studio and an agent

For an explicit title change use `rename_page` with the page number or stable ID and title. For other canonical content changes use `edit_document` with operations. Both read the source, preflight, save through the Web transaction/history and verify saved content inside one call; pass optional source when intent depends on an earlier read. Their default receipt is saved/changed plus editor status; details are opt-in. `get_context` reads the current saved editor target; `edit_narration` replaces a unique exact phrase while preserving cue/pronunciation atoms, or removes one complete block with `remove` by stable narration ID or 1-based index. `get_context` aligns saved text with stable IDs (at most 12 blocks / 2000 UTF-16 characters); prefer the ID after reading. Use canonical `setStepNarrations` to replace the complete ordered reference list, removing omitted links and preserving content still used by other steps. Pending feedback never means that the save should be repeated. Use plan/apply tools when a change needs separate impact review. The local owner's MCP credential authorizes canonical editing without a second Studio confirmation; execution, browser control and paid generation retain their own policies. External MCP exposes a compact catalog: use `operations` to discover actions and generated argument summaries, then the dispatcher matching its kind; `schema:true` opts into a complete definition. CLI parameter discovery is automatic: `presmium mcp tools <tool>` returns generated summaries, `--schema` returns inputSchema and `tools --all --json` returns the full catalog. Do not look up tool parameters in implementation source.

For an external HTTP MCP client, start Studio and configure `http://127.0.0.1:4321/mcp` (Streamable HTTP) with `Authorization: Bearer <token>` from the token file printed at startup. Studio preserves both for the same launch directory across restarts and upgrades. With `--host 0.0.0.0`, use the printed network MCP URL from other machines. When another Studio holds port 4321, a second one starts on a free port and prints that its MCP address differs this time; give each Studio its own `--preview-port` when clients need fixed addresses.

Install Presmium once with `pnpm add -g @lincyaw/presmium`; Studio is included. Run `presmium studio <workspace-or-document>`; open the complete address it prints. Editing and preview need no model. The document editor uses one native BlockNote editing surface across the whole document, including cross-block selection and native history/comments. An animation or chart preview's toolbar has Comment on step for the whole content block or one step.

In Studio, AI source edits use a private candidate workspace while the author keeps editing. A stale publication returns the current author source to the candidate; read it again and retry the intended change. Required review keeps candidate edits separate until acceptance; rejecting them preserves the author's saved content. Each published writing tool has its own version.

Web and agents modify the same `lecture.json`. Read the current document version, submit semantic edits or a full JSON document using the workspace's document transaction API, and retain unsaved input on conflict. `baseDocumentVersion` is the authoring CAS version, not a runtime IR digest.

When connected to a workspace MCP host, discover saved entities with `get_document_outline`, then read complete values with `read_document_part`. Retain source on every continuation and use returned offsets to assemble explicit JSON-text fragments before parsing once. A changed source returns 409; restart the read rather than combining versions. The full `get_document` remains available to SDK consumers but may exceed the agent's tool-result budget. Changes use `plan_document_change` and `apply_document_change` through the Web transaction and return saved-source verification; generic large change inputs/results are not yet bounded. Compilation is a separate result. Do not substitute mouse automation or an edited runtime snapshot for an available author action. Compiler-only stdio reports these authoring services unavailable.

To see a page as the presentation shows it, call `capture_slides` with its section: it returns PNG pictures (and their files in the service's state directory) of every step's rest frame, or of the steps and `at` moments you name (milliseconds into a step's animation, drawn by the same step clock a lecture export uses, so a picture is the same each time it is taken). `measure` adds the boxes of the elements matching a CSS selector, in slide pixels, with their text and `data-*` attributes; `appearance: 'dark'`, `scale: 2` and `clip` cover the dark theme, fine detail and one region; `captions: false` leaves out the captions drawn over the slide, and each frame's narration is in the result as text either way. At most 12 pictures a call. `arrive: 'backward'` reaches each step from the step after it, as a presenter going back does, with the page's own clock: compare it with the direct picture; `capture-page-reloaded` means going back reloaded the page. `capture_overview` takes every page at once (each page's last step, or every step with `steps: 'all'`) into one directory named in reading order, with sheets of labelled thumbnails; it is the material of a cold-read review. `capture_reading` takes one page of the reading version at a window `width` (default 1280, 390 for a phone), scrolled through so that its components load, at rest, cut at 8000 pixels. A scene whose code doesn't bundle fails alone: its page shows the failure, the capture's `problems` say why, and `check_document` (like `presmium check`) reports it as a `presmium.preview.code` error with its file and line. When the whole document can't be prepared the capture fails with `capture-preview-failed`, and `get_diagnostics` holds the reason.

For existing workspace audio or images, call `import_workspace_audio({path})` or
`import_workspace_image({path})` with a same-document workspace-relative path. No separate capability,
source or inspection request is needed. The host pins source and actual SHA-256/bytes before approval and
rechecks them at commit. To adopt recorded audio, call `adopt_recording({stepId, assetId})`; source and
asset hash are managed internally. Ordinary results are compact. Pass optional `source` for intent based
on a prior read, and `details:true` for verification details. Advanced `request` preserves the original
explicit native contract; do not mix it with ordinary fields. `operations` derives `inputChoices` for
these alternatives from the schema. A conflict or lost response requires checking saved assets/steps,
not automatically repeating an import. Import only registers an asset; insert an image block with its
assetId and alt text separately, and explicitly choose an audio asset before adopting it as narration.

Every tool that writes the document (`apply_document_change`, `apply_page_change`, `apply_page_duplication`, `apply_authoring_action`, `undo/redo/revert_document_change`, `import_workspace_audio`, `import_workspace_image`, `adopt_recording`, `change_media_clip`, `apply_transcription_adoption`) checks the request before the author is asked: a stale source, a changed or missing file, a wrong SHA-256, an unknown or changed plan, a missing deletion confirmation, a history target that is no longer next or an uncommitted edit returns its error at once, without an approval request. Fix the request (read the current source, plan again) instead of asking the author to approve it. The write checks again after approval: if the document changed while the author was deciding, it returns 409 and writes nothing.

`start_transcription`, `start_voiceover` and `preview_voice` follow the same order: a stale source or IR revision, a changed audio digest, an unknown asset, page or step binding, an engine that cannot transcribe, a transcription already running for the document, a reused, cancelled or failed intent, or an unknown, expired or changed preview quote returns its error without an approval request. `build` checks its saved source, targets and inputs first as well: an unknown target returns `job-target-unknown` (422, with the targets the document can be made into), and when every target already has a job for that exact source it returns those jobs with `reused: true` without asking or building again. Naming an engine that cannot transcribe or synthesize, or one that is not configured, returns 422 (`transcription-engine-unsupported`/`-unknown`, `voice-engine-unsupported`/`-unknown`, not retryable): pick an engine from the capabilities instead of retrying; 503 means the speech service itself is unavailable. Cancel tools ask only when there is something to cancel: an unknown job id returns 404 at once, and a job that already ended (or is already cancelling) returns its current state without asking. Some failures carry a `detail` and an author-readable `message` in the document's language, for example `workspace-file-missing` (`detail.path`) or `history-target-changed` (`detail.revision`, `detail.which`: read the history again); relay that message to the author rather than the code.

Read an existing real plan with `read_production_plan({request:{source}})`; explicitly read the IR resource first if it needs preparation. Use its actual binding with `validate_media_clip_change` and authorized `change_media_clip`. Removal needs no valid plan and retains the original asset. Validation retains no plan, and apply repeats media and timing checks. For voices, `get_voice_authoring_capabilities` and `get_voice_catalog` share Web discovery without compilation or synthesis; configured engines do not prove a provider request will succeed. Voice selection and generation remain separate.

For generation, copy the source, IR revision and scope targets from `get_voiceover_status`, then use authorized `start_voiceover` with a client intent. Discover or reconcile through `get_voiceover_jobs/get_voiceover_job`; `cancel_voiceover` can precede admission and remains available when current JSON is invalid. Web and MCP share the same process-local task owner and monotonic sequence. A completed job still needs actual cache/production-plan verification. Audition uses `quote_voice_preview` then separately authorized `preview_voice`; read its bounded audio resource instead of requesting data URIs, and do not describe generation as observed browser playback. The old synchronous `lecture_synthesize` plugin tool is no longer exposed.

For saved audio, read `get_transcription_capabilities` and the actual provider declaration first. A configured engine is not proof that authentication or recognition succeeded. Only `start_transcription` starts paid recognition, after host authorization; never supply `confirmed` or `origin` in model arguments. Use `get_transcriptions` to discover real workspace tasks, `get_transcription` to poll and `get_transcription_result` to read an exact immutable candidate. Cancellation uses `cancel_transcription`; keep the original intent when an answer is lost. A pre-admission cancellation has no fabricated task, and broken current JSON can still be inspected or cancelled by known task ID.

Adopt a candidate through `plan_transcription_adoption` and `apply_transcription_adoption`, using the shared source, candidate revision, draft revision and returned plan ID. Explicitly choose stable steps and preserve or resolve existing pronunciation/cue atoms; a conflicted preview has no applicable plan. Do not flatten protected atoms, invent word times or silently change the voice source. Selecting a real TTS voice and generating it remain separate explicit operations. Required agent review remains a host gate, not a payload flag.

Keep page, block, step, narration, asset and definition IDs stable. Save acknowledgement must match document, request and input version. A delayed save or generation result cannot clear a newer draft or become the current snapshot.

The page menu's Duplicate page action copies the canonical page with new owned entity IDs and remapped internal teaching bindings, including narration, cues and production settings. Definitions and assets remain shared; discussions stay anchored to the original content, and existing incoming references keep their original targets. Unknown plugin payloads are preserved without guessing references from strings. Editing and duplicating a page do not require a successful runtime compilation.

Expand an animation card's step captions/script area to edit canonical narration and its start timing through horizontal choices. Advanced hold and trailing-pause controls belong to video production. The fields show their actual inherited source. An explicit step start overrides inherited narration settings only for that step; restoring inheritance keeps shared narration, voice, cue and media settings. Unaccepted numeric input in production remains a separate form draft across step navigation and refresh; it is never written into `lecture.json`. Resolve it or explicitly restore inheritance before presenting.

For pending production inputs use `editor_action` with `production-drafts.inspect`, `.read` or `.discard`.
Discover the selected variant through `operations`; inspect returns at most ten metadata entries without
input values. Choose its opaque `draft` for an explicit bounded JSON read, or discard with `confirm:true`.
The native stores cover step hold/pause, caption timing, recording range, voice choices and media clip
proposals; recording ranges are memory only. Each media clip proposal has its own handle; discarding one
keeps sibling inputs. Voice and media forms still recover through their own native reopen flow. Discard resets the open field to its saved value without saving the document. Composition, an active
save, a changed source or unavailable storage can refuse it and retain the proposal. Local inspect/read
still work with invalid saved JSON. Use a fresh inspect after input changes; these stores contain current
proposals, not historical backup branches.

For comment drafts use `editor_action` with `comment-drafts.inspect`, `.read`, `.restore` or `.discard`.
Inspect returns metadata and a `restorable` flag without comment text, anchor signatures or baselines.
Ordinary restore needs only the returned `draft`: the client selects a unique native target and preserves
current input before adopting a new branch. It can reopen a closed new text or place-comment form;
reply and existing-comment editing use their mounted native composers. A changed text anchor is refused.
Discard retires only that exact version, then clears its open form or restores the saved comment text.
Composition, saving, read-only state, storage failure or changed input can refuse mutation. Local reads
still work when saved JSON is invalid. Inspect `details:true` and the paired `composerId/expectedCurrent`
binding are for diagnostics; do not copy them into ordinary calls. Restoring is separate from saving.

Preview compilation is independent. When it fails, retain valid document content, show readable diagnostics and identify the previous snapshot's version. Do not fix a preview by writing generated IR or silently replacing the authoring file with editor-private state.

For agent changes, state the affected objects and intended result, inspect the actual diff and validate the same document. Never infer a paid provider capability from a prototype or silently synthesize narration while editing.

For browser navigation, discover `editor_action` with `variant: "document.open"`, `"document.close"` or
`"window.read"`. An unbound external workspace owner can open a served document from home using
`action.document` (the root document is `""`); omit the top-level document. With several windows, choose
`clientId` from `get_authoring_clients({scope: "workspace"})`. Its default list is compact; `details:true`
is for transport diagnostics. A pending window result returns `{handle}`: pass it unchanged to
`get_authoring_client_request` or `cancel_authoring_client_request`, never resend the action. Navigation
uses native retained document state without implicitly saving or discarding drafts; composition, pending
forms, recordings and asset writes can block it. A document-bound assistant cannot navigate other documents.
