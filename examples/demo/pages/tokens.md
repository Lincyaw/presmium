# 文本怎样变成数字

:::{slide}
1. 模型读的是数字
2. 按字符切，还是按词切
3. 从字节出发
:::

这一章先弄清楚分词要解决什么问题，再说明 BPE 为什么从字节出发。

(tokens-numbers)=
## 模型读的是数字

:::{slide}
| 文本 | 词元 | 编号 |
| --- | --- | --- |
| `lowest` | `low` + `est` | 260, 257 |
| `newest` | `new` + `est` | 263, 257 |

**文本** → 切分 → **词元** → 查词表 → **编号** → 模型
:::

神经网络只会做数值计算，文字进入模型之前，必须先变成一串整数。分词器做两件事：先把文本切成词元，再查**词表**（vocabulary），把每个词元换成它在词表中的编号。模型输出的也是编号，分词器再把它们换回文字。

上表是本课最后得到的分词器给出的结果。`lowest` 和 `newest` 各被切成两个词元，并且共用同一个词元 `est`，编号都是 257。模型因此能看出这两个词有相同的结尾。词表里该收哪些词元，正是分词方法要回答的问题。

(tokens-granularity)=
## 按字符切，还是按词切

:::{slide}
| 切分方式 | 词表大小 | 序列长度 | 没见过的词 |
| --- | --- | --- | --- |
| 按字符 | 小 | 很长 | 都能表示 |
| 按词 | 很大 | 短 | 无法表示 |
| 子词，如 BPE | 自己选定 | 适中 | 拆成常见片段[^subword] |

[^subword]: Sennrich 等人在 2016 年把 BPE 用于神经机器翻译的分词，此后它成为最常用的子词分词方法之一。
:::

最直接的两种做法各有毛病。按字符切，词表很小，但一句话会变成很长的序列，模型要读很多步才能读完。按词切，序列变短了，可词表得收下每一个词，而且训练时没见过的新词、拼错的词都无法表示。

子词分词取两者之长：常见的词整个成为一个词元，少见的词拆成几个常见的片段。词表多大由我们决定，最坏的情况也能退回到单个字符，所以不会有表示不了的文本。BPE 就是自动找出这些片段的一种方法。

(tokens-bytes)=
## 从字节出发

```{code} python
:run: both
for text in ["low", "你好"]:
    data = text.encode("utf-8")
    print(f"{text}：{len(text)} 个字符，{len(data)} 个字节 {list(data)}")
```

:::{slide}
- 每个字节是 0 到 255 之间的整数：**256 个起始词元**，任何文本都能表示
- 一个汉字占 3 个字节：只用字节，序列太长
:::

计算机里的文本本来就是一串字节。UTF-8 编码把每个字符写成 1 到 4 个字节，每个字节是 0 到 255 之间的整数。代码下方是它的运行结果，你也可以自己运行一遍，换几个字试试。

英文字母各占一个字节，一个汉字占三个字节。如果直接把字节当作词元，词表只有 256 个，任何文本都能表示；缺点是序列太长，中文尤其如此。BPE 从这 256 个字节出发，把经常相邻出现的字节一步步合并成更长的词元，序列也就随之变短。
