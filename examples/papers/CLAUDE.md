# 三分钟读完一篇论文（翰林院传达室）

这个目录是一个 Presmium 工作区：每篇论文一份文稿 `papers/<slug>/lecture.json`，做成一段三分钟左右（一般不超过六分钟）的配音动画（讲授视频），同时是网页（画面固定、讲稿在旁边滚动）和幻灯片。在本目录 `pnpm serve` 预览整个网站，`pnpm build` 导出网站到 `dist/web/`。

工作区在仓库的 `examples/papers/`，每篇论文放在 `papers/` 下的独立子目录。CI 检查并构建所有论文；推送到 `main` 后，Pages 工作流以示例站的 `/papers/` 为基础路径构建，并将产物合入同一次部署。新增论文由 `presmium.workspace.yaml` 的 `papers/*/lecture.json` 自动收录。

写文稿、做动画、配音与导出的通用规则在仓库的技能 `presmium-author`、`presmium-animate`（`.agents/skills/`）里；这里只写这个系列自己的标准和流水线。

## 自动制作与发布

独立技能 `presmium-paper-to-xiaohongshu` 负责从论文链接到小红书发布。作者已为本工作区约定：以后发送论文链接即自动制作动画、使用已配置的火山引擎“甜美桃子 2.0”生成该篇常规配音、制作独立封面和简介，再发布到小红书账号“翰林院传达室”，标题期数接续该账号已有的论文分享。普通叙事选择、分镜预演、当前篇缺失配音生成和最终发布不再逐项询问；用户当次要求预览或暂停发布时以当次要求为准。账号变化、新的付费服务、权限扩大或必要的用户验证不属于这项约定。

期数、去重、上传、实际状态和中断恢复统一按该技能的 `references/publication.md` 执行；以原文稳定标识关联本地文稿和原笔记，不能把“第二期已发”固化成下一期的永久数字。发布简介、素材和记录分区保存到每篇的 `publish.md`。创建或验证技能本身时不生成云端用量，也不重新发布已有论文。

本系列使用账号已有的“论文解读”合集。新一期发布时加入它，修改或替换已有视频时保留并核对归属；第1、2、3期已经加入并逐条核对。复用现有合集，不创建同名合集；不改动其中其他笔记。

## 标准

- **时长**：以三分钟左右为目标，一般不超过六分钟；这不是硬性规定，按内容调整。观众需要的解释（概念的定义、基线是什么、指标是什么意思、结论的前提）不为了缩短而删：删掉之后观众容易跟丢。讲稿按火山引擎甜美桃子实测约 4.5 字每秒估算，三分钟约 800 字（按读音计，`10²³` 读作“十的二十三次方”算 7 个字）；配音生成后用 `pnpm timing <slug>` 量每步与总长；明显过长时删重复与旁枝，不删定义，也不加快语速。
- **固定开场白**，配品牌卡（`kit/opening.ts`）：“三分钟读完一篇论文。大家好，这里是翰林院传达室，今天给大家带来{单位}的《{论文中文名}》。”
- **固定结尾**，配结尾卡（`kit/closing.ts`，页面上只有“一句话总结”、那一句的短语、对话气泡与标志）：“一句话总结：{论文做了什么}。想看哪篇论文，欢迎在评论区留言。翰林院传达室为您分享最新论文，我们下期见。”结尾之前的结论页讲条件与前提，不和这一句重复。
- **顺序**：问题 → 为什么重要 → 论文要解决什么、它的办法（一句话）→ 展开：方法（概念先用画面引入再命名）→ 主要证据 → 第二个结果（如有）→ 条件与局限 → 固定结尾（一句话总结与互动）。前四项在第一分钟内讲完。
- **论文原图**：架构图、关键结果图从 arXiv 源码的图 PDF 裁切（`presmium-animate` 技能的 `gallery/catalog/paper-figure/tools/figure.py`），一步只放一张、镜头一次只框一个区域，用我们的动画在图上标注、移动、对照。原图的配色就是全片的配色，裁切和动画共用一套图例。
- **数字**：画面上的每个数字都由论文公开的数据重算（`papers/<slug>/scenes/data/derive.py`，打印与论文值的对照）；没有公开数据时取论文正文或表格的数字并在画面上标出处；示意的曲线标“示意”，估算标“估算”。
- **画面文字**：页面上只放关键词和关键词组（表格除外），不写成句的说明；数字、单位、图例照常。讲稿（也就是字幕）完整描述这一步画面上的图和字：先说画的是什么（坐标轴、颜色、每个点代表什么），再说它说明了什么，屏幕上出现的每个关键词讲稿里都有着落。
- **中文表述**：标题、关键词与讲稿都按中文习惯写。先找英文表述硬译成中文的地方（“进入 S 形函数”“噪声底”“留出的模型”这类直译、名词堆叠、被动句），再按中文语序重写；术语用这个领域的中文说法，没有中文说法的保留英文（logit、FLOPs）。
- **配音**：默认火山引擎的甜美桃子 2.0（`volcengine` / `zh_female_tianmeitaozi_uranus_bigtts`）。火山引擎的 API Key 由运营者保存在工作区的运营者目录（Presmium Studio 的“设置 → 语音服务”，或 `~/.local/state/presmium/operator/<工作区路径的哈希>/speech/credentials.json`），不进仓库；这个 Key 需要在火山引擎控制台开通“豆包语音合成模型 2.0”（资源 `seed-tts-2.0`）。所有论文统一用火山引擎配音。
- **自动时序**：同时播放配音的场景由实际配音自动决定时长，可缩短也可延长；场景 `durations` 只提供无声预演与手动播放的后备时长，不复制进 `minimumHoldMs`。只有明确需要讲完后继续读图时才设置最低停留。相邻步骤复用的图与主体从起步就存在，只对新增内容做入场，避免每步清空重画。配音后检查连续换页与静音间隔，不能仅凭最终帧验收。
- **来源页**：最后是只在网页上显示的“来源与说明”页（文献、数字来源、示意与估算、条件）。它的内容只属于网页，讲授视频跳过它，停在结尾卡上；幻灯片里只留一行“见网页版”。
- **字幕**：导出的视频烧入字幕，字号要在视频里看得清（默认 1080p 上约 60 像素），浅灰半透明底、近黑色字，贴近底边，尽量少挡画面；大小可在 Presmium Studio 的视频制作里按文稿调整。
- **品牌**：左上角固定角标 `brand()`（信使猫标志与“翰林院传达室”），标志在 `kit/brand/mark.svg`（翰林院传达室标志方案 B）。
- **发布交付**：每篇论文的视频必须配齐发布标题、正文文案、封面和对应的视频文件，四项对应同一篇论文、同一版成片。标题与正文写在 `papers/<slug>/publish.md`。小红书沿用第一期格式：标题为“论文分享第<中文序号>期：<论文名>”，期数接续账号已有的论文分享；正文用“今天分享……”引出论文，再用一段话简述研究问题、方法和发现，末尾放相关话题标签。正文不附配音方式、素材来源、示意说明、制作过程等注释性文字；数字来源与完整条件留在文稿的“来源与说明”页。发布素材区用相对链接指向 `papers/<slug>/cover.png` 和实际导出的 `papers/<slug>/dist/<轨道>.mp4`；文案概括问题、方法与主要结果，数字与条件和文稿一致。封面默认横版 4:3，主题文字在缩略图上可读，沿用系列品牌和论文配色；示意图标“示意”。交付前确认链接有效、封面文字正确、视频可播放且字幕清楚。仅有文稿、分镜或视频路径不算完成交付；视频必须实际导出。发布文案与封面随源文件提交，视频按下文约定留在 `dist/`，不提交。

## 目录

| 路径 | 内容 |
|---|---|
| `kit/` | 所有论文共用：画面与类型（`frame.ts`）、图表（`chart.ts`）、论文原图的镜头与标注（`figure.ts`）、品牌（`brand.ts`）、开场（`opening.ts`）与结尾（`closing.ts`） |
| `papers/` | 所有论文文稿，每篇论文一个独立的 `<slug>/` 子目录 |
| `papers/<slug>/lecture.json` | 文稿：唯一的内容来源（讲稿、步骤、场景引用、配音设置） |
| `papers/<slug>/storyboard.md` | 分镜：简报、论点、配色、术语表、定义表、每一步的结束画面、数字来源、制作规则、评审记录 |
| `papers/<slug>/publish.md` | 发布标题、正文文案，以及对应封面和成片的相对链接 |
| `papers/<slug>/cover.png` | 与成片对应的发布封面，默认横版 4:3 |
| `papers/<slug>/dist/<轨道>.mp4` | 实际导出的成片，不提交；交付时与文案、封面一起提供 |
| `papers/<slug>/scenes/` | 这篇论文的动画场景；`opening.ts`、`ending.ts` 复用 `kit/opening.ts`、`kit/closing.ts`；作者要求静态封面时，可在本篇包装共享片头的最终状态；`<名>.ts`（数据与配色）供各场景共用 |
| `papers/<slug>/scenes/data/` | `derive.py` 与它算出的 JSON |
| `papers/<slug>/figures/` | 裁好的论文原图与它们的文字坐标（`*.json`） |
| `papers/<slug>/.presmium/speech/` | 合成好的配音（随文稿提交，导出与网站直接用） |
| `tools/` | 取源码（`fetch.sh`）、生成文稿骨架（`new-paper.mjs`）与按工作区配置逐篇检查（`check.mjs`，`pnpm check`）；其余步骤用 Presmium 自带的命令 |
| `.cache/` | 下载的 arXiv 源码、论文代码仓库（不提交） |

## 流水线

1. **取源码**：`tools/fetch.sh <arxiv-id> <slug>` 下载 arXiv 源码（`https://arxiv.org/e-print/<id>`）到 `.cache/<id>/`，渲染全部图的预览，列出每张图的 LaTeX 说明。读 `Sections/*.tex` 比读 PDF 准确；论文有代码与数据仓库时克隆到 `.cache/` 并找到画面要用的结果表。没有仓库链接的论文照常生成图预览。当前 MCP 没有远程论文下载、源码解包或 PDF 裁切动作，这一步复用已有素材工具；创建文稿、编辑、检查与截帧通过 MCP 作者动作完成。
2. **简报与论点**：在 `storyboard.md` 写 A 到 F 节：观众、观看前后、论点（“看完后，观众明白 X，因为他们看到了 Y”）、ABT、配色、术语表、定义表。中心画面要让论点成为画面中随步骤变化、可直接看见的属性。
3. **数据**：写 `scenes/data/derive.py`，从论文公开的数据算出每个要上屏的数字，打印与论文值的对照；对不上就先查原因，不上屏。
4. **讲稿与分镜**：`storyboard.md` 的 G 节一行一步，写清结束画面与讲稿要点，并按 `presmium-animate/references/acceptance.md` 填元素与操作表：对象含义、编码、初末状态、动作路径、讲稿触发点、结果时机与跨步保留关系。先完成这些设计再写场景；只有结束帧关键词不算分镜完成。每步承载一个意思，长度随内容安排。用 `tools/new-paper.mjs` 生成文稿骨架（开场页与标准顺序的空页面），把讲稿写进 `lecture.json`。
5. **原图**：`uv run --no-project --with pymupdf python -I <figure.py> <图.pdf> papers/<slug>/figures/<名>.png --crop x0,y0,x1,y1`，`figure.py` 在 `presmium-animate` 技能的 `gallery/catalog/paper-figure/tools/`（先加 `--words` 看每个词的位置再定裁切），输出的 JSON 给出每个刻度与图例词的位置，标注按它放。
6. **场景**：协调者先写共用的数据模块和前几个场景定下画风，再把其余页面分给 agent 并行（每个 agent 只改自己的场景文件，见 `storyboard.md` 的 I 节）。规则：只用补间与 `set`，不用回调；节拍用 `clock` 的 `T(k, f)`，讲授时每个状态的时长就是这一步配音的长度，节拍跟着句子走；不用 SVG 的 `id`；要读的东西放在 77% 高度以上（下面是两行字幕的位置；坐标图的底边放在 61 个 SVG 单位，横轴标题就在这条线以上）；虚线用 `wipe` 展开。
7. **看**：连接原生 MCP `presmium` 后直接调用 `capture_slides`，用 `document: "papers/<slug>"`、`section: "p-<页>"` 取结束帧和 direct 加 `at` 的操作前中后画面；倒退检查另用不带 `at` 的 `arrive: "backward"`，不把两者合并或记成倒退定时验证。`appearance: "dark"` 看暗色，`capture_reading` 看网页（`width: 390` 看手机），`capture_overview` 看全部页面。重要验收用 `retain: true`，通过 `capture.manifestFile` 交接本轮文件，同时核对 `source` 与 `codeBundle`，不混旧图。默认 `presmium mcp <本工作区绝对路径>` 在初始化前启动或复用服务；没有 MCP 客户端的脚本才使用 `presmium mcp call ... --out <目录>`。
8. **预演与检查**：先做低成本关键操作预演和独立冷读，检查关键词、讲稿与画面对应、中文表述，以及同一对象的“设置→操作→结果→停留”；审阅者须能复述操作与比较依据。按技能分别记录事实、布局、运行与解析动效，联系表不能单独通过动效验收。闭环发现的问题后冻结文稿、代码、素材和讲稿，再做完整配音导出，不边审阅边跑正式成片。讲稿可以导出成 Markdown 润色：`pnpm exec presmium script export papers/<slug>`，改完用 `pnpm exec presmium script import papers/<slug>` 导回。
9. **配音**：先通过 MCP 查询音色、缺失句数、字数和缓存；本系列常规配音已有授权时直接生成当前缺失部分，不重复询问。没有 MCP 客户端时，`pnpm voiceover papers/<slug>` 先报告用量，再按已有授权加 `--yes` 生成；`--voice volcengine:zh_female_tianmeitaozi_uranus_bigtts` 先换默认音色。火山引擎按字数计费，只补生成改过的句子；新服务或超出授权的用量仍需相应授权。讲稿定稿后可加 `--prune --yes` 删掉不再使用的配音缓存。
10. **对时**：`pnpm timing papers/<slug>` 量每步的字数、配音秒数与总长（参考三到六分钟）；明显过长时删讲稿里重复与旁枝的话，再重新配音。
11. **导出与复看**：冻结且预演检查闭环后，经 MCP 导出烧入字幕的 MP4 与联系表；没有 MCP 客户端时用 `pnpm film papers/<slug> --burn zh-CN --contact-sheet`。检查实际音画、首帧、字幕、关键结果、操作边界与结尾，逐项记录已观察范围。完整连续观看未验证时照实写，不能用解码、联系表或源码替代；发现问题回到相应分镜或操作设计修订，再导出受影响版本。
12. **发布**：按“发布交付”补齐并检查发布标题、正文文案、封面与实际成片，再用 `pnpm build` 导出网站；提交源文件：文稿、场景、裁好的图、数据与 `derive.py`、配音缓存（`.presmium/speech/` 与 `speech.lock.json`，只留当前讲稿用到的条目）、发布文案和封面。成片不提交（每篇十几 MB），用 `pnpm film papers/<slug> --burn zh-CN` 导出到 `papers/<slug>/dist/`（已提交的配音缓存够用，不需要语音引擎与服务）。最终交付附上文案、封面与成片的实际路径。获作者授权上传平台时，用自定义封面入口上传独立设计的 `cover.png`，检查平台裁切后的缩略图，不用视频首帧代替；配音成片的封面不保留“无声预览”等旧版标记。填写 `publish.md` 的标题与正文，并按实际情况标注 AI 合成内容；核实提交结果与审核状态，保存发布记录，响应丢失时先查笔记管理再决定是否重试。

## 运行服务

```sh
pnpm exec presmium serve . --port 4410 --allow spend,operate,write   # 火山引擎用运营者目录里的 Key（pnpm exec presmium speech key status 查看）；没有 ffmpeg 时另设 PRESMIUM_FFMPEG
```


只预览不配音时 `pnpm serve` 即可；已提交的配音缓存不需要语音引擎也能播放与导出。

`presmium serve` 的作者动作（Studio 或 MCP 的修改）把每次保存记成一个 git 提交（“编辑文稿”，用仓库的 git 身份），提交在当前分支上。先核对远端，再把本次尚未推送的保存提交整理进本次提交；保留已推送的历史，不纳入其他任务的改动。
